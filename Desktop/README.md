# BakaGame 桌面壳（Windows / macOS · Tauri v2）

那个游戏反作弊计划的桌面端实现。**形态**：Tauri v2 壳 + 远程站点地址，前端 0 改动、不打包前端产物；壳里只打包
一个极小的本地启动页（`Desktop/splash/`），确认站点连得上再整页切过去。
壳里只做三件事——开窗口、跑原生自检、给通道证明签名，不含任何业务 UI。
选 Tauri 不选 Electron：release 构建默认没有 DevTools，Rust 侧调 Win32 自然，体积小一个量级。

本目录**不是** pnpm workspace 成员，构建链完全独立：只用 `cargo` 与 `@tauri-apps/cli`，不经过
`pnpm --filter`。站点地址、下载基址与分发配置属生产信息，不进本文件；取值以 `src-tauri/src/config.rs`、
`tauri.conf.json` 与 `capabilities/*.json` 为准，改站点域名必须同时改 `capabilities` 的远程来源白名单，
否则桥接能注入但 `selfCheck` / `baka_ticket` 会被权限层拒掉。

窗口导航只留在本站；页面里新开窗口的链接（`target="_blank"`、`window.open`）必须由壳接住并交给系统浏览器，
只放行 http(s)。WebView2 在壳没挂新窗口处理器时会静默吞掉这类请求，下载新版安装包等外链会点了毫无反应。
交给系统浏览器的方式按平台走系统自带能力：Windows 调 Shell，macOS 调系统自带的 `open`（地址作为独立参数传入，
不经过 shell），失败都只记日志。

**平台差异总览**：macOS 第一版只求「能开、能玩普通房、能注册设备」。与 Windows 的差别集中在以下几处，
各节分别展开：平台标识按编译目标取值；私钥只有软件保护；自检不跑任何检测、只报 `platform_unsupported`；
单实例用锁文件而不是具名互斥量；安装包只有自签名、未经 Apple 公证。HTTPDNS 与回环隧道两个平台同一口径。

**系统版本口径**：只按最新系统兼容，不为照顾旧系统砍功能或绕开新特性。某项能力要求更高的系统版本时，
抬最低系统版本，而不是给旧系统留回落；抬 macOS 的门槛要连同服务端的更新门槛一起改（见第 2 节自动更新）。

## 1. 构建

### 前置（Windows）

| 需要 | 说明 |
|---|---|
| Rust stable（x86_64-pc-windows-msvc） | `tauri-build` 与 WebView2 绑定都走 MSVC 工具链 |
| Visual Studio Build Tools + Windows SDK | 提供 `link.exe` 与系统头 |
| WebView2 Runtime | 随系统与 Edge 分发；安装包用下载引导器兜底 |
| `@tauri-apps/cli` | `pnpm dlx @tauri-apps/cli <命令>`，或 `cargo install tauri-cli --lockfile` |

### 前置（macOS）

| 需要 | 说明 |
|---|---|
| Xcode 或 Xcode Command Line Tools | 提供 clang 与 macOS SDK；依赖里有 Objective-C 构建脚本，没有 SDK 就编不过 |
| Rust stable（`aarch64-apple-darwin`，出通用包另加 `x86_64-apple-darwin`） | 通用包用 `--target universal-apple-darwin` 打 |
| `@tauri-apps/cli` | 同 Windows；版本与 CI 钉的那一枚一致 |

WebView 是系统自带的 WKWebView，不需要另装运行时。**Windows 上交叉检查 macOS 目标走不通**：
`cargo check --target aarch64-apple-darwin` 会卡在依赖的 Objective-C 构建脚本上（要 Apple 的编译器与 SDK），
不要为此伪造编译器硬凑。macOS 分支的类型检查与单测由 CI 的 macOS 作业兜底（只跑 `cargo check` 与
`cargo test`，不打包、不签名）。

### 命令

```powershell
cd Desktop\src-tauri

cargo check                              # 只做类型检查（不打包）
pnpm dlx @tauri-apps/cli dev             # 开发运行
pnpm dlx @tauri-apps/cli build           # Windows 上打 NSIS 安装包；macOS 上打 .app 与 .dmg
```

平台差异写在平台配置文件里：Tauri 只在对应平台上把 `tauri.<平台>.conf.json` 合并进主配置（JSON Merge Patch，
数组整个替换、不追加）。`tauri.macos.conf.json` 只在 macOS 上生效，定打包目标、最低系统版本与图标列表，
Windows 的打包结果不受它影响。取值读文件本身。其中签名身份写的是临时签名（ad-hoc），只为让本地产物能在
Apple 芯片上启动（本地没有发布用的证书）；CI 的发布作业用环境变量换成自签名证书，见第 2 节。

版本只写在 `src-tauri/Cargo.toml`：`tauri.conf.json` 不声明 `version`，Tauri 回落到 Cargo 清单，
安装包文件名、壳上报的 `clientVersion` 因此同源；发版改 `Cargo.toml` 后要把 `Cargo.lock` 里自身那一项带上。

`Cargo.lock` 与源码一起进 Git：壳是要发布出去的二进制，锁住整套依赖版本才能让每次构建复现同一份代码。
改完 `Cargo.toml` 要重跑一次 `cargo check` 把 lock 一起更新再提交，否则带 `--locked` 的构建会直接失败。

站点地址只由 `config.rs` 决定：非 https 会被拒绝并退回默认站点，因此 release 构建必须能访问那个站点，且**不读取** `BAKA_SITE_URL` / `BAKA_API_BASE`（进程环境改不了壳往哪发数据）。**开发构建（`debug_assertions`）例外**：没设 `BAKA_SITE_URL` 时默认加载
`http://localhost:5173`（`pnpm dev:client` 起的 Vite 服务器），并且只对回环 http（主机为 `localhost` /
`127.0.0.1`，端口不限）放行；换端口用 `BAKA_SITE_URL` 注入，桥接命令的远程白名单在
`capabilities/dev/dev-local-bridge.json`，两处要一起改。release 产物里既没有这条放行分支、也没有本地默认值，
仍只认 https，`capabilities/dev/` 下的能力文件也只在调试构建里收进去。

页面调用壳的命令要过两道门，缺一道的表现都是「壳里能用、页面拿到 `not allowed`」：一是 `build.rs` 的
`AppManifest::commands` 必须列出每个命令（`tauri-build` 据此生成 `allow-<命令>` 权限条目），二是 capability
按来源把这些权限授出去——`capabilities/site-bridge.json` 管生产站点，`capabilities/dev/dev-local-bridge.json`
管本地开发服务器。新增桥接命令时两处都要加，否则注册/取票在页面上永远失败，而控制台只留一句「通道校验未通过」。
能力文件还按 `platforms` 只在列出的系统上生效，每个桌面平台（Windows、macOS）都要列上：漏掉的平台上
页面调桥接命令一律被拒，壳自己却照常运行，表面看不出来。测试 `capability_policy` 守着这一条。
能力文件对同一窗口的页面按并集生效，所以**不要**给任何能力文件加 `core:*`
或任何插件权限：页面只调五条应用命令（桥接脚本的三条，加自动更新的两条契约外命令），多给的权限会直接落在
站点页面上。自动更新与窗口状态两个官方插件自带的命令一条都不授权，它们只在 Rust 侧用。`withGlobalTauri` 也保持关闭。

窗口建时按显示器工作区收窄初始尺寸；位置、尺寸与最大化状态由窗口状态插件记住并恢复，恢复之后再收进所在显示器
的工作区（插件只要窗口露出一个角就按原位置恢复，尺寸也照原样），换屏、改缩放比或拔掉外接屏后标题栏都够得着。

### 本地启动页

窗口先打开打包在壳里的本地启动页（`frontendDist` 指向 `Desktop/splash/`），它探测站点连得上就整页切过去；
连不上就给提示、「重试」按钮与带退避的自动重试，网络恢复时立刻再试，而不是让 WebView 停在系统自带的错误页上。
约束：

- **启动页拿不到任何命令**：每个能力文件都显式 `local: false`，只按 `remote.urls` 授给站点来源；桥接脚本也
  不在本地页上注入。测试 `capability_policy` 守着 `local: false`。
- 站点地址由壳的初始化脚本写进只在本地页上存在的只读全局，经 JSON 编码；站点页面上不多放任何全局。
- 导航白名单放行壳自己的本地来源（Windows 与 macOS 各一种），前缀相同的外站不算。
- 启动页只用系统字体（离线时站点的自托管字体也加载不到），颜色取站点默认主题；窗口建好时先隐藏，按系统明暗
  涂好同一背景色再显示，启动页与站点首屏之间不闪白。启动页的颜色改了要同步 `splash.rs` 里的背景色（有测试核对）。

### User-Agent

壳在请求里带一段客户端标识：`BakaGame/<壳版本> (<系统名> <系统版本>; <架构>; desktop) Game/<游戏版本>`。
格式、词表与取值规则的权威定义在共享契约 `Server/src/shared/ClientUserAgent.ts`，壳侧拼法在 `user_agent.rs`，
安卓壳另有一份；服务端的壳契约对账测试读三端源码逐项比对，改规则要三处一起改。约束：

- **只用于诊断与统计**：UA 是客户端自报、可以随意伪造的，不得参与任何信任、准入或判定逻辑，准入只看通道证明。
- WebView 里**追加**在内核默认 UA 之后（空格分隔），不整体覆盖：站点与第三方按浏览器特征做的判断不受影响。
  Tauri 只能在建窗时整体指定 UA，所以由 `webview_ua.rs` 走平台接口先读默认值、再写回拼接结果。
  壳自己的原生请求（注册、领挑战、换票、HTTPDNS 查询、自动更新）只发这一段。
- 系统版本与架构取运行时真实值：Windows 不取兼容层伪装过的版本号，架构报本机原生架构（模拟运行时也一样），
  macOS 在 Rosetta 下同样报 `arm64`。取不到的截写 `unknown`，整体形状不变。
- 游戏版本在建窗时还是 `unknown`；启动页阶段由壳读站点根的 `version.json`（与注册同一个 HTTP 客户端），
  读到后改写 WebView UA 并通知启动页。WebView UA 的改动只影响之后发起的导航，所以启动页探测到站点可达后
  要等这个信号（有上限）再进站；读失败或超时保持 `unknown`，不阻塞进站。

### 图标

图标按 `bundle.icon` 命名，源图与 `Client/` 共用同一枚 favicon；macOS 另用 `icon.icns`（由平台配置换上）。
重新生成的命令与口径写在 `src-tauri/icons/README.md`。`tauri build` 在缺图标时会直接失败，这是有意保留的
硬门槛；CI 的 macOS 检查作业不打包，缺 `icon.icns` 要到 macOS 发布作业打包时才会暴露。

### 蜜标与构建批次

`build.rs` 每次构建生成一枚构建标记，同时写进二进制 `.rodata`（`notice.rs` 的 `CLIENT_NOTICE` 与
`main.rs` 的构建标记常量）和构建输出目录（`OUT_DIR`）里的 `CLIENT_NOTICE.md`。仓库里的
`src-tauri/CLIENT_NOTICE.md` 只是占位，构建不会改写它，也不要把构建生成的版本提交进来。

CI 必须显式传批次标识与随机段两个变量，否则同一发布批次的每个制品标记都不一样，追溯时会误判成多个批次。
未提供时由短提交号与本机熵派生，只保证「每次构建互不相同」。

### HTTPDNS（可选，构建期注入）

壳可以让 WebView 与壳内 HTTP 客户端改走腾讯云 HTTPDNS。凭据只在构建时读取，不提供运行时配置：

| 变量 | 含义 |
|---|---|
| `BAKA_HTTPDNS_TOKEN` | HTTPS Token；设置后优先，查询走 `https://119.29.29.99/d` |
| `BAKA_HTTPDNS_APP_ID` + `BAKA_HTTPDNS_SECRET_KEY` | AES 模式；密钥必须是 16 字节 |
| `BAKA_HTTPDNS_DOMAIN` | 可选；缺省取站点与接口基址的 host |

- 任一模式配齐即可启用；凭据不全或没有受管域名时保持系统 DNS，并在 stderr 打 `[baka-httpdns] disabled reason=...`。
- 密钥会被编进二进制。这是 HTTPDNS 的固有代价：轮换凭据必须重新构建并分发，不能靠改配置。
- 解析结果按 HTTPDNS 返回的 TTL 缓存；查询失败回落系统 DNS，日志标 `degraded=true`，页面与接口继续可用。
- 受管域名的 WebView 流量经回环 CONNECT 隧道转发：只替换解析结果，不终结 TLS，SNI 与证书校验仍是原域名。
- 启用后 WebView 走该隧道，系统级 HTTP 代理不再生效；影响范围仅限壳内流量。壳自己的注册、领挑战与换票请求同样直连（不再读 `HTTP_PROXY` 等环境变量里的代理；壳内 HTTP 库本来就不读 Windows 的系统代理设置），与页面同出口：票据绑定签发时的来源地址，两条路径出口不同握手就会被拒。
- 日志：`[baka-httpdns] source=httpdns|cache host=... ips=... ttl=...s took=...ms`；
  降级为 `degraded=true ... fallback=system`；`[baka-dns-proxy] CONNECT host=... source=... ttl=... degraded=... took=...ms`。

CI 从仓库 secrets 读取同名凭据，缺失时按未配置构建。

**macOS 与 Windows 同一口径**：WKWebView 指向回环隧道靠 Tauri 的 `macos-proxy` 特性，它链接的网络框架接口
macOS 14 才有，所以 `tauri.macos.conf.json` 的最低系统版本不能低于 14，也不给更旧的系统留走系统 DNS 的回落。
Mac 的打包作业读同一份凭据；页面与壳内请求在两个平台上都按凭据决定走不走 HTTPDNS。

## 2. 代码签名与分发

### Windows

壳产物由 Windows Authenticode 签名，签名在打包**之后**做（Tauri 自己不签 Windows 制品）：

- **安装包与主 exe 都要签**。只签安装包的话，安装后的 exe 没有签名，SmartScreen 与自检的模块白名单
  都会更难解释。
- 用带时间戳的签名，证书过期后历史制品仍可验。优先 EV/OV 代码签名证书；自签证书只能用于内部测试机。
- **签名是分发流水线的最后一步**：签完再上传，签名的字节一旦改动，蜜标与包体就不对应了。
- 壳的「唯一构建标记」与 Authenticode 是两套独立证据：前者定位构建批次，后者只证明制品出自同一发布者、
  没被改过。

### macOS

**现状：自签名、未公证的通用包**（Apple 芯片与 Intel 合一的 `universal-apple-darwin`）。没有 Apple 开发者账号，
所以发出去的包：

- **首次打开一定会被 Gatekeeper 拦下**：系统提示无法验证开发者，玩家要到系统设置的「隐私与安全性」里点
  「仍要打开」。下载弹窗的 macOS 档写着这一步。Gatekeeper 只认苹果签发并公证过的证书，自签名免不掉这一步。
- **自签名的作用是让每一版的签名身份固定**：签名者一直是同一张证书，自动更新之后系统按同一个身份看待新版，
  钥匙串的访问授权与系统权限（例如已经放行过的弹窗）不会被重置；临时签名每次构建身份都不同，做不到这一点。
- 证书有效期到 2036 年。私钥丢失后只能换新证书，换证书等于换了签名身份，已安装的壳更新后钥匙串授权与系统
  权限会被重置一次，玩家要重新放行；证书与密码只在仓库 Secrets 里，备份与轮换细节属生产信息，放本地笔记。

**发布流程**（CI 里与 Windows 同一套口径，作业与步骤读 `ci.yml`）：

- 触发与 Windows 一致：main 上壳目录有改动时。先查对象存储，这个版本的 dmg 已经在桶里就整条跳过：同版本
  重打出来的是另一份构建（构建标记不同），覆盖长缓存的版本化对象会让签名与缓存里的包对不上。
- 首次发版或补发用 workflow_dispatch 的 `publish_macos` 输入：只发布 macOS 的当前版本，其余作业全部跳过，
  不会重打、重传 Windows 与安卓的包；已经发过的版本同样跳过。
- 签名：有证书 Secret 时导入临时钥匙串并把证书信任为代码签名根（自签名证书在运行器上默认不受信，codesign
  找不到可用身份），再用证书的名字覆盖配置里的临时签名；缺证书时退回临时签名，发布不失败。有更新签名私钥时
  另出 `.app.tar.gz` 与 `.sig`。发布前在运行器上用 codesign 核对 .app、dmg 里的应用与更新包里的应用签名一致，
  用了证书时签名者必须是这张证书，任何一项不符就不发布。
- 上传：版本化对象长缓存、latest 别名不缓存；先传 dmg 与更新包，再传签名，最后写别名旁的 `.version`。没有带
  签名的更新包时只发 dmg，并撤下别名旁的旧签名。服务端的 macOS 下载与更新包地址缺省就指向这两个固定别名，
  别名还不存在时弹窗写「尚未发布」、更新清单回 204。

**以后接入 Developer ID 签名与公证**需要 Apple 开发者账号，Secrets 按 Tauri 认的名字配（只列名字与用途）：

| Secret | 用途 |
|---|---|
| `APPLE_CERTIFICATE` / `APPLE_CERTIFICATE_PASSWORD` | 换成 Developer ID Application 证书导出的 p12（base64）及其密码 |
| `APPLE_SIGNING_IDENTITY` | Developer ID 证书的签名身份名，取代工作流里写的自签名身份 |
| `APPLE_ID` / `APPLE_PASSWORD` / `APPLE_TEAM_ID` | 用账号提交公证：Apple ID、App 专用密码、团队 ID |
| `APPLE_API_ISSUER` / `APPLE_API_KEY` / `APPLE_API_KEY_PATH` | 改用 App Store Connect API 密钥提交公证（与上一行二选一） |

接入后不再需要信任自签名根那一步；公证让首次打开不再被拦下。换成 Developer ID 证书同样是换签名身份，
已安装的壳更新后钥匙串授权与系统权限会重置一次。签名与公证都是分发流水线的最后几步，签完、公证完再上传；
与 Windows 一样，签名不改变唯一构建标记的作用。

### 自动更新（壳本体）

页面本来就是远程站点，这里更新的是壳自己。用 Tauri 官方的 updater 插件，只在 Rust 侧使用（`self_update.rs`）：

- **流程**：启动后等一会儿在后台线程检查 → 有新版就后台下载，下载完成即用公钥校验签名 → 校验过的包留在内存里，
  状态记为就绪 → 玩家在首页更新提醒里点「重启更新」时才安装并重启。不做退出时静默安装。Windows 上插件启动
  安装程序后壳直接退出，安装程序装完再把新版拉起来；macOS 上包替换完成后壳自己重启，重启前先放掉单实例锁。
- **页面能做的只有两件事**：用契约外命令读状态（查询中 / 没有新版 / 下载中 / 已就绪 / 失败），以及请壳安装
  它已经校验过的那一份。安装命令不收任何参数，页面给不出地址也给不出字节；插件安装前还会再校验一遍签名，
  所以页面没有任何途径让壳装上未签名或被改过的包。两条命令照「两道门」登记，不进 `__BAKA_CHANNEL__` 冻结契约。
- **失败不影响游玩**：离线、清单读不到、签名不对都只记日志并退避重试，查过没有新版隔几小时再查，间隔读
  `self_update.rs`。首页提醒在壳没就绪、壳太旧或安装失败时照旧给「下载最新版」链接兜底。
- **提醒在场时提前复查**：页面只在首页更新提醒在场时才读状态，这本身说明服务端已公布了更新的版本。
  读状态时壳若停在「没有新版」或「失败」，且距上一轮检查结束已过最小间隔，就叫醒后台线程立刻复查一轮，
  这次读到的即为「查询中」；新版发布在壳启动之后也不必干等下一次定时复查。读状态的命令本身不发请求、
  不收参数，复查仍由后台线程去做；最小间隔保证离线时页面的定时轮询不会变成对接口的轰炸，连续失败次数
  照旧累计、不因提前复查清零。检查进行中、已就绪（后台线程已结束）或本构建不启用自动更新时不叫醒。
- **页面反馈**：查询中与下载中时提醒按钮进入进行中，不给下载链接；已就绪给「重启更新」；其余情况给下载
  链接，点下去由壳交给系统浏览器后，按钮要短暂换成已交给浏览器的确认，不能让点击看起来毫无反应。
- **清单与安装包**：清单由服务端按 Tauri 动态格式提供（路径由壳契约对账测试与服务端路由核对），数据取自制品
  清单：版本读 `.version` 旁文件，签名读 `.sig` 旁文件，地址就是对象存储上的更新包。安装包字节从对象存储直接
  发给壳，源站不转发。清单地址按 `config.rs` 的口径拼：发布构建固定 https 站点；开发构建默认不自动更新，
  显式设环境变量才启用（变量名读 `self_update.rs`），免得每次开发运行都在后台下包。
- **Windows 的更新包就是 NSIS 安装包本身**；macOS 的更新包是 `.app.tar.gz`，与下载用的 dmg 不是同一个文件，
  服务端另配地址（缺省指向它的固定别名），发布作业把它连同 `.sig`、`.version` 一起传上去。
- **macOS 按系统版本把门**：更新器装完就重启，新包要求的系统版本高于这台 Mac 时，玩家手上只剩一个打不开的壳。
  服务端因此只给请求头客户端段报出的系统版本不低于新包最低版本的 Mac 下发清单，读不出系统版本（不带客户端段
  的旧壳）也不下发，交给首页提醒引导手动下载；这份答复随请求头变化，只许端上缓存。门槛值与
  `tauri.macos.conf.json` 的最低系统版本是同一个数，契约对账测试核对两边。
- **发布顺序**：先传安装包，再传 `.sig`，最后写 `.version`。版本一变同批签名已就位；万一读到新包配旧签名，
  壳只会校验失败、稍后重试，不会装错。某一版没签名时要撤下别名旁的旧签名。

**签名密钥**：更新签名用的是 Tauri 的 minisign 密钥对，与 Windows 的 Authenticode 证书是两回事。公钥写在
`tauri.conf.json` 的 updater 配置里、编进每一个壳；私钥与密码只在仓库 Secrets 里，CI 打包时用它们产出
`.sig`。**私钥丢失或泄露的代价很重**：已安装的壳只认编进去的那把公钥，换一对密钥后它们再也收不到自动更新，
只能让玩家手动重装带新公钥的版本。私钥的备份与轮换细节属生产信息，放本地笔记。插件还能校验签名里记下的
版本号以防降级，等确认打包 CLI 产出的签名带版本后再打开这道开关。

**对反作弊自检的影响**：

- 插件是静态链接进壳的 Rust 代码，下载走与注册相同的 TLS 栈，更新期间不会加载白名单外的新模块；Windows 上
  启动安装程序用的系统接口在启动时就已加载。
- 自动更新后新版壳由安装程序拉起，父进程是更新插件写出的安装包（形如 `bakagame-<版本>-installer.exe`），装完
  很快就退出。父进程检测因此改为启动时尽早记下并缓存（父进程本来就不会变），并把这个名字形状算作已知父进程，
  否则更新后的那次启动会一直被记成可疑。判据与已知父进程表一样只看名字，强度不高于原有口径。
- 安装命令不能被页面利用来装别的包，理由见上。
- 窗口状态插件同样静态链接，本地启动页走壳自己的协议加载，都不引入新模块。开发壳实测（经 CDP 连续两次
  `selfCheck`）硬失败为空；软失败只有测试环境自带的两项：从终端启动的父进程，以及为了连 CDP 开的调试端口。

### 分发侧约束

- **下载地址由服务端配置给**（每个平台一条固定别名，不带版本号、永远指向最新，旧链接长期有效）；配成空
  串即该平台不进制品清单，页面不给它下载链接，更新提醒也读不到它的最新版本。地址形如
  `https://example.com/files/<固定别名>`；别名对象还没传上去时该平台照样列出、写「尚未发布」。取值与变量名读服务端配置。
- **前端不写死日期与大小**：安装包架构、构建日期、文件大小一律来自服务端制品清单接口，逐条说明见
  [Server/docs/ClientChannel.md](../Server/docs/ClientChannel.md)。入口在首页，先选平台再给链接，
  入口文案不写反作弊前提——装不装由玩家自己判断。
- 制品对象名要带内容哈希，缓存键随内容变化；发布顺序永远是先传对象、后更新清单。发布流水线细节属生产
  信息，放本地笔记。
- Windows 与 macOS 同一口径：同一版本只发一次（版本化对象已在桶里就整步跳过），发完对别名与旁文件各请求
  一次预热边缘缓存，失败只告警。约束与理由见 [Deployment](../Agents/Deployment.md)。
- **强制更新**：壳启动注册时上报 `clientVersion`，服务端返回 `minimumVersion`；低于最低版本由服务端在
  握手回 `CLIENT_OUTDATED`，**只拦反作弊房，普通房不受影响**。通道证明协议一旦变更必须抬高最低版本，
  否则旧壳还能继续签名通关。最低版本放在服务端配置里，不发版也能紧急抬升。
- **首页软提醒**与准入是两件事：不更新照样进普通房，反作弊房仍由服务端硬拦。桌面壳已在后台下好新版时，
  提醒里的按钮换成「重启更新」。提示里的「下载最新版」按壳
  自报的类型与平台给对应平台的包，不得让移动端壳拿到桌面链接，也不得让 Mac 壳拿到 Windows 的安装包；
  本平台没发布时不给按钮。查询更新时带上壳自报的平台，「有没有新版」按本平台的已发布版本比。
  提醒有两个来源：低于最低准入版本（硬提醒），或低于发布流水线写下的最新壳版本（软提醒）；后者不改变
  任何准入判定。Mac 壳报出的系统版本低于新包要求时不给软提醒，新包在那台机器上装不了。
- **资源更新**：桌面壳加载远程站点，Client 发版后刷新页面即用上新资源，不需要重装；只有原生侧变更
  （自检、签名、构建布局）才需要发新安装包。

## 3. 桥接契约

`bridge.rs` 的脚本经 `WebviewWindowBuilder::initialization_script` 注入，时机是「全局对象已建好、HTML
尚未开始解析」，因此页面脚本执行前 `window.__BAKA_CHANNEL__` 一定存在。契约成员的名称与类型以 `bridge.rs`
为准，这里只记不可破坏的性质：

- `platform` 按编译目标取值（Windows 与 macOS 各一个分支），脚本里只留占位符，生成脚本时换成注册上报的
  同一个常量：页面看到的平台与服务端登记的平台不能各说各话。服务端的壳契约对账测试逐个分支核对。

- `channelTicket` 必须是**访问器属性**（getter），不是普通字符串字段：票是短 TTL 且用过即焚，读走一次
  立刻作废并同步向壳再要一张，第二次读取绝不能返回同一张。`Object.freeze` 只锁数据属性的写入，访问器
  每次读都会重新执行，所以冻结后仍然能给出新票。
- `selfCheck`：每次调用都重跑全部检测，不缓存结果（调试器可能中途才附着）。
- **页面拿不到签名能力**：页面可用的只有 `selfCheck` 与一次性票据；设备私钥签名只在壳内部用于通道证明，
  由 `attest` 模块直接调用，不经过桥接脚本。页面即使被注入脚本，也无法用设备私钥对任意内容签名。
- **注入失败就不注入**：拿不到 Tauri IPC、非顶层框架、名字已被占用时保持静默，页面按 Web 处理。刻意不
  注入一个永远 reject 的假通道——那会让桌面用户连普通房都进不去。
- 契约只有已声明的那几个成员，**多一个字段就是改协议**：页面需要 `clientId` 时走契约外的 Tauri 命令，
  或让服务端在 challenge 帧里带回，本壳不擅自加字段。对象整体被 `Object.freeze`，属性不可写、不可配置。

证明闭环（领挑战 → 逐字节签名 → 换一次性票）的流程与判定约束见
[Server/docs/ClientChannel.md](../Server/docs/ClientChannel.md)，字段与词表以代码为准。要点：

- 换票时的自检结果**每次现跑**，不复用启动那次结果。
- 只重试「挑战过期」与「客户端未知」两类错误，且一轮最多两次；其余错误当场放弃。
- 拿不到票**不报错给玩家**：票保持空串，页面按网页口径连接，普通房照常，反作弊房由服务端拒——与「注入
  失败就不注入」是同一个取舍。
- 领挑战与换票在建连关键路径上，超时必须明显短于注册请求的超时。
- 补票时机全部在后台线程（启动就绪、每次允许的导航先弃票再预签、票被读走立刻补、定时轮询、首次同步读
  命中预签缓存），绝不占用导航回调与 IPC 线程。
- 一次性保证靠「已交出」标记 + 取出即记为已用，并用一把串行闸门避免轮询与导航预签撞成重复往返。
- 到期余量必须与桥接脚本里的同一常量保持一致：宁可当没有，也不把「到页面手上才过期」的票交出去。
- 离线时轮询要有退避，不能变成对证明接口的轰炸。

`selfCheck` 上报的 id 词表、权重与归类以服务端 `ClientChannel.ts` 的权重表为唯一真相源，判定原则见
[Server/docs/ClientChannel.md](../Server/docs/ClientChannel.md)。**macOS 上不跑任何检测**，只上报一条
`platform_unsupported`：它写在硬失败格里，但服务端按权重判、不看格子，以权重表的归类为准（当前归为标记：
放行并标可疑）。壳侧日志里的判定只按格子数数，这一项会显示成不可信，不要据此排查准入。

**新增 id 只能追加，不要改名**——服务端与前端按字面量匹配；改名等于换协议，两边都得同时抬最低版本。
要把某项从标记改成硬失败，改权重表，别靠改 id 名解决。没跑成的检测绝不能当成「已通过」：拿不准的一律进软失败或标记，不计入 clean。

模块白名单按系统目录、壳自身安装目录与浏览器运行时分发目录判定（按目录边界匹配，不是字符串前缀），热修可经环境变量追加分号分隔的目录路径，
抬白名单不需要重新发版；变量名读 `selfcheck.rs`。

## 4. 数据与隐私面

壳只在注册与每次通道证明时上报：公钥、客户端版本、平台、命中的检测项 id。**上报内容只有 id，没有任何
路径、进程名、命令行原文。** 本地诊断日志默认关闭，只有显式开关才写入用户目录，内容仅为时间戳 + 检测项
id + 命中原因，用于本地排查，不自动上传。反作弊房关闭时以上任何一项都不影响玩家。
此外每个请求都带上一节的 User-Agent 段（壳版本、系统名与版本、架构、游戏版本），其中不含任何设备标识。

私钥种子经系统级用户范围加密后存用户目录；该能力不可用时**降级**为软件保护并如实上报保护等级，不拒绝启动
——此时私钥只有用户目录 ACL 这一层保护，上报字段要让服务端分辨得出。离线启动不阻塞：注册失败只记日志，
签发通道证明时会顺带补一次注册。

macOS 没有这层系统加密，私钥一律是软件保护并如实上报 `software`，只靠用户目录的文件权限；改用钥匙串是
后续工作。壳的数据目录（密钥、`clientId` 与单实例锁文件）在 Windows 上落在漫游应用数据目录下，在 macOS 上
落在当前用户的 `~/Library/Application Support` 下；取不到用户目录时不启用桌面通道，绝不退回相对路径。
具体路径读 `device.rs`。本地诊断日志只在 Windows 上写，macOS 上不写（只有一条固定的平台项，没有可排查的内容）。

发布构建同一登录会话里只允许一个壳进程：双开会让两个进程竞争同一份设备密钥文件、各起一套回环隧道。
Windows 用具名互斥量判定，后来者把已有窗口拉到前台后退出；macOS 对数据目录里的锁文件加独占锁，后来者直接
退出（从访达或程序坞重复打开同一个 .app 时系统本身会把已有实例带到前台），锁随进程退出自动释放。
守卫持有到进程退出，只有自动更新重启前会主动放掉（重启是先拉起新进程再退出旧进程）。
拿不到锁时失败放行，不拦玩家启动。开发构建不限制，方便多账号联调。
设备密钥文件确认损坏（或 DPAPI 在可用的前提下解不开）时，旧文件改名留证并重新生成设备身份；
读取失败、版本或保护方式不认识、DPAPI 暂不可用这类说不清好坏的情形只报错，不重建。

## 5. 尚未验证与尚未实现

`cargo check` 通过不代表壳可用，以下边界必须如实对待：

1. `tauri.conf.json` 与 `capabilities/*.json` 的 schema **只有 `tauri build` / `tauri dev` 会校验**，
   `cargo check` 不读这些 JSON。
2. 手写 Win32 结构体的运行时布局需要真实进程验证，尺寸断言只在测试里跑。
3. 证明闭环的三趟往返字段是照着服务端 strict schema 逐项核对出来的，本地单测只钉住序列化出来的字段名，
   不需要网络；真实握手仍未验证。
4. `reqwest::blocking` 只能在**非 async 上下文**里用（在 reactor 线程上构造会 panic）。所有调用点必须在
   阻塞任务线程里；后续改代码不得把 HTTP 传输直接挪进 `async fn` 命令体。
5. 票的一次性语义只有壳侧标记与到期余量兜住，**没有服务端配合的回归测试**：「同一张票被消费两次」「导航
   后旧票还在」只有真实握手才能暴露。
6. 前端取票时机仍需在握手查询串里补上票参数，并且**每次连接前重新取**——在模块加载时把查询串拼死会复用
   已被消费的票。

刻意留下的未实现项（不伪造实现）：

| 项 | 现状 | 缺什么 |
|---|---|---|
| 模块**签名**校验（Authenticode） | 只按路径白名单判定 | 系统验签接口的手写绑定不确定，不敢瞎声明；命中面比路径判定准得多，是下一优先级 |
| 浏览器内核 DevTools 设置位的读回 | 未实现；改读「调试端口文件 + 远程调试参数」，任一命中记软失败 | 要读设置位本身需要拿到内核 COM 接口，依赖版本要与渲染层绑定对齐，本机无法验证 |
| 降级态文件的显式 ACL | 依赖用户目录 ACL | 安全描述符与文件安全接口的 SDDL 绑定 |
| 强制更新的壳侧拦截 | 只记录并打日志 | 契约里没有可暴露的字段；按「只拦反作弊房」口径由服务端拒 |
| 移动端 / iOS | 不在本目录范围 | 见 [Mobile/README.md](../Mobile/README.md) |
| macOS 私钥的钥匙串保护 | 软件保护，上报 `software` | 钥匙串存取与访问控制的绑定，以及从软件保护迁移的口径 |
