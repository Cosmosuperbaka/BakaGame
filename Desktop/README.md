# BakaGame 桌面壳（Windows / Tauri v2）

CEE 反作弊计划的桌面端实现。**形态**：Tauri v2 壳 + 远程站点地址，前端 0 改动、不打包前端产物。
壳里只做三件事——开窗口、跑原生自检、给通道证明签名，不含任何业务 UI。
选 Tauri 不选 Electron：release 构建默认没有 DevTools，Rust 侧调 Win32 自然，体积小一个量级。

本目录**不是** pnpm workspace 成员，构建链完全独立：只用 `cargo` 与 `@tauri-apps/cli`，不经过
`pnpm --filter`。站点地址、下载基址与分发配置属生产信息，不进本文件；取值以 `src-tauri/src/config.rs`、
`tauri.conf.json` 与 `capabilities/*.json` 为准，改站点域名必须同时改 `capabilities` 的远程来源白名单，
否则桥接能注入但 `sign` / `selfCheck` 会被权限层拒掉。

## 1. 构建

### 前置（Windows）

| 需要 | 说明 |
|---|---|
| Rust stable（x86_64-pc-windows-msvc） | `tauri-build` 与 WebView2 绑定都走 MSVC 工具链 |
| Visual Studio Build Tools + Windows SDK | 提供 `link.exe` 与系统头 |
| WebView2 Runtime | 随系统与 Edge 分发；安装包用下载引导器兜底 |
| `@tauri-apps/cli` | `pnpm dlx @tauri-apps/cli <命令>`，或 `cargo install tauri-cli --lockfile` |

### 命令

```powershell
cd Desktop\src-tauri

cargo check                              # 只做类型检查（不打包）
pnpm dlx @tauri-apps/cli dev             # 开发运行
pnpm dlx @tauri-apps/cli build           # 打 NSIS 安装包
```

`Cargo.lock` 与源码一起进 Git：壳是要发布出去的二进制，锁住整套依赖版本才能让每次构建复现同一份代码。
改完 `Cargo.toml` 要重跑一次 `cargo check` 把 lock 一起更新再提交，否则带 `--locked` 的构建会直接失败。

壳按远程地址加载页面，`frontendDist` 非 https 会被 `config.rs` 拒绝并退回默认站点，因此开发也要能访问
那个站点。要用本地页面调试，得提供一个真正能给 https 的地址（本地反向代理或已签发的预览域），通过
`BAKA_SITE_URL` 注入。

### 图标

图标按 `tauri.conf.json` 的 `bundle.icon` 命名，源图与 `Client/` 共用同一枚 favicon。重新生成的命令与
口径写在 `src-tauri/icons/README.md`。`tauri build` 在缺图标时会直接失败，这是有意保留的硬门槛。

### 蜜标与构建批次

`build.rs` 每次构建生成一枚构建标记，同时写进二进制 `.rodata`（`notice.rs` 的 `CLIENT_NOTICE` 与
`main.rs` 的构建标记常量）和 `src-tauri/CLIENT_NOTICE.md`。

CI 必须显式传批次标识与随机段两个变量，否则同一发布批次的每个制品标记都不一样，追溯时会误判成多个批次。
未提供时由短提交号与本机熵派生，只保证「每次构建互不相同」。

## 2. 代码签名与分发

壳产物由 Windows Authenticode 签名，签名在打包**之后**做（Tauri 自己不签 Windows 制品）：

- **安装包与主 exe 都要签**。只签安装包的话，安装后的 exe 没有签名，SmartScreen 与自检的模块白名单
  都会更难解释。
- 用带时间戳的签名，证书过期后历史制品仍可验。优先 EV/OV 代码签名证书；自签证书只能用于内部测试机。
- **签名是分发流水线的最后一步**：签完再上传，签名的字节一旦改动，蜜标与包体就不对应了。
- 壳的「唯一构建标记」与 Authenticode 是两套独立证据：前者定位构建批次，后者只证明制品出自同一发布者、
  没被改过。

分发侧约束：

- **下载地址由服务端配置给**（每个平台一条固定别名，不带版本号、永远指向最新，旧链接长期有效）；配成空
  串即从下载弹窗里去掉该平台。取值与变量名读服务端配置。
- **前端不写死日期与大小**：安装包架构、构建日期、文件大小一律来自服务端制品清单接口，逐条说明见
  [Server/docs/ClientChannel.md](../Server/docs/ClientChannel.md)。入口在首页，先选平台再给链接，
  入口文案不写反作弊前提——装不装由玩家自己判断。
- 制品对象名要带内容哈希，缓存键随内容变化；发布顺序永远是先传对象、后更新清单。发布流水线细节属生产
  信息，放本地笔记。
- **强制更新**：壳启动注册时上报 `clientVersion`，服务端返回 `minimumVersion`；低于最低版本由服务端在
  握手回 `CLIENT_OUTDATED`，**只拦反作弊房，普通房不受影响**。通道证明协议一旦变更必须抬高最低版本，
  否则旧壳还能继续签名通关。最低版本放在服务端配置里，不发版也能紧急抬升。
- **首页软提醒**与准入是两件事：不更新照样进普通房，反作弊房仍由服务端硬拦。提示里的「下载最新版」按壳
  自报的类型给对应平台的包，不得让移动端壳也拿到桌面链接。

## 3. 桥接契约

`bridge.rs` 的脚本经 `WebviewWindowBuilder::initialization_script` 注入，时机是「全局对象已建好、HTML
尚未开始解析」，因此页面脚本执行前 `window.__BAKA_CHANNEL__` 一定存在。契约成员的名称与类型以 `bridge.rs`
为准，这里只记不可破坏的性质：

- `channelTicket` 必须是**访问器属性**（getter），不是普通字符串字段：票是短 TTL 且用过即焚，读走一次
  立刻作废并同步向壳再要一张，第二次读取绝不能返回同一张。`Object.freeze` 只锁数据属性的写入，访问器
  每次读都会重新执行，所以冻结后仍然能给出新票。
- `sign`：签名对象**逐字**是 challenge 这个 ASCII 字符串的字节，不做任何二次编码或加盐；返回值是标准
  base64（无换行、无 URL-safe 变换）。服务端按同一口径验签。
- `selfCheck`：每次调用都重跑全部检测，不缓存结果（调试器可能中途才附着）。
- **注入失败就不注入**：拿不到 Tauri IPC、非顶层框架、名字已被占用时保持静默，页面按 Web 处理。刻意不
  注入一个永远 reject 的假通道——那会让桌面用户连普通房都进不去。
- 契约只有已声明的那几个成员，**多一个字段就是改协议**：页面需要 `clientId` 时走契约外的 Tauri 命令，
  或让服务端在 challenge 帧里带回，本壳不擅自加字段。对象整体被 `Object.freeze`，属性不可写、不可配置。

证明闭环（领挑战 → 逐字节签名 → 换一次性票）的流程与判定约束见
[Server/docs/ClientChannel.md](../Server/docs/ClientChannel.md)，字段与词表以代码为准。要点：

- 换票时的自检结果**每次现跑**，不复用启动那次结果。
- 只重试「挑战过期」与「客户端未知」两类错误，且一轮最多两次；其余错误当场放弃。
- 拿不到票**不报错给玩家**：票保持空串，页面按网页口径连接，普通房照常，反作弊房由服务端拒——与「注入
  失败就不注入」是同一个取舍。
- 领挑战与换票在建连关键路径上，超时必须明显短于注册请求的超时。
- 补票时机全部在后台线程（启动就绪、每次允许的导航先弃票再预签、票被读走立刻补、定时轮询、首次同步读
  命中预签缓存），绝不占用导航回调与 IPC 线程。
- 一次性保证靠「已交出」标记 + 取出即记为已用，并用一把串行闸门避免轮询与导航预签撞成重复往返。
- 到期余量必须与桥接脚本里的同一常量保持一致：宁可当没有，也不把「到页面手上才过期」的票交出去。
- 离线时轮询要有退避，不能变成对证明接口的轰炸。

`selfCheck` 上报的 id 词表、权重与归类以服务端 `ClientChannel.ts` 的权重表为唯一真相源，判定原则见
[Server/docs/ClientChannel.md](../Server/docs/ClientChannel.md)。**新增 id 只能追加，不要改名**——服务端
与前端按字面量匹配；改名等于换协议，两边都得同时抬最低版本。要把某项从标记改成硬失败，改权重表，别靠改
id 名解决。没跑成的检测绝不能当成「已通过」：拿不准的一律进软失败或标记，不计入 clean。

模块白名单按系统目录、壳自身安装目录与浏览器运行时分发目录判定，热修可经环境变量追加分号分隔的路径前缀，
抬白名单不需要重新发版；变量名读 `selfcheck.rs`。

## 4. 数据与隐私面

壳只在注册与每次通道证明时上报：公钥、客户端版本、平台、命中的检测项 id。**上报内容只有 id，没有任何
路径、进程名、命令行原文。** 本地诊断日志默认关闭，只有显式开关才写入用户目录，内容仅为时间戳 + 检测项
id + 命中原因，用于本地排查，不自动上传。反作弊房关闭时以上任何一项都不影响玩家。

私钥种子经系统级用户范围加密后存用户目录；该能力不可用时**降级**为软件保护并如实上报保护等级，不拒绝启动
——此时私钥只有用户目录 ACL 这一层保护，上报字段要让服务端分辨得出。离线启动不阻塞：注册失败只记日志，
首次签名调用会按节流补一次注册。

## 5. 尚未验证与尚未实现

`cargo check` 通过不代表壳可用，以下边界必须如实对待：

1. `tauri.conf.json` 与 `capabilities/*.json` 的 schema **只有 `tauri build` / `tauri dev` 会校验**，
   `cargo check` 不读这些 JSON。
2. 手写 Win32 结构体的运行时布局需要真实进程验证，尺寸断言只在测试里跑。
3. 证明闭环的三趟往返字段是照着服务端 strict schema 逐项核对出来的，本地单测只钉住序列化出来的字段名，
   不需要网络；真实握手仍未验证。
4. `reqwest::blocking` 只能在**非 async 上下文**里用（在 reactor 线程上构造会 panic）。所有调用点必须在
   阻塞任务线程里；后续改代码不得把 HTTP 传输直接挪进 `async fn` 命令体。
5. 票的一次性语义只有壳侧标记与到期余量兜住，**没有服务端配合的回归测试**：「同一张票被消费两次」「导航
   后旧票还在」只有真实握手才能暴露。
6. 前端取票时机仍需在握手查询串里补上票参数，并且**每次连接前重新取**——在模块加载时把查询串拼死会复用
   已被消费的票。

刻意留下的未实现项（不伪造实现）：

| 项 | 现状 | 缺什么 |
|---|---|---|
| 模块**签名**校验（Authenticode） | 只按路径白名单判定 | 系统验签接口的手写绑定不确定，不敢瞎声明；命中面比路径判定准得多，是下一优先级 |
| 浏览器内核 DevTools 设置位的读回 | 未实现；改读「调试端口文件 + 远程调试参数」，任一命中记软失败 | 要读设置位本身需要拿到内核 COM 接口，依赖版本要与渲染层绑定对齐，本机无法验证 |
| 降级态文件的显式 ACL | 依赖用户目录 ACL | 安全描述符与文件安全接口的 SDDL 绑定 |
| 强制更新的壳侧拦截 | 只记录并打日志 | 契约里没有可暴露的字段；按「只拦反作弊房」口径由服务端拒 |
| 移动端 / iOS | 不在本目录范围 | 见 [Mobile/README.md](../Mobile/README.md) |
