## 1. 准入、协议与载体

- 排位是独立的轻量服务，不复用多人房引擎：不占四位房号、不进大厅、没有房主与设置。复用的只是纯函数层（反馈判定、提示生成、检索、检索配额与台账）。命令走统一入口的 `cee.ranked.*`，与多人房命令同表校验、在入口按前缀分流；房间服务的入口类型不包含排位命令，穷尽检查因此仍成立。
- 主页入口的可用性由运行期旋钮 `enableCeeRankedEntry` 决定，客户端经 `GET /api/site/config` 现读（不缓存）。关掉后入口**仍然呈现但置灰不可点**，并标注「暂时关闭」：让玩家看得出这个玩法存在、只是暂时不能进；本节准入不变，直连路径与在途系列赛都不受影响。
- 准入是连接级的：已登录、带服务端验过的客户端通道证明、版本不过低，并且**拒绝 Agent（MCP）连接**。与反作弊房共用同一个准入函数，两边的文案按场景区分；改其中一边的判据要同时看另一边。查询状态、排队、主动打人机三条命令过准入，其余命令要求调用连接是该账号当前的排位连接。
- 每个账号同一时刻只有一条排位连接：后到的连接接管推送，旧连接收到空闲状态后不再收推送。一个账号同一时刻只能在一个队列或一场系列赛里。
- 没有数据库（未注入审计仓储）或没有题库时排位整体不可用，与账号同一模式；不做内存降级。
- 排位状态按连接推送，走差量同步。系列赛只在内存里，**进程重启时在途系列赛作废、不写库**；不进房间快照。
- 结算后双方各自停在结果页：一方离开（或从结果页再来一场）只解开自己，不能连带清掉对手的结果页；两人都离开才丢弃运行时。结果页停留超过保留时长由巡检替玩家离开并推空闲，运行时不常驻内存。
- 检索命令只在系列赛进行中可用；取角色图在结果页也放行（逐局回看答案与双方猜测要用）。

## 2. 赛制与对手可见性

- 一场排位是三局两胜的系列赛：每局双方猜同一答案、同时开始，先猜中者赢下这局，先赢满两局者胜。**系列赛不设平局**：一局双方都没猜中则双方都不得分，加赛一局，直到有人赢满两局。半分会让「打平」变成可积累的收益，也让比分读不出谁更接近赢。
- 加赛有安全上限（防双方挂机无限续局）：题目在开赛时按上限一次抽好且互不相同，状态机因此仍是纯同步的；打到上限（或题库不够上限、备用题用完）仍无人赢满两局，按赢局多者胜，仍相同才记平。这是唯一会出现系列赛平局的路径，评分照旧按 0.5 计。用不到的备用题不下发。
- 每局有读秒、常规、骤死加时三段。双方都用尽次数或常规到点且无人猜中即进入加时：未认输的一方各追加次数，双方同时看到同一条系统提示（优先取角色简介生成的句子，没有简介时退到登场年份或作品数）。加时仍无人猜中，本局不算分。局与局之间有固定的复盘停顿，然后自动开下一局。
- 同一角色重复猜测直接拒绝且不扣次。「认输」只放弃当前这局；「退出」与连续离线超时整场判负，进行中的那局记为退出方认输。掉线不暂停时钟。断线与从离线中重连都当场推给双方，不等下一次状态变化顺带送出。
- **对手可见性**：进行中的局里，对手的每次猜测只下发比较符号（方向与远近）、是否命中共同作品、标签命中个数；角色、数值、作品名与标签文字一律不下发，视图测试以序列化后不含这些内容为准。已结束的局双方完整公开。
- 人机明确标注身份；人机的强度分不出现在任何视图里。真人对手定级后显示整数分，定级中只显示「定级中」。

## 3. 评分、定级与人机计分

- 评分是 Glicko 的两参数形式（分数与偏差，不含波动率）：一场系列赛只结算一次，用系列赛胜率作似然（在单局分差上乘放大系数）。**不逐局结算**：逐局批量会让高分方以 2:1 赢下系列赛反而掉分。结算前按距上次对局的时间回涨偏差，偏差夹在上下限之间。
- **定级**：账号打满定级场数之前只显示进度、不显示分数，分数照常更新。**定级中的账号排队不进真人队列，直接开人机局**，避免定级中的真人互打影响初始分；定级中的人机局一律计分、不占每日额度。
- **人机计分**：人机以「计分分数 + 最大偏差」作为对手参与计算（计分分数见 §5 自动校准），单场影响由偏差自然打折，输赢对称；定级结束后每个北京日只有前若干场人机系列赛计分，之后照常可打但不计分并在审计里写明原因。
- 不计分的系列赛不改分数与偏差，但照样计入场数与胜负平。
- 难度档按**保守分**（分数减偏差）选：新号从最低一档起步，赢得越多、偏差越小，题库自然升档。真人局取双方保守分的平均，人机局取真人的。

## 4. 难度档与题库

- 难度只靠作品广度与年代跨度提升，标签数与主角限定在各档保持不变：减少标签或加入配角带来的难度是信息贫乏而不是推理深度；每档都留在知名角色口径内，不做全集池。
- 排位题库与随机出题**共用同一条热度榜查询与同一条作品主角查询**，两边口径不得分叉。每个角色的先验权重按「先等概率抽作品、再等概率抽主角」累加，答案按这组权重抽，人机的先验也用同一组权重。
- 题库按「难度档 + 北京日」缓存，并发请求共享一次计算，失败不缓存。首猜排名是题库大小平方级的计算，必须留在数据 Worker 里，不回主线程。

## 5. 人机

- **只在本场题库上推理**，并且用与真实判定**同一个**反馈函数生成「猜某角色、答案为某候选时」的反馈签名来过滤候选；人机不偷看答案。
- **开局谱**：人机的第一手从离线开局分析整理出的开局谱里选（数据在 `domain/CEERankedOpeningBook.ts`，按本场题库重新评估切分效果后排序）；开局角色不必在本场题库里，但热度低于下限的不用（人机不用冷门角色开局）。第二手起只在题库内推理。
- **不完美推理**：普通人格只记得最近若干条反馈、每条线索按概率用上，并且只认识题库里一部分角色；不认识答案时只能靠小概率「想起」。人机掌握本场题库名单，完美推理几步就能锁定答案，所以强度主要靠压低知识面与推理可靠度来调。强度按分数锚点插值；锚点在入门档上按线上真人的猜中率、步数与用时标定，以猜中率为主（入门档与多人房默认题库同口径，真人基线可直接对照），参数随分数单调。标定脚本是 `Server/scripts/CEERankedCalibrate.ts`。
- **人格**：每场随机抽一个人格（不连续遇到同一个），同一场不换。普通人格只在强度之上做风格偏移；**爱噶**是固定规则：每局第一手固定猜丰川祥子，之后只在剩余一致候选里按「最坏情况最少」二分选择，选择不使用随机，猜测间隔只按对手分数决定。她有意比同分普通人机难缠（标定为对同分基线人机多数胜出，但不是稳赢），强出的部分记在计分上，见下条。
- **自动校准**：按真人对人机的实际得分反解人机强度相对标称分的系统偏差，普通人格与爱噶各自一组，用法不同。普通人格用「标称分减偏差」生成强度、按标称分计分，让真人对它的期望得分回到标称；爱噶的强度只跟玩家分数走，偏差加到她计分用的分数上，赢她多涨、输给她少掉，难度不被校准拉平。每组有先验（普通人格为 0，爱噶为模拟折算的溢价），样本不足时取先验，样本够了从先验按样本量向估计值收缩，并夹在上限内。

## 6. 匹配

- 队列在 CEE 分片进程的内存里（生产按游戏分片，所有 `cee.*` 落在同一进程）。按分数窗口配对，窗口随等待时间放宽到上限；短时间内不重复匹配同一对手，双方都等待一段时间后解除这条限制，小人群下优先匹配真人。
- 排队满一段时间后玩家可以主动开人机局，不点就继续排；再久仍没排到自动开人机局。审计里记录人机局是主动、超时还是定级进入。
- 从移出队列到开赛之间有多次异步读取：期间账号处于「开赛中」，重复排队被拒、取消不生效；开赛失败把相关玩家置回空闲并记错误日志，不能让玩家停在排队界面。

## 7. 审计记录与结算写库

- 排位记录与通用对局记录分开，单独成组（评级、系列赛、席位、单局、每次猜测），**永久保留，代码里只有插入与评级 upsert**。账号注销时评级行随账号删除，对局席位的账号列置空、记录保留。
- 每次猜测记录服务端时刻、客户端类型、猜前是否检索过与检索时刻（与反作弊特征同口径，人机行为空），供人工复核；代码路径不存在任何自动处罚。
- 一场系列赛的全部审计行与评级在**一个事务**里写入；失败按退避重试，期间该账号不能再排队；全部失败则标记本场未计分，并把完整结算载荷写进错误日志供补录。结算写库不阻塞命令回执。
- 战绩按结束时刻做游标分页（资料带第一页，往前翻用上一页最后一条的结束时刻），多取一条判断有没有更早的，不另发计数查询。
- 全服排行榜只收打满定级赛且未被封禁的账号，按分数排、名字取账号当前昵称；头部名单短缓存、结算写库成功即作废，本人名次每次单独算（榜外也给出）。排行榜与战绩都属于已绑定排位连接才能调的命令。
- 表结构变更走 [Database](Database.md) 的一次性脚本流程，脚本要与 schema 逐句一致（可用 drizzle-kit 按 schema 导出核对）。

## 验收要点

验证命令见 [Testing](../../Agents/Testing.md)。必须覆盖：Bo3 计分、平局不计分与加赛、加赛上限收口、加时与次数追加、认输与退出与离线判负、上下线即时推送、结果页双方各自离开与超时清理、对手视图脱敏、系列赛整场结算与人机打折、定级只打人机与亮分、每日人机计分额度、难度档按保守分升档、题库与出题同口径、爱噶首猜与二分规则、爱噶计分溢价与两组校准的不同用法、准入的四种拒绝、战绩翻页与排行榜口径（定级中不上榜、榜外名次、缓存失效）、队列窗口与重复匹配、主动与超时人机、写库重试与失败、审计五类行与注销口径。
