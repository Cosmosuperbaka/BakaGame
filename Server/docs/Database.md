# 数据库

涉及持久化表结构、表结构变更、连接配置或数据导入时查阅。账号、对局记录的业务规则见 [Account](Account.md)、[GameRecord](GameRecord.md)。表结构、连接参数、脚本名读代码（`Server/src/infrastructure/db/`、`Server/package.json`）。

## 边界

- ORM 为 Drizzle（MySQL 协议），连接串来自 `DATABASE_URL`，必须包含库名。
- 数据库承载账号、身份徽章、用户设置、运行期旋钮、词库、对局记录、排位评级与排位审计记录（规则见 [CEERanked](CEERanked.md)）、审计、反馈、访问统计与状态页数据（历史日格、实时样本、状态事件）。**房间与对局实时状态仍为纯内存**，不读写数据库。状态页数据按部署环境标记分行：开发与生产共用一个库时互不可见。
- `app_setting` 只存 `T3` 运行期旋钮的**覆盖值**，环境变量同名项是缺省：没配数据库、库没起或读不到行时一律按缺省执行，行为与引入这张表之前一致。键、校验与生效值解释只有一份定义（`src/shared/RuntimeSettings.ts`），新增旋钮改这里，不改表结构。凭据、监听地址与来源名单永远不进这张表（分层见 [Conventions §5](../../Agents/Conventions.md)）。
- 旋钮的读取**同步**走内存快照：准入检查在握手与请求路径上，不能为一个版本号去等数据库。因此数据库故障只会让旋钮退回上一次读到的值，不会把玩法打挂。
- 游客游玩不依赖数据库：`/readyz` 不检查数据库；数据库故障时账号相关功能报错，游戏照常。
- 生产环境缺 `DATABASE_URL` 必须拒绝启动；本地开发与隔离测试不配置时，账号相关功能整体关闭，词对不落库。

## 连接

- 唯一入口是 `db/Database.ts` 的 `createDatabase`：强制 TLS 且校验证书，不提供明文开关；时间列按 UTC 读写，业务“自然日”按北京时间在写入前换算成日期字符串，不依赖库端时区。
- 创建即开始连通性检查（有限重试），结果暴露为 `ready`；所有仓储写入先 `await database.ready`。连不上只记错误日志，相关功能持续报错，不阻断启动。**服务启动不改表结构。**
- 停机时随资源释放关闭连接池，仓储自身未完成的写入由排空阶段处理。

## Schema 与表结构变更

- 表结构唯一真相源是 `db/Schema.ts`；属性名即 Better Auth 字段名（适配器按属性名映射），列名蛇形。
- 时间列一律 `datetime(3)`，不用 `timestamp`（2038 溢出，远期封禁时间放不下）。
- 仓库不保留迁移历史。空库或开发库用 `db:push` 按 schema 直接建表；**已有数据的库不用 push**（它按差异直接改表，可能删列丢数据）。
- 已有数据的库要跟上 schema 变更时，把这次变更写成一份**一次性 SQL 脚本**（统一放 `Server/oneoff/`，执行完即删），与改 schema 的代码同批提交，用 `db:oneoff` 在每个环境显式执行一次（先 `--dry-run` 核对语句）；所有环境都执行过后在下一次提交里删除脚本。脚本只做本次变更，不依赖任何前序脚本。
- 一次性脚本要能在「新代码 + 旧表」与「旧代码 + 新表」两种组合下都不出错：先加列（可空或带缺省）、再改代码读写、确认无旧版本运行后才删列，删列与改代码不在同一次发布里。MySQL 的 DDL 会隐式提交、无法整体回滚，执行器逐条执行并在失败处停下报序号，回退按脚本反向手写。
- 徽章目录不写进表结构脚本：目录行在启动时按 `shared/Badges.ts` 幂等补齐，并删除已下线的类型（授予关系随之级联删除，佩戴中的徽章由外键置空）。
- 注册序号 `user_registration` 的存量回填也在启动时按注册时间补齐，不写在表结构脚本里；序号由应用层按「当前最大值 + 1」分配，**不用数据库自增**——托管库 TiDB 的自增按缓存段预取（`AUTO_ID_CACHE` 默认一段 30000），先行者的「前 N 名」判定会被跳号顶穿。序号连续、注销后不回收。佩戴状态是 `user.equipped_badge`，外键指向徽章目录，徽章删除时置空。
- 按表达式分组（如按北京时间切日）的**单表**查询要按别名分组：Drizzle 在 SELECT 里省略表名、在 GROUP BY 里保留，开启严格 `only_full_group_by` 的库会把两者视为不同表达式而报错。内存仓储测不出，此类查询须经真实库冒烟。
- 词对按 `(word_a, word_b)` 唯一，入库前经 `normalizeWordPair` 规范化；重复提交累加使用次数。批量导入脚本重复执行安全，格式错误的条目整体失败，不静默跳过。

## 测试

- 单元与集成测试不连真实数据库：服务以可选依赖注入仓储，未注入即不落库。
- 仓储的 SQL 口径由**打在 mysql2 连接层的桩**覆盖：`drizzle()` 与查询构建器仍是生产那一套，桩只实现连接的 `query()`，因此断言的是实际生成的语句文本、占位符参数与行列解码，而不是对着手写假接口自证。行按 SELECT 列表的列序给数组，时间列给驱动的 UTC 文本，写操作给 `insertId` / `affectedRows`。
- 这类用例查的是「无库可跑」时最容易溜过去的东西：环境隔离条件、按别名分组的 `only_full_group_by` 写法、upsert 的覆盖列、分页与计数是否同条件、`$defaultFn` / `$onUpdateFn` 补的时间列、数据库未就绪时是否整体失败而不发半截语句。**新增或改写仓储时同批带上这类用例**，不把缺口留给「以后补」，也不用下调覆盖率阈值来掩盖（见 [Testing §门禁](../../Agents/Testing.md#门禁)）。
- 对真实库的验证（表结构脚本、写入、聚合）属于一次性人工验收，结束后恢复被改动的数据，不进 CI。
