# 数据库

涉及持久化表结构、迁移、连接配置或数据导入时查阅。账号、对局记录的业务规则见 [Account](Account.md)、[GameRecord](GameRecord.md)。表结构、连接参数、脚本名读代码（`Server/src/infrastructure/db/`、`Server/drizzle/`、`Server/package.json`）。

## 边界

- ORM 为 Drizzle（MySQL 协议），连接串来自 `DATABASE_URL`，必须包含库名。
- 数据库承载账号、身份徽章、用户设置、运行期旋钮、词库、对局记录、审计、反馈、访问统计与状态页数据（历史日格、实时样本、状态事件）。**房间与对局实时状态仍为纯内存**，不读写数据库。状态页数据按部署环境标记分行：开发与生产共用一个库时互不可见。
- `app_setting` 只存 `T3` 运行期旋钮的**覆盖值**，环境变量同名项是缺省：没配数据库、库没起或读不到行时一律按缺省执行，行为与引入这张表之前一致。键、校验与生效值解释只有一份定义（`src/shared/RuntimeSettings.ts`），新增旋钮改这里，不改表结构。凭据、监听地址与来源名单永远不进这张表（分层见 [Conventions §5](../../Agents/Conventions.md)）。
- 旋钮的读取**同步**走内存快照：准入检查在握手与请求路径上，不能为一个版本号去等数据库。因此数据库故障只会让旋钮退回上一次读到的值，不会把玩法打挂。
- 游客游玩不依赖数据库：`/readyz` 不检查数据库；数据库故障时账号相关功能报错，游戏照常。
- 生产环境缺 `DATABASE_URL` 必须拒绝启动；本地开发与隔离测试不配置时，账号相关功能整体关闭，词对不落库。

## 连接

- 唯一入口是 `db/Database.ts` 的 `createDatabase`：强制 TLS 且校验证书，不提供明文开关；时间列按 UTC 读写，业务“自然日”按北京时间在写入前换算成日期字符串，不依赖库端时区。
- 创建即开始应用迁移，结果暴露为 `ready`；所有仓储写入先 `await database.ready`。迁移失败只记错误日志，相关功能持续报错，不阻断启动。
- 停机时随资源释放关闭连接池，仓储自身未完成的写入由排空阶段处理。

## Schema 与迁移

- 表结构唯一真相源是 `db/Schema.ts`；属性名即 Better Auth 字段名（适配器按属性名映射），列名蛇形。
- 时间列一律 `datetime(3)`，不用 `timestamp`（2038 溢出，远期封禁时间放不下）。
- 改 schema 后用 Server 的 `db:generate` 生成迁移（不连库），迁移文件进 Git，服务启动时自动应用。**不手写或手改已发布的迁移 SQL。**
- 徽章目录不写进迁移 SQL：`0009_badges` 只新增 `badge` 与 `user_badge`，不修改既有表，回滚按 `user_badge` → `badge` 顺序删表即可；目录行在启动时按 `shared/Badges.ts` 幂等补齐。
- 按表达式分组（如按北京时间切日）的**单表**查询要按别名分组：Drizzle 在 SELECT 里省略表名、在 GROUP BY 里保留，开启严格 `only_full_group_by` 的库会把两者视为不同表达式而报错。内存仓储测不出，此类查询须经真实库冒烟。
- 词对按 `(word_a, word_b)` 唯一，入库前经 `normalizeWordPair` 规范化；重复提交累加使用次数。批量导入脚本重复执行安全，格式错误的条目整体失败，不静默跳过。

## 测试

- 单元与集成测试不连真实数据库：服务以可选依赖注入仓储，未注入即不落库。
- 对真实库的验证（迁移、写入、聚合）属于一次性人工验收，结束后恢复被改动的数据，不进 CI。
