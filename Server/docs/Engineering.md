# 服务端工程约束

修改实时同步、传输层、日志与遥测、健康检查、停机、HTTP 契约或出口安全时查阅。跨端原则见 [Spec](../../Agents/Spec.md)。阈值、常量、环境变量名、路径读代码（`Server/src/transport/`、`config/`、`infrastructure/`），本文只记约束与理由。

## 1. 实时网络必须节约带宽

- 实时状态默认使用带修订号的增量消息（RFC 6902），不得在每个业务动作后无条件向全房重复发送完整快照或未变化的私有状态。
- 状态通道必须保留最终同步能力：首次加入、重连、修订号缺口、补丁应用失败、周期校准、补丁累计过多、单次补丁体积接近全量时，强制发完整状态；客户端缺少基线时不得猜测或跳过补丁。
- 同一事实只通过一个生产通道发布：版本化状态已包含的变化，不再广播客户端不消费的重复事件；聊天等列表变化不得同时由事件追加和状态补丁追加。
- 滑动窗口数组（如聊天）的下行编码依赖“挤出最旧、追加最新”的形状；改成定长覆盖、换序或环形队列必须两端同步改，否则补丁静默错位。
- 文本输入、高频草稿、自动保存必须防抖或合并，连续修改只提交最新值，不按每个按键触发全房广播。
- 向全体大厅订阅者下发的房间列表必须走合并窗：窗内多次变更并为一次下发，尾沿保证突发停止后最后一次变更仍被带出；新订阅者只取自己那一份，不得为一个人打开大厅而向全服重发整张表。
- 「每帧自带完整视图」的全量刷新帧（如大厅列表）与差量状态帧共用同一条出站积压水位：越过水位一并丢弃，回落后由下一帧补回；两条丢弃闸门各自回滞，丢一份列表不得把快照的补丁链打回全量。ACK、错误与聊天等有去无回的帧永远不在可丢集合内。
- 生产 WebSocket 优先保证各平台连接兼容性：消息压缩全局关闭（部分 iOS WebKit 客户端协商失败），只有运行时支持可靠的按客户端协商并完成 iOS 回归后才允许重新启用。
- 修改公开快照、私有状态、广播频率或封包时必须运行网络容量测试，估算出口不得超过其设定预算（基线与预算读测试）。大厅列表的变体按人均帧数、帧率上界与变更到可见的延迟判定，合并窗收益与逐变更扇出在同一夹具内对照。

## 2. 可观测性

### 追踪与会话隔离

- 客户端每次与服务端交互必须生成全局唯一的 Trace ID（含时间戳、单调计数器与随机熵），禁止跨连接的小整数自增 id。
- HTTP 响应头回传 trace id；WebSocket 的 ACK 与错误包回传 trace id；日志把它作为一级索引字段。自建 `Response` 会绕过框架写头的那一层，由全局响应映射钩子统一补齐缺失头。
- 请求没带自有追踪号时沿用上游已开的 W3C 或 Sentry trace-id，最后才自造：日志、OTLP 与 Sentry 必须能用同一个号串起来，不能各自生成一套互不相识的标识。调用方自带的追踪号（请求头、WS 信封）不可信：只认 UUID 或 32 位十六进制两种形状，其余丢弃，不进日志、OTLP 与 Sentry 的任何字段；进 OTLP 时无法规整的号取摘要，不补零。
- WS 校验失败诊断只记录类型、长度与键数：任意属性名和无效 id/type/trace 也能承载敏感文本，不复制到 stdout、OTLP 或 Sentry；关联字段只在错误回包返还原请求方。

### 结构化日志与脱敏

- 禁止空 `catch {}` 或无上下文的裸字符串报错。捕获的异常必须走结构化日志，并保留 name、message、stack 与完整 cause 链；附加业务元数据全部序列化输出，不只打静态标题。
- 敏感信息在输出前必须物理脱敏：身份凭证（cookie、session、authorization）保留极短前缀用于定位；密码与登录验证码、口令类（可重放的短期凭据）**全量掩码**，且自由文本通道同样清理。
- 上游音源的取流直链按**只摘查询串、保留 host 与 path** 处理：签名参数名随音源而变，认不出来就等于外发，而 host+path 正是判断「解灰命中了哪个音源」的唯一排障线索。键名点名直链（audioUrl 一类）时不看路径形状——代理地址常常没有扩展名。同一条链的控制台、本地结构化文件、OTLP、Sentry 四个出口必须共用这一收口，不能只在某一层做。
- 必须保留明文的开发期输出（本地联调验证码）走仅控制台的本地输出，不进结构化文件、OTLP 或 Sentry。结构化 info/warn/error 一律视为会被长期保存与外送的数据。
- 脱敏函数必须有最大递归深度保护，防深层或循环引用栈溢出。服务端不开放把匿名请求体写进日志的打点接口：前端事件只经 Sentry 隧道上报，没有调用方的匿名写日志入口一律删除。
- OTLP 导出器：固定缓冲上限（溢出淘汰最旧并统计丢弃数）；校验响应状态，超时/限流/5xx/网络异常时未发送批次回退队列头部，其余 4xx 是对端明确拒收，重发无益，批次直接丢弃并计数（同样进退避，避免持续撞一个必败的对端）；**丢弃数必须从外部看得见**（溢出与拒收按信号和原因汇总成指标），否则「日志少了」读不出是被丢的；连续失败有限指数退避；飞行并发锁与网络超时；停机时提供排空契约。导出的日志与本地文件**共用同一份记录与同一套属性编码**：追踪号写在 LogRecord 顶层（后端据此串起日志与追踪，不写进属性），数值属性保持数值类型；入站 HTTP 请求的 span 是服务端类型，其余进程内操作为内部类型。不另写第二套编码——两套编码必然漂移。

### 本地 OTel 日志与人类控制台

- **两个出口面向不同读者，不得混用**：结构化出口写一行一条 OTLP/JSON，供 Agent 与长期排障；控制台写给定宽、可截断、可着色的人类视图。禁止再把结构化 JSON 直接打到 stdout/stderr。
- 结构化文件按**部署环境**命名，默认落在 `Server/storage/logs`（以代码为准）；开发与生产即使共用同一台机器也不得写进同一个文件。按 UTC 日轮转并带分段上限，历史文件的保留清理由部署侧负责。
- 每条记录必须带 `service.name`、`service.namespace`、`deployment.environment` 与 `host.name` 资源属性；严重级别用 OTel 数字与文本双写；异常使用 `exception.type/message/stacktrace/cause` 语义属性，正文中文。
- 操作记录默认只覆盖失败、慢操作与显式关键事件（`LOG_OPERATIONS` 可切到全量）；**控制台永远不逐条打印成功请求**。debug 只进入结构化文件，不送 OTLP/Sentry，也不打印。
- 控制台固定列宽并中文展示；正文与字段按显示宽度截断（CJK 计两列），字段只取人工白名单里的短值，URL 只显示 host。异常只显示类型、短消息与首个调用帧；过长消息只留类型，完整栈与 SQL 等长文本只进结构化文件。连续重复记录在短窗口内合并并标注次数。
- 文件写入分两档：**告警及以上立即同步落盘**（进程被强杀前的最后一条错误、停机看门狗的强制终止日志必须在盘上），信息与调试记录进内存缓冲、按短周期或体量阈值合并成一次写入，不再每条日志阻塞一次事件循环；强杀时低级别记录最多丢一个合并窗口，停机时先 flush、关闭文件出口再退出。**文件必须有容量上限**：单文件有字节上限，超限滚到下一个分段，每日分段数也封顶，封顶后当日记录直接丢弃并提示一次——日志洪水只能占满一个确定的磁盘配额，不能无限增长。目录不可写等故障只停用文件出口并告警一次，不得阻塞启动或业务。
- **日志级别只有一张口径表**：告警级必须稀缺，否则真正的告警被正常流量淹没，远端的日志与事件配额也被它耗光。级别由「谁的错」决定，不由状态码是否异常决定：

  | 类别 | 级别 | 理由 |
  |---|---|---|
  | 调用方的错：参数不合法、未登录、无权限、房间或资源不存在、口令错、房间已满、被限流、业务阶段不对 | 信息 | 预期流量；失败仍进结构化文件当排障线索，不上控制台 |
  | 扫描探测命中的未注册路径 | 调试 | 互联网背景噪音，只留按固定桶聚合的指标计数 |
  | 服务端的错：未预期异常、上游或依赖不可用（5xx） | 错误 | 要有人看；异常事件只走一条路，不再同时写一条同内容的远端日志 |
  | 需要人看的安全事件：客户端完整性拒绝、证明链被拒、异常来源 | 告警 | 由发现点显式记一条，操作日志对同一件事不再重复记告警 |
  | 玩家掉线、房间因空置关闭等生命周期事件 | 信息 | 常态 |

  告警级的预期安全事件会被旧版客户端或扫描放大成同一件事成百上千次：这类调用必须按键节流（窗口内只记一条，被压制的条数进指标，下一条带上 `suppressed`），键表有上限。控制台的连续相同行合并只服务人眼，不能替代文件与远端出口的节流。

  操作日志的级别缺省取自状态码（4xx 信息、5xx 错误），只有口径之外的特例才显式覆盖；新增调用点不得自己按状态码再写一份映射。
- 远端配额按价值分配：Sentry Logs 收系统日志与告警级以上的领域事件，领域事件的信息级常态流量只进本地文件与 OTLP，事件量由按事件计数的指标承担；操作的 span 与指标不因本地过滤而缺失（成功操作的耗时分布是慢命令排查的依据）。
- 控制台颜色由 `LOG_CONSOLE_COLOR` 决定，`auto` 只在 TTY 着色；容器日志不得依赖 ANSI 才能读。
- 文件出口与 OTel/Sentry 的**级别过滤相互独立**：本地只记失败与慢操作，不代表指标、span 或远端事件可以缺失；反过来，远端通道故障也不得让本地文件停止记录。

### Sentry 与隧道

- 前端上报统一通过后端隧道中转，隧道对信封头的目标主机与项目标识做白名单鉴权，杜绝开放代理与内网 SSRF。浏览器到后端是跨域，不能把隧道称为同源网关。
- **主机白名单必须精确**（官方摄取域名模式或显式配置的私有部署主机），禁止 `includes("sentry")` 之类模糊匹配；仅放行 `https` 与默认端口；上游路径强校验项目标识格式；载荷有上限、请求有超时、应用级限流。
- 上游错误必须脱敏为通用响应，不暴露内部拓扑与堆栈。**上游状态码不原样透传**：只保留“该退避（429）”与“上游不可用（5xx）”两类信号，其余折叠为统一的上游拒绝，避免替匿名调用方确认 DSN 吊销或项目不存在。上游 429 必须带退避头：优先转达上游值（封顶），无则用本地窗口剩余时间。
- **上游网络失败识别必须覆盖全运行时**（Node 旧文案、Bun 文案、undici 错误码、errno 的不同大小写形态），并下钻 cause 链。网络抖动与超时降级为 warn 并回 502/504，只有真正未预期的内部异常才允许 error 与 500。
- 服务端 Cron 心跳只允许生产环境上报（dev 实例会顶替生产心跳掩盖真实停机）；心跳间隔必须不大于监控判定裕度，排程、判定参数与监控标识同居一个真相源模块，随 check-in 一并 upsert。具体监控标识不进文档。
- **采集链路自身的故障不得进 `ignoreErrors`**：忽略名单只装可判别的预期客户端断连文案，禁止宽子串（如按底层错误文案过滤）——同一子串会连其它上游的真实网络故障一起抹掉，「没有事件」就再也读不出「没有故障」。隧道自身故障走专用出口：每次故障一个计数指标点，聚合 issue 按代码里的限速间隔至多一条；上游返回 5xx（经隧道转发的客户端事件整批丢失）与抛异常降级同样进这条出口。上游 4xx 折叠是调用方 DSN 问题、429 是退避指令，都不计入隧道故障，防止坏客户端刷歪指标。
- **环境标记缺省即安全失败**：配了遥测凭据却没有显式注入部署环境标记（来源链任一非空；空赋值视同未设置）时，遥测初始化直接拒绝启动，不允许静默回落 development——那会让生产心跳停报、事件与本地开发流量同池且事后不可区分。

### 健康检查探针

- 存活探针 `/livez`：只验证进程与事件循环，O(1)，不挂数据库或外部 I/O（避免抖动触发反复重启）。
- 就绪探针 `/readyz`：停机状态立即回 503 使上游停止分配新流量；**这只摘流，不等于拒绝新连接**——进程内的新握手要靠同一份停机状态直接拒，见 §3；**数据库不参与就绪判定**（游客游玩不依赖它，数据库故障不得摘流）。边界见 [Database](Database.md)。
- `/health` 保留给监控大屏，匿名只回量级（一位有效数字），精确值要求维护令牌（常量时间比较）并按来源限流；在线房间数、连接数这类量级不得无条件对外精确可读。响应带部署环境标记：环境是「显式注入还是猜的」关系到心跳与事件池归属，部署后可直接对它断言，不必等 missed check-in 再倒查。
- `/livez`、`/readyz` 是负载均衡的契约，**不设额度**（被扫爆导致误摘流的后果比被扫更严重）。

### 公开状态页

- **可用率只按有结论的样本算**：探测失败记为异常；「未知」只表示没有结论（未接入监测、监测本身取不到），计入样本数但不进可用率分母，既不把「没接入」压成 0%，也不抬高真实故障。窗口可用率从原始计数累加，不从四舍五入后的格子比例反推。
- **上游读数以服务端直连探测为底**：服务端自己访问各上游接口，拿到 HTTP 应答且非 5xx 即算可达，计时到响应头、不消费响应体；**403 与 429 例外**——那是对端在封禁或限流我们，应答不能证明服务可用，读作没有结论而不是正常，否则出口被封时状态页仍是一片绿。配置了外部监测时由它定等级，它没给出延迟时由直连探测补。直连读数按缓存节流，不随页面推送频率打上游；外部监测失败也短暂缓存，故障期间不逐次重打一个已经出问题的上游。
- 出站探测一律不自动跟随跳转（[Deployment](../../Agents/Deployment.md) §3）。外部探针在服务装配处注入，应用装配的单测不得因状态接口触网。
- 前端探测地址未单独配置时，取可信来源名单里第一个公网来源；本机与内网来源只在没有公网来源时兜底，避免生产里探一个容器内连不上的地址、把正常的前端误报成异常。
- 公开接口只给等级、延迟与可用率；在线人数、房间数这类经营指标不出接口。
- **账本写回的是绝对值，所以读回必须先于写回且与启动期样本求和**：采样器不等历史读回就开始记账，读回覆盖会丢掉启动几秒的样本，写回早于读回会把库里的旧账整格覆盖。读回与内存累计求和，写回前等读回完成；读回失败过则写回前先重试，仍失败就保留待写集合，不拿只有新样本的值去覆盖旧账。
- **日格与实时格同口径累计延迟**：格子按「和值 + 个数」累计带延迟读数的样本，读时求均值，没有延迟读数的样本不冒充 0ms；窗口均值按样本加权（样本多的日子权重大），不是各格日均的简单平均。

### 全局异常

必须注册 `unhandledRejection` 与 `uncaughtException`：未处理拒绝记 ERROR，未捕获同步异常记录并触发优雅停机。

## 3. 优雅停机

- 标准时序：标记停机状态（readiness 熔断）→ 停定时器与巡检 → 向全部在线长连接广播停机事件 → 留出摘流缓冲窗口 → **把内存里的房间状态落盘** → 排空已发起的数据库写入 → 依次关闭监听、释放资源、排空遥测；全部成功才以 0 退出。
- **排空集合覆盖每一条在途写队列，不是只覆盖某一款游戏**：可排队写入的队列按项逐项排空（队列归谁拥有就暴露在哪一层的公开 API 上），多项写入共用一条队列时排那一条，不重复造等价 API；确实没有可排队写入的服务要能给出证据。任一项失败不跳过其余项。
- **停机状态必须同时驱动「摘流」与「拒绝新连接」**：readiness 回 503 只让上游停止分配新流量，进程内的新握手照样会完成升级，排空窗口因此永远等不到「没有新连接」的那一刻。两者必须由同一份停机状态驱动，并给出可判别的拒绝码（新连接的握手/入房入口在停机中直接拒）。
- **预通知与最终停机分离**：维护接口只广播并置停机状态（摘流），不提前退出或排空持久化；最终停机用独立的共享任务去重，不能以 readiness 标志判断已清理；重复信号或致命异常共用同一任务，各阶段只执行一次。
- **清理失败隔离**：每个阶段单独捕获并记录（带阶段名与完整堆栈），某步拒绝不跳过剩余资源关闭；遥测 flush/close 返回失败同样算失败；完成其余清理后以非 0 退出，不把失败伪装成正常。
- **必须有总看门狗，且不得 `unref()`**：外部 I/O 或套接字挂起时由它兜底强制退出；`unref` 的定时器在事件循环转空时不会触发，挂起的停机会以退出码 0 收场（假成功）。正常路径必须 `clearTimeout`，因此持有它不会拖慢退出。
- **停机总预算是单一命名常量**，各阶段耗时从它推导，不在编排里散写数字；到点必须先留下一条「强制终止」日志（带预算与已完成/未完成阶段）再以非 0 退出，静默消失的停机不算可诊断的停机。数值以代码为准。
- **总预算必须严格小于编排侧的停止宽限**（容器或编排器在 SIGTERM 后杀进程前的等待时间），否则进程在写出强制终止日志之前被 SIGKILL，退出原因不可读。两处分属进程常量与部署脚本，必须有用例断言它们的大小关系与重启显式带上宽限。
- **房间状态在广播之后、排空之前落盘**，且落盘失败不阻断后续阶段：快照是这一局能不能续上的唯一依据，必须赶在排空（可能要等对局记录收尾）之前写完；但它同样跑在停机预算里，一次写失败不该让关监听与遥测出口来不及执行。存储介质必须不依赖网络——最需要它的时刻恰好是最不稳的时刻。
- **快照按游戏分开存放，并由「片角色」决定谁读谁写**：同一份代码目录会被多个进程挂载共享，合在一起时只接一款流量的进程会把别的游戏的房间一并恢复成无人可连的影子房间。片角色写错必须拒绝启动：静默回落到「全部负责」正好让这条防线失效。
- **快照读到即消费**：快照只代表最后一次优雅停机时的状态，启动读到后无论恢复成功、失败还是过期丢弃都要清掉；否则恢复后再被强杀、OOM 或回滚（不经优雅停机、不写新快照）时，同一份旧状态会被再恢复一次。
- **快照里有座位令牌与口令摘要，按凭据对待**：目录与文件只给属主读写；清除与替换后不得残留在空闲页与 WAL 里（删除即清零、检查点截断）。座位令牌只存摘要属于更根本的收紧，需要连同重连比对一起改，尚未做。
- **恢复时时间字段按语义分两类处理**：截止时刻按停机时长平移（停机期间没人能操作），空房、掉线、空闲三类计时从恢复时刻重新起算（停机不是人走了）。混为一谈会让房间在恢复瞬间被回收，而且不报错——日志里只有「房间消失」，看不出原因。
- **停机前广播的语义是「原地待命」而不是「退房」**：客户端保留会话票据、留在房间页等重连，服务端恢复后凭原票据接回原位。恢复后房间已不在时，客户端说明情况并退回大厅，不得按房号自动重建：同号新房会让后刷新的人只看到座位失效。客户端提前清票据等于把唯一能回去的凭据扔了。
- 回归证据边界：停机的集成测试与冒烟只能证明监听器编排，不冒充操作系统实际信号投递；平台原生信号验收需要在 Linux/容器环境执行。

## 4. 传输与 HTTP 契约

### 来源身份与限流

- 客户端身份由统一解析函数产出：优先采信边缘层在回源请求上写入的真实 IP 标头，**且必须能解析成 IP 字面量**，否则退回运行时的真实对端地址。`X-Forwarded-For` 可被客户端任意伪造，任何场景都不得参与分桶。
- 解析函数还兼容读取一个旧的真实地址标头（改名前的默认值，只用于已发布边缘配置的过渡），它排在新标头之后。**移除条件**：边缘确认只写新标头之后，下一个版本直接删掉旧名读取与相关用例；在此之前不得再给它加新用途。
- 采信该标头的前提是**源站只被边缘回源访问**，这由部署侧保证，应用内排除不了，所以对端桶与全局桶必须保留。限流器必须是三层桶（单客户端 / 回源对端 / 全局），无 socket 的请求共用一个桶。标头名是代码与边缘配置的同步契约，改名必须两侧同批；各条限流口径不得漂移。
- 限流器公开入口返回结论（是否放行、重试等待、重置时间、额度、剩余），布尔只是它的投影；多层桶返回**第一个被拒的桶**。多层桶的记账必须全有或全无，并从最细的键查起：被细键拒绝的请求不得消耗粗键额度，否则单个来源超额后的持续请求会耗尽全局额度，把全站挤出去。
- 任何 429 必须带限流呈现头与 `Retry-After`（滑动窗口取“最早一次请求出窗”的剩余时间）。缺少这些头，重试方只能猜。
- WebSocket 握手配额两层都要卡（在途连接数与新建速率），在 Origin 与 Agent 标记之后、任何查库或换票之前占名额；拒绝必须 **throw**（upgrade 钩子的返回值被框架忽略）。名额以租约持有：`open` 确认、`close` 归还，未在时限内确认的租约自动归还，归还幂等且不依赖业务连接注销成功——升级可能在钩子之后失败（畸形握手、后续步骤抛错、客户端中途断开），那时 `open` 与 `close` 都不会触发。占位之后的步骤抛错要当场归还。网关层对握手必需头不合格的升级先回 400，不进钩子、不占名额。
- **实时入口只有一条路径**：`/api/ws` 同时承载三款游戏与站点通道，按信封 `game`（显式优先）与命令前缀分发；`/api/whoisfaker/ws` 等旧路径只为已发布客户端保留别名，新增能力不得再开新路径。解析必须发生在分发之后：三张命令表的信封都拒绝未知字段，先统一校验会把 `game` 与别款游戏的字段判成非法。
- **连接按需登记进游戏服务**：一条统一连接在第一次使用某款游戏时才登记进该服务，关闭时只注销已登记的那些。一次登记三份会把一条连接在在线数里数三次，并在没碰过的游戏里留下永不订阅的影子记录。
- **「对每一款游戏做同一件事」只有两处登记，都按玩法标识映射**：组合根产出的服务表（应用层）与传输层的端点表（协议、日志前缀、命令归属、建房闸门键加承载它的服务）。登记连接、消息分发、关闭注销、站点页准入与发布、巡检、健康聚合、停机通知、快照目标与信封里的玩法标识校验，一律从这两处取，不得再手写三叉或三行；新增一款时漏登记必须是编译错误。三款服务仍是具名独立的三个位置，没有哪一款是宿主。分发时三款的命令类型不同，经泛型函数落到单个端点，不把三个端点塞进同一个数组丢掉各自的类型。
- **服务端时刻只随命令的确认帧下发**（可选字段，旧客户端忽略即可），供客户端估算本机时钟偏差。事件帧与快照帧走公共封包、一次封装多处复用，不得为时间戳加字段；也不另设对时命令。
- **站点通道由传输层自己处理**（`site.subscribe` / `site.focus` / `site.leave`，标签页身份见下节），不进任何游戏服务：它只有公开的「谁在哪一页做什么」，字段是封闭集合，控件焦点与逐字输入进度不得进来；`site.focus` 只接受握手时声明为 Agent 的连接。活动按 TTL 过期，不设清理定时器。

### 模式开关

- 每个能单独暂停的玩法对应一个运行期旋钮（`enable*Entry`），键与模式的对照只在 `src/shared/SiteFeatures.ts` 与 `src/shared/RuntimeSettings.ts` 各一份；`GET /api/site/config` 原样下发全部开关，响应 `no-store`。新增模式时两处同批登记，旧字段只增不删，已发布客户端靠「少字段按开放」兼容。
- 关掉的模式**只拦建房**：建房闸门挂在 WS 分发处，统一入口与旧路径别名共用一个判定，回 `MODE_CLOSED`。加入已有房间、断线重连和局内命令一律放行，正在玩的人能把这局打完。单人局与多人房按建房载荷区分；CEE 增强房与原版房共用一个开关。
- 排位开关只停首页入口，不进建房闸门：上线前的灰度需要直连可用，排位准入另见 [CEERanked](CEERanked.md)。
- 闸门每条建房命令现读内存快照，不缓存结论；未装配开关（隔离测试、没有数据库）时全部放行。

### 测试房

- **测试房是部署侧开关启用的特权，不是房号的属性。** 三款玩法都有一间约定房号的测试房（单人开局、调试指令、调试信息、豁免回收），生产上任何人都能新建同号房，所以特权不能只凭「房号对上」给出。开关是运行期旋钮，缺省关闭、不随部署形态推断（缺少部署标记时推断会静默失效）；需要测试房的本地开发、端到端测试与测试夹具各自显式打开，生产不打开。
- 策略对象由组合根构造一份、注入三款玩法与对局记录包装，`domain/TestRooms.ts` 是唯一判定点：玩法代码不得再自行比较房号与测试房号。策略每次现读开关，调用方不缓存结论；开关在房间存续期间关闭时，该房立即退回普通房，不留半特权。
- **关闭时测试房号是非法房号**：`ensureRoomId` 对它与其它非法房号同码同文案，不泄漏「这是测试房号」，也探测不出开关状态。
- 测试房的豁免只限「无人在线时不立即回收空房」，不触及房主不变量：房主掉线照常带重连宽限，宽限内新进来的人不接任，宽限过后才改选。特权不能让房主身份变成「谁先到谁是」。
- 测试指令只在策略认定的测试房里受理，并要求房主；非测试房里一律等同未知指令，同样不给探测者区分「开关关了」与「这间房不是测试房」的信号。调试信息（如调试身份）只向策略认定的测试房下发。
- 测试房不写对局记录：记录器在组合根经 `skipTestRooms` 包装，玩法服务不感知。

### 标签页身份

- **一张标签页就是一个人**：身份的生命周期等于标签页，刷新、前进后退、站内跳转、退房再进都不变，关闭即失效。三款游戏的玩家、座位、观战与聊天归属都按这份身份算；同账号的两张标签页是两个人，账号只表达登录态，不参与座位归属。
- **只有站点连接能分配**：任意页面一进入就建立的站点连接用 `site.session.claim` 领取或续用；游戏连接用 `site.session.attach` 挂上站点连接领到的身份，不分配、不参与冲突判定。身份在业务命令之前绑定，一条连接只绑定一次：中途改绑等于让已入座的连接换了主人。
- **不并成一条连接**：游戏连接的开合就是座位在线与否，通道证明票据又绑在握手上，CEE 换票必须重建连接；并成一条会让一款游戏的重连掐断别处的座位。身份统一已经满足「同一个人」，连接继续按需建立。站点连接本就常驻，身份不增加连接数与心跳，握手配额、Origin 校验与 Agent 准入都不变。
- **令牌是持有者凭证**：只在标签页存储与首帧之间传递，不进 URL（长寿命凭证会落进访问与边缘日志）。服务端只留摘要作身份键，挂在连接记录上供内部派生，不进快照、私有状态、聊天、MCP 视图、日志与任何下行帧。
- **对外只有派生的玩家号**：玩家号由身份键单向派生，按「游戏 + 房间」隔离。确定性派生让退房再进、服务端重启后都回到同一个号，且不需要存映射；拿到它既反推不出身份，也关联不到同一张标签页的其它房间。派生号的格式不得落入房间快照回收发号计数器的规则。
- **身份不登记、不过期，服务端只索引在线持有者**：重启后标签页要凭原令牌认回恢复的席位，所以不校验「是否由本进程签发」；自造令牌也只是一张没有席位的新标签页。在线索引按连接登记、断开即摘，规模以在线连接数为上界，不设清理定时器。
- **一份身份只能有一张开着的标签页**：复制标签页与 `window.open` 会继承 sessionStorage。客户端在页面加载时同步判定并丢弃继承来的身份与座位凭证，服务端是最后一道：领取时已有在线持有者就探测它，应答则后来者是复制品、发新身份，超时或断开则是刷新残留、后来者接管。探测有等待上限，只发生在旧连接未断的窄窗口；只认被探测连接自己的应答。
- **席位归属**：重连与再次加入时，座位凭证或标签页身份任一对上都回到原座位，不重复核对口令，也不与自己撞名；被踢的记录不算座位。回到原座位与重连共用同一段准入判定，不另写一份。
- **座位凭证继续是座位级**：`sessionToken` 只管一个座位，标签页令牌不替代它，也都不交给 Agent。
- **回执带进程级 epoch**：领取与挂接都带回，重启后两种连接谁先连上由退避决定，游戏连接先到时也要在恢复房间之前知道服务端重启过，客户端才能把「房间消失」讲准。
- **Agent 不持有标签页身份**：握手声明为 Agent 的连接绑定一律拒绝。接管人类页面时 Agent 也拿不到身份：租约挂在站点连接领到的身份上，Agent 只拿到一个会话号。
- **未绑定身份的连接按旧方式发号**：已发布的壳与部署瞬间在线的旧页面不发身份帧，退回每个座位一份随机玩家号的行为，协议不抬版本；新页面遇到不认识领取命令的旧服务端同样按无身份继续。这是明确批准的兼容范围，旧路径别名下线时一并收掉。

### HTTP 错误信封

- HTTP 失败只有一种形状：`{ error: { code, message, traceId } }`，由统一函数产出，与全局错误钩子完全一致。路由内禁止回临时的字符串形状。RPC 路径是唯一例外（客户端把其形状解成 RPC 错误），但 `code` 与 `message` 口径仍与全局信封一致。
- `code` 是大写下划线机器码，`message` 是给人看的中文；判定只认 `code`，不解析 `message`。
- **响应映射钩子每个分支都必须显式返回原值**：框架把钩子的 `undefined` 产出当成“响应就是这个 undefined”，随手 `return;` 会让所有 4xx/5xx 变成状态码正常、响应体为空串。

### 请求与帧边界

- WebSocket 单帧载荷必须有硬上限；HTTP 请求体必须用运行时原生上限（框架没有对应选项，缺省值形同不设），取值留足最大合法载荷的余量，并保留 413 回归。
- CORS 对称开放所有业务端点所需的方法，并把追踪头放入预检放行，防分域部署时遥测被静默拦截。
- 来源校验放行私有局域网网段（面对面联机）；WebSocket 与 HTTP 共用同一个来源校验函数。WebSocket 的 Origin 只在全局请求闸里判一次（覆盖所有升级路径，先于任何升级钩子），钩子里不再重复。不带 Origin 的升级放行：浏览器的跨站升级一定带它，不带的只可能是 MCP 进程与本地工具，它们本来就能伪造该头；放行路径计数留作收紧的依据。公开的状态页实时通道同样按来源限并发，不能只有全局名额。
- 监听地址与对外公开地址解耦（容器内默认监听全网卡）；本地持久化介质默认基于模块位置寻址，不依赖 `process.cwd()`；环境变量的启动期校验分两类：必填项与速率、容量类取值写错即以配置错误中断，不静默回退；有意宽松的只有两处——客户端最低版本门槛由运行期设置校验（可在线改，启动期拒启的代价高于收益），采样率类取值不合法时回退默认（偏差只影响观测精度，不值得让服务起不来）。新增环境变量默认归入强校验，要宽松须说明理由。
- 配了持久化凭据却没有显式注入部署环境标记时，环境会被推测成开发环境，生产专属校验静默失效：启动时记一次告警（同一进程只记一次），不拒启；带遥测凭据的情形另由遥测初始化门拒启。
- 时间：服务端日志、持久化与接口时间一律标准 ISO-8601 UTC 或 UTC 毫秒，禁止裸本地时区函数拼接无偏移时间。
- **出站帧只经工厂构造**：事件与回执一律用 `createEvent` / `createAck` 产出，禁止在业务代码里手写 `{ type: "event", ... }` 字面量。帧形状变更时手写字面量会漏改，发出与其余帧形态不同的包。

### 出口收紧

- **安全响应头只在一处登记**，由全局钩子写入并补到所有自建响应上，禁止逐路由自己加（新增路由默认不带就是静默回退）。
- CSP 放宽只允许给文档页，API 响应本身不返回 HTML，不跟着放宽。HSTS 等条件性收紧项按真实链路判定（读转发协议头，边缘不得剥离或改写）。
- **由数据决定的 `content-type` 不得直回浏览器**：库里的类型与上游响应头都可被旁路写入，只认图片白名单，白名单外降级为 `application/octet-stream` 并保留 `nosniff`。

## 5. Agent（MCP）接入

- MCP 有两条入口：独立 stdio 进程（`Server/src/mcp/`，`bun run mcp`）与站内远程 Streamable HTTP 端点（`/api/mcp`）。两者共用 `Server/src/mcp/Tools.ts` 的工具表，且都**不得嵌入**三款游戏的服务端逻辑，只以普通玩家身份走现有 WebSocket 协议。
- `MCP_ENABLED` 是总开关，缺省 false；关闭时服务端在握手阶段直接拒绝声明为 Agent 的连接，远程端点返回不可用。Agent 连接通过 `?agent=1`（或 `x-bakagame-agent: 1`）自报身份，服务端只把它当作准入与展示标记，不能用来证明客户端类型。
- 站内必须提供机器可读发现：`.well-known/mcp.json`、`.well-known/mcp/server-card.json` 与 `llms.txt` 指向同一远程端点；Agent 只拿到站点链接即可自行发现并连接，不依赖人工转述。玩家侧不设公开说明页。
- 发现文件按转发头与 Host 还原公网地址，但两者都由调用方控制、结果又可公共缓存：还原出的 origin 必须是站点前端或服务端自己的公开来源（不复用 WebSocket 的来源白名单，那份还放行内嵌壳与私网互认），否则退回配置的服务地址，响应带 `Vary` 按转发头分缓存——否则一次请求就能把指向他人主机的端点种进缓存。
- **发现端点必须有一条绕开 SPA 兜底的路径**：前端静态托管的路由顺序是「静态资源 → 边缘函数 → 兜底」，未命中静态资源的请求会拿到首页 HTML，而只有 `/api/*` 由边缘反代到后端。因此三条发现路由同时提供 `/api` 前缀别名（`/api/.well-known/mcp.json`、`/api/.well-known/mcp/server-card.json`、`/api/mcp/server-card`），两套路径共用同一个 handler；返回体里的 `serverCard` 一律指向别名，否则根路径被兜底时 Agent 会读到一份 HTML。`Client/public/.well-known/mcp.json` 只是静态指路（端点、`serverCard`、`canonical`、`llms.txt`），**不复制**启用状态、反作弊声明与工具清单——那些只由别名下的活数据回答，测试锚定两边端点同源。
- 三款房间设置的 `allowAgents` 缺省 false，传输层保持可选：旧客户端 / 旧快照 / 旧原版设置没有该字段时一律按关闭处理，不能因此拒绝建房或恢复房间；Agent 进入被关闭的房间返回 `AGENTS_NOT_ALLOWED`。大厅摘要必须暴露该字段，房间卡片据此显示 MCP 徽标。
- Agent 写操作限流：stdio 按「Agent + 游戏 + 房间」；远程入口同时按会话与来源 IP 计——会话号由调用方决定、可随手新开，只按会话计等于不设限。远程会话表按来源封顶，满表时拒绝新会话，不得挤掉其他来源的会话（建会话不需要凭据，挤掉别人等于让匿名方把他人的 Agent 连同座位踢下线）。同一来源满额时也只回收已闲置的旧会话：云端 Agent 平台从共享出口发起调用，同一来源背后可能是互不相识的用户，单来源额度与写额度都要按这种场景留。每次工具调用写一条审计日志（Agent、工具、动作、房间、结果、耗时），不记录聊天正文、密码、会话凭证或控制器令牌。
- **远程会话的出站目标与生命周期**：Agent 的游戏连接只连服务端自己的回环地址，目标来自服务端配置，不得取自请求的 `Host` 或转发头；站点公开基址只用来拼人类可达的页面链接。回环只能到达本进程：按游戏拆成多个进程部署时，MCP 入口所在进程未必负责目标游戏，届时入口与游戏分流必须一并设计，不能沿用回环。会话表满额时回收闲置够久、且既无座位也无页面租约的最旧会话，不能让匿名方用少数来源占满全表；同一会话的工具调用串行执行，排队与持有都有上限，挂起的调用不得永久堵住后续调用。会话号是承载凭证，日志只记不可逆的短摘要，来源同理。
- SongGuessr 开局仍要求房间内有人类登录网易云或 QQ 音乐账号；Agent 听不了音频，屏幕 `panel.audio` 只下发片段区间与歌词开关，房间关闭歌词时不下发歌词行；任何屏幕字段与点击反馈都不得带上游音轨地址或可反推歌曲标识的字段，否则等于直接交出答案。
- 原版 CEE 房不支持 `allowAgents`，按默认关闭处理：Agent 不得进入。
- **使用边界必须写进协议层**：`initialize`、`server/discover` 与工具描述都要明确声明「本 MCP 只能用于纯 Agent 自行游玩，严禁用于辅助人类作弊」。这是产品红线，不能只依赖页面文案。
- **隐藏文档不等于隐藏协议**：玩家侧不展示接入文档页，配对码只出现在设置与房间的 MCP 设置项；机器发现仍保留 `llms.txt`、`.well-known/mcp.json` 与 `server-card`，供只拿到站点链接的 Agent 使用。
- **会话边界**：远程 MCP 的一个 Agent 会话是跨三款游戏与站点通道的统一会话（一条 `/api/ws` 连接）。站点通道承载标签页身份与公开的 Agent 活动（`site.*`），不承载房间状态。
- **任意工具调用都绑定会话**：不再要求「先建房/进房」才有会话，首次调用即建立并回传 `session`；唯一的无状态工具是 `get_mcp_policy`。站点活动靠这条连接连续上报，临开临关会让首页指示器闪一下就没。
- **导航面只有一张表**：`get_site_map` 与 `visit_page` 依据服务端登记的路径表工作，只写导航事实（路径、用途、可达条件），不复制页面文案；`list_rooms` 标记 `joinable`，Agent 只加入开启 MCP 的房间。

### 标签页接管

人类把页面交给 Agent 只有这一条模型，首页、大厅、设置与房间内没有差别。

- **接管的对象是标签页，不是座位**：Agent 操作的是人类自己的页面，用的是这张标签页本来的连接与座位。服务端不给 Agent 任何游戏连接、座位凭证或标签页身份，它唯一的入口是租约；人类座位因此不存在「被别人拿走」的路径，Agent 连接直接认领或重连人类座位一律拒绝。
- **只有站内远程 MCP 能接管**：stdio 进程没有可绑定的浏览器连接，页面能力经窄接口注入，缺它时工具明确报错，不做静默降级。
- **配对码一次有效、短时效**：页面发起、Agent 认领，认领即作废，未认领时断线即失效。Agent 连接不能发起接管。一个 Agent 会话只驱动一张标签页。
- **租约按标签页身份记账**：刷新只是换一条连接，身份不变，断线后保留一个等待窗口让同一身份认回来，页面继续锁定、焦点继续。复制出来的标签页身份不同，接不上。等待窗口的长度两端共用一处定义，页面据此判断接管是否已断。
- **任何一方都能立刻结束**：人类收回不需要 Agent 配合，本地先解锁再通知服务端；Agent 会话结束立刻解锁；远程 MCP 是无状态 HTTP，收不到断开信号，所以租约另设闲置上限。页面要告诉人类结束的原因。
- **Agent 与人类看到的是同一份**：`page_state` 只从渲染好的 DOM 取人类此刻能看到的内容，不读 Store 与存储，隐藏、透明、模糊与屏幕阅读器专用的内容都跳过。服务端不为接管另发任何字段，也不做脱敏：别人的私有信息本来就不发给这张标签页，这张标签页主人能看到的，Agent 才看得到。
- **Agent 与人类走同一条操作路径**：`page_act` 在真实控件上回放事件，命令由页面自己的连接发出，校验、敏感词检测与游戏规则都不绕过。工具表不保留按动作直接改状态的捷径接口。
- **敏感边界两层**：页面按白名单（管理后台、账号、登录、排位不在其中，服务端拦导航，页面在读取与每步动作前再拦一次，停在受限页面时只能读取和离开）；页内敏感区域由 `data-agent-sensitive` 标注，读不到也点不了，新增账号、登录、第三方凭据或配对相关的界面必须标注。站外链接与下载一律拒绝，回车和空格按点击同等检查，密码框只报存在、不报内容。
- **房间的知情权**：`allowAgents` 同样约束接管。坐在没开 MCP 的房间里不能认领，接管中的标签页进不了这样的房间，新建的房间强制开启；原版 CEE 房、排位与反作弊房不开放。被接管的座位在公开快照里带 `mcpControlled`，同房玩家看得到，这一状态由连接所在的标签页实时回答，不落盘。
- **锁定是交互层的**：服务端分不清页面发出的命令来自人类还是 Agent，也不需要分：两者都是座位主人自己的这张标签页，绕过前端锁只影响他自己，碰不到别人的座位或信息。不要在服务端按「接管中」拒绝命令，页面的自动命令（同步、就绪上报等）会被误伤。
- **Agent 自有座位是另一回事**：`create_room` / `join_room` / `get_screen` / `ui_run` 是没有人类页面时的独立 Agent 玩家（stdio 的唯一形态），背后没有人可接管，走服务端的同构界面；局内写操作只能走界面控件，`type` 必须作用于当前焦点，每步返回玩家可见的全量视图。接管期间这组工具一律拒绝，否则同一个 Agent 能绕开页面直接发命令；坐在自有座位上也不能接管。
- **MCP 读取边界必须与玩家对等**：工具只能返回玩家本可看到的信息，不得新增任何「玩家界面拿不到、但 MCP 能拿到」的字段；工具实现不得调用任何会返回他席答案的接口。

## 6. 用户文本的敏感词检测

- **服务端是唯一权威。** 所有「用户输入且其他玩家可见」的文本在写入房间状态前必须经过敏感词检测：房间名、昵称（含改名）、聊天、卧底词语与描述、白板提示与猜词草稿、猜角色自填提示、Agent 名称。新增这类入口时同步接入；搜索框、仅自己可见的内容、系统下发的词语不检测。客户端不做拦截，不能作为绕过依据。
- **命中即拒绝写入。** 抛 `TEXT_SENSITIVE`，文案固定为「内容包含不允许的词语，请修改」，不回显命中的词，不静默改写，不替换成星号。存量数据不回溯，只在写入时检查。校验放在会改动状态之前，失败不留半成品。
- **匹配口径。** 自动机启动时构建一次，耗时与文本长度线性相关。文本先做繁简、全半角、大小写归一，再剥掉一切非字母数字字符（空白、标点、零宽、控制字符），所以插空格或插符号的规避写法同样命中；纯 ASCII 词按整词判定（连续单字符片段视为一个词），避免误伤更长的英文单词。单字词、纯数字词和过短的 ASCII 词不启用。
- **词表与误伤治理。** 词库来自 konsheng/Sensitive-lexicon（MIT），来源、提交与收录文件记录在词表数据文件内，由构建脚本生成；广告、网址、泛化词表误伤过多不收录，并已登记到开源致谢。作品名、角色名、曲名里的合法命中靠白名单：整词停用通用词汇，或以完整名称短语放行（命中完全落在短语内才放行，跨出边界照常拦截）。扩充词表或白名单后，用本地作品、角色与曲库名称重新统计误伤，再提交。
- **测试只用占位词。** 通过注入词表覆盖，测试文件里不出现真实敏感词。
