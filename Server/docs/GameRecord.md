# 对局记录

涉及对局记录的写入、保留、字段口径或按记录做统计时查阅。表结构与连接见 [Database](Database.md)；字段与表读 `Schema.ts` 和 `domain/GameRecord.ts`。

## 边界

- 一局 = 一个房间从创建到销毁；局内每次结算 = 一个回合。记录按“一局 + 若干回合”保存。
- 记录只服务后台复盘与统计，不承担实时回放，也不反向影响对局。
- 三款游戏地位相同：在“一次结算”时经端口 `GameRecorder` 交一个回合，房间销毁时调 `finishRoom` 收尾。服务以可选依赖注入，未配置数据库即不注入、不落库。
- 猜猜呗只记录增强房：原版房的对局在上游服务器进行，本端拿不到完整答案与全员猜测。
- 猜猜呗的结算散落在多条领域路径，但都以一次发布收尾；必须按结算摘要对象去重，结算后的多次发布只记一个回合。
- 摘要只放复盘需要的最小信息，不放歌词、音频地址、cookie、头像等大字段或敏感字段。
- 玩家行分两层：局级累计总分（按 `playerId` 合并各回合增量）与回合内的得分增量。`userId` 取连接上的登录身份，游客为空。

## 落库与保留

- `GameRecordService` 按房间会话聚合并串行写入（同一局的回合按结算顺序落库，聚合行不会被旧快照覆盖）。**写失败只记告警，绝不抛回游戏服务。** 数据库不可用时待写回合有积压上限，超出丢弃并告警。
- 单个回合的时间线有序列化上限，超出保留前段并追加截断标记；后台详情的合并时间线出口另有上限。
- 记录永久保留，不按时间清理。
- 未走销毁流程（如进程重启）时记录停在最后一个回合的结束时刻，仍是一条完整的一局。
- 按日统计以北京时间切日，与访问统计同口径；“对局”按房间行计数，“参与人次”按每局去重玩家数累加。

## 验收要点

验证范围见 [Testing](../../Agents/Testing.md)。必须覆盖：同房多回合聚合成一局、玩家分数累计、写入失败隔离、时间线截断、重复回合与销毁后迟到回合被忽略、空房间不落库、三款游戏结算各交一个回合。真实库验证属一次性人工验收，结束后删除测试数据。
