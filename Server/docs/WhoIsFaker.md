# 谁是卧底：规则、权限与状态机约束

修改 WhoIsFaker 规则、协议、权限、房间状态或断线处理时使用本文。纯视觉改动查 [DesignGuide](../../Client/docs/DesignGuide.md)。阶段名、字段、常量、人数阈值、命令名读代码（`Server/src/shared/WhoIsFaker.ts`、`domain/Rules.ts`、`application/WhoIsFakerService.ts`）。

## 1. 架构铁律

- 信封与同步类型引用 `shared/Protocol.ts`，领域命令引用 `shared/WhoIsFaker.ts`，不在文档里复制接口。公开/私有通道的全量与补丁同步、基线隔离与容量要求见 [Spec](../../Agents/Spec.md)。
- **纯内存状态机**：房间与对局状态只在内存；数据库只异步记录词对与对局结果，不参与实时状态。
- **双快照**：公共快照（全员相同）与私有状态（连接专属：本人词语、天使候选、白板词性提示、出题人底牌、本人真实选票）严格分离。**前端不得从公共快照推断任何私有信息**，私有信息只来自私有状态；sessionToken、词语、本人行动不得并入共享公开视图。
- 业务拒绝统一抛带业务错误码的 `AppError`，由传输层打包为错误包，不在应用层零散构造。
- 广播视图：同一次发布最多生成有限几种公开投影，同权限连接复用同一对象；缓存只活在本次发布内，不跨房间、阶段或后续广播保留；不得深冻结状态机仍持有的领域数据。分组依据始终是 `canViewerAccessGhostChat`，不是单独的 membership（活跃阶段的旁观出题人仍看不到 ghost）。性能声明以网络预算测试为准，不把本地准备次数的减少表述为生产收益。

## 2. 会话与连接

- sessionToken 按房间隔离存在当前标签页的 `sessionStorage`，仅昵称保留在 `localStorage`；刷新可 `room.reconnect` 恢复，新标签页是独立访客。
- 建房、加入与恢复会话先校验目标房间、密码、昵称与会话资格，**被拒绝的请求不得改变原绑定**。成功换房按原席位断线处理（保留可恢复会话）；连接绑定不能独立于玩家生命周期清空，旧席位状态与新绑定在首个异步等待前完成，防止同号建房、同名加入的校验与写入被并发穿透。
- **掉线按需暂停**：只有掉线玩家正在阻塞流程（未提交发言、未投票、夜间行动未执行、白板猜词中）才进入房主决策队列；已完成本轮动作的掉线直接忽略，不暂停倒计时。阶段跨越时重新核算离线玩家是否阻塞新阶段。出题人掉线不走普通决策队列，走专用的重连宽限倒计时。
- 孤儿空房由定期巡检清理。**测试房**不因闲置或全员掉线而回收；该豁免只有一个判据函数，只出现在巡检的空房回收和空房计时起点两处。真人**显式离开**测试房仍会关闭它，改这里时不要把“显式离开”误当成“全员离线”而顺手加豁免。

## 3. 规则与状态机

- 阶段流转：等待 → 指定出题人 → 出题 → 描述 → 投票 → 反馈 → 平票 PK / 夜晚 → 反馈 → 次日描述（循环）；白板猜词是可打断的全局阻塞阶段；结算归档后 `gameOver`。阶段的精确集合以代码为准。
- **反馈阶段**：投票、平票 PK、夜晚、白板猜词结算后先进入 `feedback`，结果写进公共快照，由本局出题人点继续推进（测试房可由房内任何人继续）。决出胜负时同样**先反馈再结算**。
  - 出局在结算那一刻落地，续接动作只存服务端，继续时才执行；`feedback.next` 只是服务端预判，客户端只用于展示下一步状态，反馈期间有人离场则按当时局面重算。
  - 投票反馈公开全部选票（含弃票）；夜晚反馈只公布出局者，**不公开凶手**；白板猜词反馈只给最终两词、对错与是否经裁定。
  - 反馈阶段没有倒计时，白板不能在此插入猜词；停顿只由反馈阶段承载，不得另设旁路事件。
- **全局历史**按时间顺序记录投票（含平票）、夜晚、白板猜词与对局中途离场，描述阶段不记；夜晚条目带行动者身份与目标，只在结算页公开。结算页有全局历史时以它为准，不再并列渲染旧的明细块。
- 房主没有准备态：开局只看其他参与者，客户端不得替房主自动发准备指令；快照里房主恒视为已准备（存储字段不改），与猜歌、CEE 同口径。
- 卧底人数由人数公式决定；白板与天使需达到人数门槛，真相源是 `getRoomRoleLimits()`，客户端提示与之对齐。
- 胜负：好人（卧底全部出局）、卧底（存活卧底 ≥ 存活平民）、白板（猜中两词）、流局（出题人被踢/重连超时/房主解散）。
- 死亡身份揭露开关：关闭时死亡玩家的角色在公共快照中严格保持未定义，仅出题人、旁观者或 `gameOver` 才揭露。

## 4. 发言与补充发言

- 发言记录分常规、平票 PK、补充三类；`speechMode` 驱动前端差异化展示发言列，不新增顶级阶段。
- 补充发言：常规发言完毕后至投票结算前，出题人可指定任意玩家补充。期间已投选票完整保留，但禁止新投票、撤销与强制推进；**未完成补充本身是推进阻塞条件**。进入补充必须重算掉线待决并运行机器人补交；各完成路径（真人、机器人、超时、强移除）统一清理补充计时器并恢复原阶段。最后补充者在白板打断期间离场，只更新挂起的恢复目标，不提前退出猜词。
- 手动推进先通过权限、阶段及完成性校验再撤销当前计时器；被拒请求不得改变倒计时状态。
- 发言顺位序号在提交时固化为 1-based 整数，每轮从该轮首位发言玩家起顺时针递增，后续重排不改历史。发言构造器只接受作者 `id/name`，名册里已无此人的超时记录用最小占位身份，不伪造完整玩家实体。

## 5. 白板猜词

白板猜词是**全局阻塞阶段**：整房暂停一切倒计时，全员围观。

- 每局仅一次机会。发起猜词打断发言阶段时必须暂存当前阶段剩余时间，裁定未通过或超时切回时精确恢复，不得丢失或重置为初始全长；嵌套上下文（描述、补充、PK）保留在本局中，各条恢复路径统一从这些真相源恢复发言模式、原票及剩余计时。恢复出来的定时器与正常调度的定时器共用同一条超时守卫，因此**比对基准一律取调度时刻捕获的阶段、发言模式与 PK 档位**：在触发时刻现读 `round.phase` 等于拿当前值和它自己比，守卫恒成立，迟到的定时器会把已经走远的阶段再推进一次。
- 草稿节流广播给全房围观；草稿允许未完成输入，到期时空词、同词或规范化后为空均形成失败记录并收束；正式提交仍严格拒绝非法词对，不先消耗机会。
- 自动比对未精确匹配时**不直接宣告失败**，而挂起等待出题人人工裁定（避免错别字/同义词误杀）；批准则白板获胜，否决则机会耗尽（残局触发按残局结算，否则退回原阶段）。真实词对只通过私有状态下发给出题人。无论结果，都先进入阶段反馈。
- 平票 PK 中白板被投出触发猜词，期间白板离场：必须保护暂存的平票上下文，避免内部流转阶段意外冲刷；扣除后平票候选 ≤ 1 人时自动收束平票并推进到夜晚；推进阶段处也要自愈——平票上下文丢失或候选不足时降级安全转入夜晚，不抛阻断性致命异常。
- **手动主持的截止语义（Spec 的领域例外）**：在线白板猜词与人工裁定不自动创建固定截止；本局出题人可选择时长、取消或重新开启计时，取消只撤销计时，不消耗/恢复机会、不撤销裁定权限，也不留隐藏硬截止。聊天会刷新房间闲置时间，所以闲置关闭不能充当这两个阶段的有限截止。此例外不新增默认时限。
- “主持人”指本局**出题人**，不等于房主；转让房主不转让这组权限。房主不能用普通阶段推进绕过猜词，但可移出白板收束猜词，或移出出题人使本局中止。普通推进拒绝跳过白板是规则，不代表授权出口失效。
- 白板掉线待决先由出题人选择等待或移除；选择等待会挂载可取消/重开的兜底计时（因此不是不可取消的硬上限）。离线席位清理、出题人重连宽限、主动离开/被踢收束是独立机制，不能冒称为在线白板的自动截止。
- 回归必须覆盖：普通房间多真实参赛者、聊天续活、人工裁定、计时开/取消/重开、掉线等待与恢复、离场/被踢、房主与出题人分离；验证要实际执行授权推进出口，不得以缺少 deadline 字段直接判定死锁。

## 6. 投票

- 当前玩家已投目标的唯一受信任来源是私有状态里的“我的当前选票”，**严禁在组件内私自缓存选票**。
- 投票/平票阶段可随时撤销己方选票重选。弃权票是有效提交（计入“全员已投票”推进条件），但不计入任何玩家得票；弃权达到最高票直接进入平票 PK。

## 7. 标记与房主权限

- 玩家对他人的身份标记纯前端本地，不持久化、不上报。出题人与旁观者直接展示服务端下发的真实身份。
- **旁观者的上帝视角由独立开关决定，与「允许旁观」正交**：进场资格与进场后能看到多少是两件事，默认只给资格不给答案。开关关闭时局中不得向旁观者下发双侧答案、全员身份与投票/夜杀预览，服务端按连接直接不下发这些字段，前端不做「收到但藏起来」的过滤；出题人的上帝视角属于主持职责，不受该开关影响。结算属于答案公开时刻，旁观者照常拿到全部答案，因此收紧只作用于局中。开关只在局外可改，与其余房间设置同口径。
- 房主可在任意阶段踢出掉线玩家或转让房主；踢出当前出题人导致流局。

## 8. 播报与聊天

- 阶段播报统一由发布流程中的单一出口广播，**严禁**在命令处理函数中零散追加系统消息。
- 旁观者在等待、指定出题人、出题阶段留在公共主聊天频道；对局活跃期才流转到观战专属频道。

## 9. 测试房

房号为测试房名时自动启用测试模式，允许调试指令（跳阶段、改自身角色、增减仿真机器人）。调试指令必须只在测试房生效，机器人要占用真实席位、参与发言与投票。
