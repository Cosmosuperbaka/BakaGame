# 网易云音乐 API 使用规范

涉及 `NeteaseMusicProvider`、登录、歌曲请求、缓存或音频行为时使用本文。歌词见 [SonGuessrLyrics](SonGuessrLyrics.md)。具体常量、函数、接口名读代码；上游踩过的坑见本机 `.agent-notes/pitfalls-netease.md`（不入库）。

## 资料与版本

- 接口行为以锁定依赖 `@neteasecloudmusicapienhanced/api` 的实际导出为准，版本见 `Server/package.json` 与根级 `pnpm-lock.yaml`。官方文档可能有缓存，与代码版本不一致时以依赖导出为准。
- 优先复用接口包的函数，不自行拼装请求 URL，不直接 import 它的传递依赖或内部目录（上游改目录即整条失效，还会绕开 provider 的限流队列与出口 IP 归属）。

## 安全与使用边界

1. 不使用第三方在线 Demo 服务，不向其提交账号、密码、手机号、邮箱或 Cookie。
2. 仅用于学习与开发。尊重版权、服务条款与平台规则，不得侵犯版权、绕过付费限制或滥用流量。
3. 生产服务不得从环境变量读取网易云 Cookie。正式登录只能由房主在客户端完成，Cookie 只在房间内临时存在于服务端内存，不得写入日志、快照、聊天、测试输出，也不得发给其他玩家。客户端只收到必要的登录 ACK。
4. 环境文件里的真实接口测试 Cookie 只供显式运行真实接口测试使用，禁止在应用启动、房间创建或普通测试中读取，不得提交到 Git。没有凭据或授权时先完成 Mock 回归，并在交付说明里报告真实接口未验证。

## 请求、缓存与频率限制

- 不高频重复调用登录接口；登录态校验结果必须缓存复用，玩家反复进出房间不得每次都触发上游往返。
- 启动阶段必须预热音乐上游（不阻塞启动，失败只记告警），否则第一位进房玩家会替全进程垫付冷启动成本。
- 限流判定必须同时覆盖多种响应码形态，且同时检查 `body.code` 与 HTTP status，不能只认一种。
- 退避起点必须与上游限流恢复窗口同量级（分钟级）；过短的退避会把一次限流放大成长时间的全服不可用。
- 本地队列拥塞与上游限流必须用不同错误码编码，否则线上排查方向会跑偏。
- 生产环境靠合理缓存、请求合并与按连接配额解决限流，不通过无限重试放大请求，也不用代理池规避账号、版权或频率限制。
- 对完全相同的 URL 上游会短时缓存。需要绕过时只在确认必要的调用点加入明确、可测试的缓存策略，不对登录、搜索、播放地址接口无条件追加随机参数。

### 出口 IP

上游按“请求方声称的出口 IP”（`realIP`，落到 `X-Real-IP`）同时判定登录凭证归属与限流配额。约束：

- **scope 必须跟随登录会话，而非 cookie 内容。** 扫码登录整条链路（取 key、创建二维码、轮询、设备上报、状态校验）共用同一出口 IP，会话结束后把该 IP 固化到登录后凭证的 scope。
- `login_status` 必须携带 `realIP`；可选调用包装必须与主调用一样透传 `randomCNIP` 等出口参数；设备上报的兜底路径同样要带。
- 匿名请求按玩家分桶，不同玩家不互相占用配额；匿名会话与公共请求的 IP 独立于登录会话。
- 出口的调用点必须**显式声明自己属于哪个 scope**：请求驱动的走玩家作用域，定时维护一类的后台任务走显式命名的匿名作用域。缺作用域时不得静默归到共享出口——那会把多个玩家的配额并成一个桶、上游风控只看成一个来源；回落必须留下可观测信号（限频告警 + 计数指标），否则配额隔离失效与上游异常码都无法归因。新增调用点若既没包作用域又没显式声明，按缺陷处理。
- 限流兜底时允许刷新触发限流的那个 scope 的出口 IP（可用性优先，不是常态）。
- cookie 对象做 scope 用键序无关的稳定序列化。
- `realIP` 只用于出口兼容与限流兜底后的恢复，不得用于放大请求量、绕过账号或版权限制，也不得伪造用户来源。生成 IP 必须来自接口包自带的 CN 网段库，禁止手工拼接；不要为此 import 包内会打印日志的工具模块，也不得为屏蔽第三方日志而改写全局 `console.log`。数据文件缺失或损坏时回退到内置兜底网段，不得抛错导致无法出网。
- `randomCNIP` 必须与 `realIP` 成对下发；`noCookie` 只用于不需要登录态的公开请求；`ua` 只在接口确实要求时设置，值保持可审计。

### 图片与分页

- 图片优先在展示层按需缩放，不无上限地广播或缓存大图。
- 分页接口根据 `more` 递增并设上限，不能因为 `more` 无限请求；搜索结果限制单次数量，不把整张歌单推给客户端。

## 猜歌接入约束

### 请求链路

- 所有歌曲相关请求都经过 `NeteaseMusicProvider`。猜测歌曲只读元数据，不请求歌词或音频；出题歌曲才取详情、歌词、播放地址、百科与副歌。
- 登录仅支持二维码，创建与轮询采用官方 PC 客户端契约，并携带自定义设备名；登录成功后上报设备名只调用接口包的原生模块，缺模块时静默降级。
- 播放地址优先用稳定接口，后备接口可能抛公钥缺失，不能只判断函数是否存在就直接调用。播放地址在服务端统一转 HTTPS。
- **解灰**：默认开启（可由环境变量或 provider 选项控制）。官方未提供地址、返回试听片段或 404 的受限歌曲自动解灰，只使用接口包公开接口。
  - 必须显式指定音源顺序，并拒收一切指回官方外链的“伪解灰”结果，继续尝试下一个音源；全部失败才抛 `SONG_UNAVAILABLE`。改动音源顺序或新增音源时保留该校验。
  - 必须有单源与总预算的超时上界；用 `Promise.race` 加超时时必须同时给原 Promise 挂 `catch`（超时后才拒绝会是 unhandledRejection，Bun 会终止进程）。
  - “能不能播”只认总字节 ÷ 时长落在正常码率区间，不能看 200/206 或 content-type。拿到 `freeTrialInfo` 时不得把官方 url 当可用地址，绝不回退返回试听片段。账号会员状态不参与出题可用性判定，选曲链路不得按 `requiresVip` 预剔除候选。
- 副歌无数据时平滑降级为无副歌信息，客户端回退到整曲起点。

### 服务会话与异步结果归属

- 房间音乐认证“最新请求意图获胜”：发起前占有认证操作标识，返回后复核房间、当前标识、席位与房主；清除账号、离房和房主变更使旧认证失效，迟到结果不得恢复或覆盖账号。开局复验只能更新其开始时捕获的同一会话。
- 客户端装载本机凭据必须是有界重试事务（同房间、席位、凭据只允许一个事务，确定性拒绝不重试），不能退化成“只发一次”。
- 自动开局与下一轮在安装回合前复核当前操作、阶段与调用归属；失败回滚和释放加载锁只属于原操作。
- 猜歌、猜番校验期间拒绝放弃，两种题型共用同一互斥语义；异步校验失败仍补偿预占配额。
- 房间设置先在副本中完成校验再整体提交；被拒绝的设置不得改变任何现有设置。
- 猜番候选解析只对“歌曲不可用/未找到”继续尝试，音乐依赖限流、会话失效等全局失败原样透传（保留错误细节），不能降级成“没有关联歌曲”。
- 音频准备与答题使用独立时钟：准备有宽限，全体未就绪时巡检在宽限后强制进入可答态且不扣配额；答题/硬截止在首个就绪时才锚定；聊天续活不能延长回合硬截止。回合硬截止必须覆盖全部猜测窗口及每次回源校验的裕量，不能按单次窗口计算，否则第一次超时后的倒计时会被逐次截短，最后一次几乎提交即判超时。
- 巡检落账存在空窗（旧窗口到期到巡检记超时之间）：期间提交的猜测先补记旧窗口超时并重开下一段窗口，本次提交按新窗口继续，不能拿已过期的截止时刻直接拒绝；回合硬截止已过则与巡检一致强制结算整回合，不再受理猜测。
- 手动出题的选题阶段是全房唯一的推进者：时限从指定出题人起算，每次提交尝试重新顺延；超时、出题人断线、离房、被踢都退回选出题人，并同时写房间公告与快照里的提示字段，不写原因玩家只会看到页面莫名回到选人。
- 出题提交请求客户端不设超时（长任务），默认超时会把仍在装配的题目报成失败，导致重复选歌。

### 房间账号池取号

- 池子由各玩家贡献的账号组成；「可用」只取决于开关开着且不在冷却，与贡献者是否在线、当前在途数无关。
- 每号并发上限与改造前 provider 的全局并发一致；多号的总容量按「单号上限 × 号数」叠加，不额外做池级总闸。
- 所有可用号都达到单号上限时，请求在房间队列里等空位，任一租约归还或池子变化即唤醒重试；等待超时后取在途最少的可用号直接跑，交给 provider 自己的队列。**繁忙不是降级条件。**
- 只有该平台**没有任何可用凭据**（未配置、全部冷却、或没有满足会员档的号）时才省略该平台凭据：QQ 改用匿名补充检索（受运行期开关与熔断控制，只保证免费曲可播），网易云走匿名/解灰。降级不能发生在「有号但在忙」时。
- 共有曲目由哪一侧代表按房间能力决定：两边都有账号时网易云优先；只有 QQ 账号时 QQ 优先，避免默认归到本房没有直接凭据的一侧。该偏好只影响主实体与同分决胜，不压过相关度。
- 匿名 QQ 只是补充源：会员专享曲仍按池内会员账号判定；匿名检索有限流，不能当作稳定全量音源，也不用于自动出题。
- 租约必须成对释放（成功失败都要），释放同时唤醒等号者；房间关闭、号主离房、关开关、凭据判死都要唤醒，否则等号请求会白等到超时。

### 组队

与 CEE 增强房同一口径（见 [CEE](CEE.md)）；单人房没有队伍。

- 回合按“作答单元”记账：同队队员共用已用次数、结果与限时；个人、人机与出题人各自成单元；人机不入队。
- 一人猜中全队结束，分数只记给猜中者。未开血战时任一玩家猜对就结束整局，开血战才继续到全部单元结束。
- “下轮加入”席位预约只在**轮次起点**结算；选定出题人并提交题目的安装回合步骤不是轮次起点，在那里结算会让席位在回合中途被换掉。
- 旁观者被指定为出题人后照常操作音乐，其余旁观者仍然拒绝。
- 出题人的队友本局观战：能看到答案与全房猜测，不能作答，不计入回合完成判定。
- 可指定的出题人由服务端计算并只发给房主；没有候选时手动开局被拒绝，指定名单外的人被拒绝，轮换出题只在候选中轮转。客户端只用这份名单，不自行筛选。

### 服务端缓存

- 公共歌曲数据按不带 Cookie 的键共享缓存；Cookie 只参与需要登录态的请求，且经摘要后才进缓存键，原文不进缓存或日志。播放地址按 Cookie 单独缓存，避免把授权态或易失效 URL 共享给其他请求。
- 缓存有条目数与字节上限，LRU 淘汰；TTL 按数据稳定性区分，软过期返回旧值并后台刷新（仅在队列空闲且未处于限流冷却时），硬过期必须重新请求。长时间没有用户主动请求时暂停预刷新并清理低命中条目。
- 空结果默认也按 TTL 缓存，表示“上游暂时没有该数据”。**例外：重试可能成功的取值（播放地址）不得缓存空结果**，空地址直接抛 `SONG_UNAVAILABLE`、下次重新回源。判据是“重试可能成功”，上游确实没有的数据（副歌、百科、元数据）空结果照旧缓存。
- 浏览器报告播放地址失效时，服务端删除该作用域的旧 URL，强制请求一次新地址并广播最新快照；新地址仍不可用才向前端返回音乐错误。

### 客户端只读查询复用

客户端对**只读**查询统一走“命中即复用 + 同键合并”窗口（`Client/src/lib/QueryReuse.ts`）。

- 只有只读命令可以复用；写命令一律直发，绝不进窗口。
- 关键词类输入归一化后做键；歌单链接/ID 这类精确输入只去空白。
- 收益边界：只减少往返与等待，不改变对网易云的请求量。失败结果不写入窗口。
- 窗口是模块级状态，测试必须用对应的清理函数隔离用例。

### 音频播放（客户端技术约束）

- 结算阶段播放答案音频与副歌，起止点由服务端数据决定，客户端不自行推断。
- 音频加载至少监听 `canplay`、`loadeddata`、`error`，并设超时与重试入口，不只依赖 `canplaythrough`。
- 音频资源必须 HTTPS 且支持 Range。**`<audio>` 元素严禁声明 `crossOrigin`**：解灰音源不返回 CORS 头，声明后请求直接失败；官方 CDN 带 CORS 头不能作为“该属性必需”的依据。

## 歌曲筛选

- 聚合检索给出的 `sources`（同作品备用音源 URN）要随手动选曲回传；服务端先按序尝试这些已知音源，全部失败后才回到按歌名+歌手跨平台搜索。已知音源逐个尝试时关闭聚合器的隐式 failover，避免每失败一次就多打一轮搜索。
- 歌手/专辑检索要先按规范化名称去重，再按平台偏好交错输出；不能两边直接拼接后截断，否则后一个平台在正常输入下永远看不到。歌单与歌手分属不同平台时，按名字在歌单平台补找同名歌手再取交集；交集仍为空才报筛选无结果。
- 歌单读取要**翻页取完**，按曲目 ID 去重并设页数上限；不支持 `offset` 的回退接口用“本页是否带来新曲目”作终止条件；翻页失败只结束翻页、保留已取到的曲目。客户端提交歌单 ID 或链接，服务端只保存规范化后的数字 ID。
- 多个歌手在歌手筛选组内取并集，再与歌单、热度条件取交集；三个筛选项都可选。
- 红心数用专用接口的 `count`，不要用歌曲详情里的 `pop`（另一种热度指标）。
- 自动出题选中候选后仍需取详情获取歌词、音频与百科。

## 测试要求

- 常规 `bun test` 使用 mock API，不访问网易云，不读 Cookie，保证离线、快速、可重复。
- 真实接口测试单独运行（见 Server 的脚本），失败时先看状态码与接口文档，禁止通过无限重试或批量更换 IP“修复”。测试输出不得打印 Cookie、账号资料或完整响应。
- 新增或修改音乐接口时，至少补一条 mock 回归；接口不适合真实测试时在文档中记录原因和替代验证方式。
