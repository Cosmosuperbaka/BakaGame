# Bangumi 接入、图床与请求边界

涉及 Bangumi API 镜像、图片回填、自建图床、运行时更新器、请求队列与隐私边界时查阅。数据集构建与角色资料见 [BangumiDataset](BangumiDataset.md)，猜番曲目匹配与出题预算见 [BangumiSongMatch](BangumiSongMatch.md)。环境变量名、默认值、限额、缓存时长读代码（`Server/src/config/Env.ts`、`infrastructure/BangumiProvider.ts`、`Server/.env.example`）。

服务端负责所有 Bangumi 网络请求。客户端只通过 WebSocket 命令搜索条目、提交 subject ID，不直接访问 Bangumi API；图片地址由服务端重写。CEE 与猜歌共用同一份本地数据集与镜像配置。

## 1. 配置与图片前缀

- `BANGUMI_API_URL` 指向兼容 Bangumi v0 API 的镜像。**具体地址属于部署配置，不进仓库与文档。**
- **图片前缀写死为站内相对路径，没有环境变量开关**：所有 Bangumi 图片改写到自建图床（与后端同源，直接读本机缓存），不再把 Bangumi 源站地址发给浏览器（源站在国内多数网络连不上）。前缀刻意不开放配置：一旦可配，必有人配出边缘不放行的路径，整站图片会变成 SPA 的 HTML。
- 对外前缀是相对路径，所以回源地址**没有缺省值**（跟着它回源等于自己回自己的死循环）。要让图床自行抓缺失的图，必须显式配置回源前缀；留空则只服务已缓存的图。
- **新增后端路径一律挂在 `/api/` 下**：边缘层只放行 `/api` 与探针路径，其余路径会被前端托管吞掉，请求到不了后端、返回 SPA 的 HTML，`<img>` 就是裂图。排查此类问题先确认请求有没有被边缘层拦截，再谈回源。具体边缘平台的配置属于生产信息，放本地笔记，不进文档。
- 回源端只要满足：带 `Accept: image/avif` 时返回 avif，且保留源站路径与查询串。
- 镜像的角色详情接口里 `infobox` 是 `[{ key, value }]` 数组，与归档 dump 的 wikitext 字符串形态不同，**两套解析器不可混用**。

## 2. API 回填缓存

只读数据集里作品与角色的图片列始终为空（构建脚本不写图片），图片只能回源。只读数据集不能被运行时写入，补充数据因此单独存一张可写表（猜歌与猜番共用，按实体类型与编号为键，载荷只含图片地址）；它不进 Git。

必须遵守：

1. **只存上游原始 URL，不存镜像地址**。镜像地址在读取时按前缀重写，换图床不需要清缓存。
2. **失败绝不固化**。上游超时、报错、非 2xx、无图，既不写回填缓存，也不进内存正缓存，只记短时内存负缓存（进程重启即失效）。不得在 `catch` 里把 `undefined` 写进正缓存（一次瞬时超时会让条目在进程生命周期里永远没图）；联网 Provider 通用的缓存会把失败与空结果缓存满 TTL，所以角色立绘回源刻意不复用它，只缓存成功结果；这份成功缓存与主缓存共用同一个条目上限（有界 LRU，下限锁到 1），长进程里不得按累计角色数无上限增长。
3. **配置错误响亮失败，运行期异常降级放行**。构造时落点打不开直接抛错（静默降级会让缓存“悄悄不生效”）；使用期读写异常只告警并跳过，缓存是优化而不是真相源。
4. **跨 Worker 只传可克隆参数**。Provider 在 Worker 里，初始化参数不能含函数，缓存路径随初始化参数传入。

角色立绘与作品封面走同一套规则：请求按“实体:编号”合并；无图或 404 只进短时负缓存，其它失败原样报错；非法 id 直接返回 `undefined` 不回源。作品列表查询只读已回填封面、不回源，缺图的条目由客户端滚进视口时按需补；本地不存在或 NSFW 的条目返回 `undefined`。

## 3. 自建图床与运行时更新

数据集不由 CI 定期重建：**库是可写的，由后端自己更新**。图床与更新器都跑在数据 Worker 里，写操作收口在单一线程；主线程只读分片，单写者不变。

### 图床

- 分片存储，分片数按目录里实际存在的文件推断，与构建脚本一致；路径与 Bangumi 源站一致，所以图床换部署形态都不需要改 URL 改写逻辑。
- 命中直接回 avif（长缓存），缺失才回源，回源结果转交 Worker 落库。
- 主线程读取侧再加一层**有界字节缓存**：开局满房时客户端成批请求同一批头像，这层把重复请求收敛成一次同步 SQLite 读。它必须同时限条目数与总字节——只限条目数时几十张大图照样压穿长进程；单张就超过字节上界的图不缓存（写入会被拒），每次请求各读一次分片，不得为此抛错。
- **回源配额两层，先扣个人再扣全局，顺序不能反**：否则一个扫描者用随机路径就能吃光共享预算，正常玩家再也回不到源。命中缓存不占额度，同图并发请求合并成一次回源。分桶键只采信边缘写入的真实客户端地址（口径见 [Deployment](../../Agents/Deployment.md)）。
- **配额用完是 429，不是 404**，并带限流头与退避头：把“额度没了”伪装成“图不存在”会让客户端缓存失败结论、让运维查不到原因。
- 只认 avif 魔数：上游返回错误页或 jpeg 时**绝不入库**（坏字节入库就再也不会重下）。
- **响应类型走白名单**：库里的类型是自由字符串，白名单之外一律降级为 `application/octet-stream`，浏览器可直接导航到图片 URL，误写的 `text/html` 不能被当页面渲染。

### 更新器

- 按热度分位分层设置刷新间隔，分位每轮按当前热度分布重算；按在线玩家数线性限速，所有回源（含补图）过同一个时隙队列；玩家点开过的条目登记为按需，下一轮优先且只刷确实过期的。
- 落库后只把 id 写进待索引表，轮末批量 flush 到搜索索引；失败计数重试，超限丢弃（下一轮刷新会重新入队）。
- 失败指数退避并设上限，成功清零；**上游标为 nsfw 的条目不落库**并推后重问；备份快照期间暂停写库。
- 状态表建在数据集里，与它描述的数据同生共死。**首轮必须先把现有作品登记为“此刻已刷新”，不得一上线就全库刷新一遍。**
- 缺省只在生产开启，测试与本地开发不打线上上游。

## 4. 请求边界

- Bangumi 请求统一由 `BangumiProvider` 发起：条目搜索（固定动画类型）、条目详情、关联条目（筛音乐类型，与 infobox 主题曲信息融合互补）。
- 搜索与详情带 LRU 缓存，相同键的并发请求共享一个 Promise。请求由有界并发队列调度；上游 429 进入冷却、取消等待请求并返回 `BANGUMI_RATE_LIMITED`。上游非 2xx、无效 JSON、未配置 Provider 都转为明确的业务错误。
- 排队、请求和响应体解析共享同一截止预算；超时必须取消排队或在途请求并释放槽位，冷却不能留下挂起任务。已入队请求也要检查冷却，避免 429 后继续突发。测试注入请求函数，**不访问真实上游**。
- 角色搜索排序先为候选生成一次评分摘要，再由纯比较器排序；比较器不得重复触发补充资料查询。
- 图床回源与 CEE 图片提示的出站抓取统一走 `OutboundGuard`：禁用自动跳转、逐跳复核目标地址，回源只允许留在回源前缀同源；边界与残余风险见 [Deployment](../../Agents/Deployment.md)。
- CEE 图片提示跨键共享有界下载与解码队列，同键合并；排队、读取及解码共用截止预算，取消需释放读取器和解码资源；缓存同时限制条目数与字节数，不能仅依赖输入图片大小限制。

## 5. 隐私与协议

搜索接口只返回公开条目摘要；出题与猜测命令只传 subject ID。当前回合的番剧答案仅在出题人私有状态、旁观者私有状态或回合结算摘要中公开，猜测玩家在结算前只能看到自己的猜测记录。
