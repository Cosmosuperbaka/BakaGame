# Bangumi 数据集与图床

`bangumi.sqlite`（单库，猜歌与 CEE 共用）与 `images/`（分片图床 + 校验 `manifest.json`）均**不进
Git**：体积远超仓库该承担的额度，且能由数据构建工具重跑。本文件只写约束，工具、路径与命名以
实际脚本和配置为准。

## 约束

- **基线在本地一次性构建，之后由后端自行更新**：角色标签走上游增量 diff、作品标签与封面地址走
  API 刷新、新条目按首播日期窗口发现；备份只留一份，不参与分发。
- **投放走带内容哈希的对象名 + 清单**：文件名带内容哈希 ⇒ 缓存键随内容变化；发布顺序永远是「先
  传对象、后传清单」，不存在「清单指向未就绪数据」的窗口。清单与对象地址属部署配置，不进文档。
- **部署绝不搬走、绝不覆盖已有数据**：只在目标环境没有可用库时按清单补发；只有魔数校验通过的
  SQLite 才允许落位，绝不能让无效文件（如占位指针文本）覆盖唯一的真实库。下载失败必须不重启
  服务、不留坏数据。
- **CI 不生产数据**：数据缺失时 CI 直接失败并提示补发，不临时构建数据集。
- 需要真实数据实体的测试与冒烟按其专项入口取数，不放宽出口守卫（见
  [Agents/Testing.md](../../Agents/Testing.md)）。
