## 自动随机选歌真实测量（2026-10-03 UTC）

### 方法与边界

- 工作目录 `Server/`，运行 `bun run scripts/SongRandomnessProbe.ts 8055401334 7565047469 18335787613`。先调用真实 `playlist_track_all` 取得歌单，再通过 `SonGuessrService` 的真实命令分发、单人房间状态机、真实 `NeteaseMusicProvider.getSong` 和默认 `Math.random` 连续出题；不启动浏览器，不声称验证玩家端听感。网易云 Cookie 未配置；房间登录边界以隔离夹具满足，因此不能代表真实账号的 VIP 登录鉴权。音频 Range 探针返回 HTTP 206、`audio/mpeg`（三个歌单的代表曲目均成功）。
- 每歌单另用取得的真实曲目列表做 100 个独立房间、每房 100 轮的选歌器回放；`getSong` 和登录使用夹具，生产抽样、最近 10 个 ID 排除、回合状态机和随机源仍走原实现。回放分别模拟列表曲目全可用与按 `requiresVip` 排除会员曲目。详情加载失败的影响不在回放模拟中。
- 比较两种重复口径：歌曲 ID（同一资源）以及完全相同的歌曲名 + 歌手（玩家更容易感知的代理指标；不同录音也可能同名）。重复率 = 重复出现次数 / 成功出题轮数。失败的歌曲详情请求不计作出题轮。

### 结论

“重复太高”**对小歌单 / 较窄的可用候选池，以及歌单含同名歌曲的玩家感知层面成立**；小歌单非会员模拟的 30 轮窗口 ID 重复约 50%。大歌单在本次短窗口内重复低。当前机制只排除最近 10 个歌曲 ID，所以早先曲目仍可再次出现。若期望整局不重复，应使用候选池耗尽策略，而非只调整随机函数；若按玩家感知判重，也应考虑规范化后的标题/歌手键。此次只测量记录，没有更改产品策略。

重跑以上命令会对网易云产生真实请求；普通 `bun test` 不调用脚本、不访问网易云。配套隔离行为回归：`bun test test/SongRandomnessProbe.test.ts test/SonGuessrService.test.ts`。
