# 部署边界（通用约束）

仅在修改部署、代理、公开基址、静态外壳、缓存或发布流程时读取对应章节。本文只写**与具体平台无关的约束**；生产域名、托管平台配置、密钥命名、服务器拓扑与运维步骤不进入被追踪文档，见根 `AGENTS.md`「本地笔记」。本文不授权执行部署、重启或线上写探针，按用户已授权范围完成本地验证和发布准备。示例地址只用 `example.com` 占位。

## 1. 反向代理职责与来源身份

三款游戏的实时业务各有独立的 WebSocket 路径。应用负责协议解析、业务权限、房间状态与握手配额；这些**不能代替**公开入口的保护，入口保护也不能代替应用校验。

公开入口的反向代理或边缘网关必须：

- 终止 TLS，只向公网暴露 HTTPS/WSS；
- 限制单来源的握手速率、请求速率、并发 WebSocket 连接数，限制请求体、帧大小与连接带宽；
- 配置空闲与握手超时，同时允许正常对局长连接；
- 正确转发 `Upgrade` / `Connection` 头；
- **不得注入或强制启用 `permessage-deflate`**（应用为兼容 iOS WebKit 全局关闭）；
- 只把受信任的前端来源转发给服务，应用的前端来源配置必须与之一致。

具体数值按平台容量与真实流量确定，由平台监控验证。没有完成入口保护时，不得把服务端口直接暴露到公网。

**来源身份只能信边缘写入的真实 IP 标头，且该前提靠部署保证、代码保证不了**：

- 应用统一用来源解析函数，采信边缘写入的标头，退回运行时 peer 地址；`X-Forwarded-For` 可伪造，任何场景不参与分桶。限流为三层桶（单客户端 / 回源 peer / 全局），详见 [Server/docs/Engineering](../Server/docs/Engineering.md)。标头名是代码与边缘配置的双侧契约，改名必须两侧同批发布。
- 只有**源站只被边缘回源访问**时“标头客户端改不了”才成立。服务监听地址的默认值读 `Server/src/config/Env.ts`，入口把端口对外映射就等于自开公网入口，所以生产必须二选一：只放行边缘回源，或端口只发布到内网地址。监听网卡配置不是防火墙。
- 验收从公网侧向源站直发一条带伪造标头的写请求，期望**连不上**；能收到应用响应就说明源站可直连，按 IP 计的层已作废，只剩 peer 与全局层。
- 直连成立时的额度兜底有回归测试钉住；去掉 peer 层，该用例必须变红。

## 2. 请求链路与基址

- **链路口径（同源或跨域）是边缘配置与前端构建变量的一对约定，文档不记录当前取哪一侧**：解析语义读 `Client/src/lib/ServerEndpoint.ts` 及其测试，实际注入值读 CI 的构建步骤与 `Client/.env.example`。改口径必须两侧同批发布，并把写死在产物里的基址一并核对。
- **切换口径的前提是完整链路验证**：WebSocket 要在目标环境跑通「握手 → 命令 → 对应 ACK」。**仅 101 或 HTTP 成功不满足条件**——`200 + HTML` 说明请求被前端托管吞掉、根本没到后端，那是另一种故障。先验证再切换，切早了游戏直接不可用。
- 跨域直连时由后端以 Origin 白名单与 CORS 回应；同源时前端不留基址。两种形态下后端的来源校验都不能省（WebSocket 不受浏览器同源策略约束）。
- **新增后端路径一律挂在 `/api/` 下**：前端托管的兜底规则会吞掉未放行的前缀并返回 SPA 的 HTML。排查此类问题先确认请求到没到得了后端，再谈回源。
- 边缘验证的适用范围：本地开发环境缺少边缘注入能力时，本地失败不能直接代表线上结果；只验证 HTTP 响应头与 SPA 兜底不足以证明转发可用。托管平台的构建触发方式以平台文档为准。

### 探针与完成条件

- 对后端公开基址逐个请求健康、存活与就绪探针（路径读服务端系统路由），核对状态码与 JSON 内容，不能只接受 200（首页 HTML 也可能是 200）。
- HTTP 代理验证用已知只读 GET 端点并检查响应体与 `x-trace-id`；不得用 POST 写接口探测连通性。
- WS 验证连接后发送只读大厅订阅并检查关联 ACK；可能创建房间或改变对局的命令使用隔离本地实例。
- 生产目标检查只在已有授权范围内运行；只改文档不触发线上探针；既有结论不能替代本次发布证据。

## 3. 服务端出站

- 图片、头像等出站抓取统一经出站守卫：**永不自动跟随跳转**（逐跳处理并设跳数上限，超限释放响应体）；不可信地址（来自数据集或上游协议）每一跳都复核——只允许 http(s)、禁止内嵌凭据、拒绝回环/私网/链路本地（含云元数据地址）/CGNAT/组播/保留段，拒绝 `localhost` 家族与无点单标签主机；运维配置的可信基址只锁同源。
- 残余风险：守卫基于主机名与字面量地址，**公开 DNS 名解析到内网（含 DNS rebinding）不在应用层能力内**。容器出网必须在网络层收敛（只放行所需公网网段，显式拒绝到内网与元数据地址）；内部服务入口不得成为可被抓取的目标。
- 内部依赖服务（如昵称查询）走内网直连，不经边缘与公网，不新增边缘路由；其拓扑与防火墙细节属生产信息，放本地笔记。

## 4. 前端静态外壳（SEO）

前端是纯 SPA，构建产物的挂载点默认是空的；不执行 JS 的爬虫只能读到空壳。构建末尾的静态外壳插件把页面数据里的正文与 head 元信息写进各路由的 HTML。

- **零浏览器依赖**：纯字符串注入，**不要改回无头浏览器预渲染**（构建环境不装浏览器，下载既慢又脆）。
- **文案单一真相源**：页面元数据同时被运行时 SEO 组件与构建插件消费；未登记的路径（房间页、单人页）必须显式传描述，否则当场抛错。
- 新增开放大厅须同步页面元数据（含 FAQ 与结构化数据）、主页介绍与链接、资源冒烟与 SEO E2E；站点地图与分享图随构建生成，不手改。房间页保持 `noindex` 并在 `robots.txt` 排除对应房间路径。
- 落点双形态（目录索引型与 clean URL 型主机都能命中），别名与正式路径内容一致，重复内容由 canonical 收敛，别名不进站点地图。站点地图 `lastmod` 只在页面文案或结构显著变更时更新，不随构建刷新。
- **分享图必须用抓取器认的格式**（全站图片管线只产 webp，而部分社交抓取器不认 webp），分享图一律从源图转 jpg。
- **FAQ 与组织实体结构化数据**由构建期写入并派生；缺问答、空条目或重复问题让构建直接失败（内容坏了没有观感反馈，只能靠断言拦在部署前）。
- **分享标语前置**：每个登记页面的描述第一句固定为站点标语（社媒卡片只渲染描述的前两行）；构建期断言、资源冒烟与 SEO E2E 共同约束。
- **外壳必须在首次绘制之前消失**：外壳后紧跟 parser-blocking 的内联脚本同步清空挂载点。**不要改成 CSS 隐藏**（等于把正文标成隐藏文本），**也不要用 `<noscript>`**（信号更弱）。
- **静态 head 标签必须在客户端启动时摘掉**，再由 Helmet 写入当前路由的真值；**不要让 Helmet 接管静态标签**（该版本在 React 19 下不复用旧标签，会产生重复 canonical，比缺失更糟）。JSON-LD 例外：用固定 id 由运行时覆盖，不重复。
- 房间页与单人页不注入（内容由实时状态驱动，且已 `noindex`）。
- 自校验：插件在注入点缺失或产物缺标记时让构建失败；资源冒烟逐路由断言外壳存在；“有没有产生重复标签”由真实浏览器 E2E 断言。
- 构建期对公开仓库提交历史的一次只读请求必须**降级而不是让构建失败**，并有硬超时；需要更高配额时在构建环境注入令牌，未配置也能跑。
- 上线验收：用无 JS 的 `curl` 访问各大厅路由，正文应含对应文案且 canonical 指向自身；若平台把大厅回退成首页外壳，先检查静态产物与平台路由解析，不要把它当成 API 转发故障。

## 5. 边缘缓存策略

前端响应头与边缘缓存配置文件是**纯数据**：写错没有类型检查与构建报错，只会在线上表现为“发版后老用户拿到旧页面”或“静态资源反复回源”。对应的客户端测试把下列约定固化成断言。

- **分档的唯一判据是“文件名会不会随内容变化”，不是文件类型**：带内容哈希的构建产物与内容摘要命名的资源可长期 `immutable`；保留原名的公共图片**不得 immutable**（文件名不变，浏览器与边缘不会再回源，等于锁死换图能力）；实时接口 `no-store`；SPA 外壳不带哈希，必须 `max-age=0, must-revalidate`，长缓存会卡住发版。具体时长读配置文件与测试。
- **规则顺序：具体在前，兜底垫底**。平台按书写顺序取首个命中，`/*` 前置会静默吞掉后面所有规则（JSON 仍合法，故障是静默的）。
- **响应头与边缘缓存必须同档、成对修改**：`Cache-Control` 的 max-age 与边缘 TTL 描述同一个保鲜期，只改一处会让两侧判断分裂。
- 缓存头正确不能证明业务请求到达后端；发布时按实际基址分别检查三档资源与后端探针，`<hash>` 取本次构建产物。前端的 `/api/*` no-store 可单独检查，但不得要求 SPA 兜底响应携带后端追踪头。

## 6. 容量与带宽

- 实时状态采用带修订号的增量同步，首次连接、重连、修订缺口和周期校准才发全量。发布前必须运行网络容量测试；它是**人均带宽回归地板**，拦住的是“新增快照字段/重复事件把人均推高”，**不得为了过测而延长状态延迟或取消最终同步**。预算数值读测试，不当作部署硬上限。
- 负载测试工具在 `Server/scripts/loadtest/`，用与生产同一条应用装配线拉起独立被测进程。口径：**人均带宽要按节奏取窗口**（窗口必须覆盖一个完整回合，否则低估数倍）；房号空间有限，同一被测进程里跨步骤复用号段时要先等上一步遗留空房被清掉，否则整批开局撞号。

## 7. 隔离启动与交付回归

- 生产冒烟与 E2E 后端共用隔离启动脚本：禁用 `.env` 自动加载、环境白名单、清空遥测/账号/数据库连接、使用临时目录、独立端口、自有子进程退出竞赛。
- 仅测试 preload 阻断主动网络出口（fetch、WebSocket、TCP/TLS/DNS/UDP 等）与子进程派生；真实第三方测试另行授权，**不通过增加重试或放开出口修复测试**。该守卫不是操作系统沙箱，不承诺隔离原生扩展或未纳入守卫的新网络 API。
- 交付脚本有离线测试覆盖门禁反例、固定 SHA、退出假绿、所有者标记与出口拒绝；E2E 的外部图片/音乐需求应由专用 Provider 夹具接替，不可重新放开网络。

## 8. 发布流水线与密钥

触发条件与命令以 `.github/workflows/` 为准，本节只记约束：

- 自动发布由整条 CI 的完成事件触发，门禁要求整体 CI 成功**且**服务端作业实际执行并成功（客户端或文档改动使服务端作业跳过时，不自动部署后端）。服务端路径与部署脚本自身必须保留在 CI 的路径过滤范围内，保证改发布脚本也经过门禁。部署消费 CI 结果，不重复跑完整测试；手动触发必须指定要消费的 CI 运行，并与自动路径共用同一道门禁。前端托管的构建可能由主分支推送独立触发，“不部署后端”不代表没有生产影响。
- **部署只认获验的完整 SHA**，不消费移动分支；部署环境的 reset 操作不要在本地工作区照抄。
- **数据实体不随代码分发**：数据库（数据集与图床）由运维一次性上传，此后由后端自行更新。部署**绝不搬走、绝不覆盖**服务器上已有的库；仅在服务器没有可用库且提供了基线清单时按规则补发。只有魔数校验通过的 SQLite 才允许落位，绝不能让无效文件（如 LFS 指针文本）覆盖唯一的真实库。数据下载失败必须不重启容器、不留坏数据；不得为防止 LFS 出境下载而恢复复杂的镜像/代理/测速方案。
- **容器创建时注入的环境变量**才会被容器内 `--no-env-file` 运行的步骤读取；重启保留旧环境，补注入必须重建容器。发布前逐项核对必需变量（变量名与规则见 `Server/.env.example` 与 `config/Env.ts`），缺失时的行为必须是“安全失败”（停机通知缺凭据则中止部署且不重启）。生产环境标记必须显式注入；依赖外部搜索服务的配置须在该服务就绪、网络可达并单独验证索引构建后再启用，不与其它变更同批。通行密钥域名必须在第一位玩家添加密钥之前定好。
- **预通知 → 排空 → 重启 → 健康检查**：停机预通知通过容器内脚本以维护令牌鉴权，不使用自报来源头、不打印令牌、不放入命令参数；缺失、非成功或超时均中止部署且不重启，不声称预通知成功。重启后检查就绪与三款游戏订阅 ACK（不创建房间），通过把获验修订的只读探针脚本送入容器运行，不猜测挂载路径、不加载应用或 `.env`。失败打印容器日志并让作业失败，**不自动二次重启或回滚**。
- **发布元数据**：在维护通知前由获验修订生成，只含修订、版本等最少字段，不含环境变量、凭据或私有端点；原子落盘，失败中止发布且旧元数据不被截断；无有效证据时 release 返回空并提示，不硬编码版本或采信任意环境字符串。本地测试通过不等于线上 release 流量已正确，部署后须按实例与环境复核。
- **时间预算铁律**：构建机与生产机分处两地，出境链路不可控。部署作业的每一段都有预算，**任何新的部署步骤都要先声明它占用的秒数**，否则不得合入；数据下载路径必须设计成“无事发生”。各段预算与总时限读工作流配置。
- **部署脚本健壮性**：开工先做环境自检（逐个检查依赖命令）；任何失败必须带行号喊出来；下载用分片并行、全局截止与长度/摘要自校验，断点续传的分片目录按文件名与目标摘要命名，临时路径由文件名派生（并行任务不得用会被子 shell 继承的进程号拼路径）；传参先做格式校验以防注入；保留 LFS 双保险。
- **密钥管理**：严禁将真实服务器凭据提交至代码库；部署与数据发布依赖的 Repository Secrets 名称与说明放本地笔记，不进文档。**生产机全程不持有对象存储凭证**，部署与运行时只按公开 URL 下载版本化对象；一致性锚点只有公开的清单。
- 部署与运行相关的变更若让文档与线上漂移，须在同一批改动里校正文档（见 [Spec §7](Spec.md)）。
