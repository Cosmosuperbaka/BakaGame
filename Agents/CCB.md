# CCB 多人玩法与互通契约

本次从已删除旧实现后的代码基础重新实现。原版玩法依据相邻仓库
`anime-character-guessr` 的 `server/utils/socket.js`、`gameplay.js` 与
`client/src/utils/bangumi.js`；不恢复旧版页面或服务。本文记录已确认的目标，完成情况以测试为准。

## 产品边界

- 房间来源分为增强房与原版房。增强房由本服务权威执行；原版房实际建在配置的原版服务器，
  每位增强版玩家通过独立上游连接参加。原版适配器不另外运行本地比赛。
- 两类房的增强版角色检索与判定资料均来自 SQLite。原版客户端资料版本不同，允许反馈差异；
  兼容房最终状态、计时、积分服从远端。上游当局答案快照必须保留，不擅自换成本地答案。
- 三个小游戏暂时使用公共默认头像，不实现角色头像选择、抽卡、兑换或 QQ 登录。
  增强版无角色头像本命奖励，首猜奖励保留；原版玩家已有本命机制保留。
- 增强版删除玩家短留言，由聊天替代。兼容房新增聊天只在增强版玩家之间互通，
  不把原版短留言伪装成聊天，也不改原版客户端的留言功能。
- 上游地址及 AES 配置仅在服务端环境变量；绝不写入前端构建或日志。

## 玩法与状态

`waiting → preparing / answering → guessing → settled → waiting`。
局号与同步轮号是不同字段。开局冻结设置；猜测只提交角色 ID，不接受客户端判中结果。
支持普通、同步、血战、角色全局 BP、标签全局 BP 的全部组合，个人、1—8 队、观战，
随机与手动出题、目录与追加作品、文本与图片提示。

- 普通首位猜中结算；同步等当轮参与者全部完成才判定；血战继续到全部参与者结束。
- 队伍共用尝试记录、次数与行动计时；超时按当时在线且可行动的队员人数扣次数。
- 同步血战同轮答对并列，基础分在同步轮开始时冻结；两个第一名之后下一位第三名。
  非同步血战按消息顺序。原版同时修复这一规则。
- 同步胜者按自己的首猜、本命与快速猜中奖励结算，不共享首位胜者奖励；原版同时修复。
- 基础胜利分 2；首猜额外 12；非首猜第 2—3 次额外 2，第 4 次至次数上限一半向上取整额外 1。
  血战基础分按开局可猜人数减此前胜者数、最低 1。作品分与出题人奖惩保留原版口径。
- 同队共享次数，但胜者、贡献者与奖励用明确记录，不从共享表情串反推玩家身份。
- 出题人与其队伍本局观战；中途新成员本局观战；已结束玩家只能观看、不能重复提交。
- 角色 BP 保留本人重复、同步同轮及正确答案例外；被拒绝猜测不扣次、不登记标签。
- 标签发现与有效猜测原子提交，私有视图裁剪隐藏标签。同步轮末处理沿用原版口径。
  原版服务部署 `2778144` 后通过 `playerGuess.sharedMetaTags` 同步登记，并以
  `tagBanApplied` 确认；旧原版部署仅能退回独立标签事件，最后同步提交者的标签可能延至下一轮。
- 默认多人设置为近五年、热度前二十、十次、每次六十秒、作品和角色各四标签。
  预设基础值不同，不能替代多人默认值。不限行动计时仍有房间闲置与阻塞阶段超时。

## 数据和隐私

- 只读基础库与可写补全库组成统一查询结果；API 补全的头像原始 URL 与有效角色资料持久化，
  周更不覆盖补全库。禁止把网络查询作为 SQLite 角色检索失败后的隐式回退。
- 目录成员先同步入库，对局只用已落库成员；缺失条目给出明确数量。
- 登场作品和标签池按房间设置运行时推导；具体字段口径遵循 BangumiApi.md。
- 答案、设置和已使用角色视图在局内冻结；后台资料更新不得改变已给出的线索。
- 自动文本提示服务端生成一次；图片提示由服务端生成当前允许的模糊版本，
  未解锁时不得发送原图、原图 URL 或可猜出的资源路径。提示请求必须鉴权。
- 文本与图片提示阈值零表示关闭。被隐藏标签同时移除原文与命中标志。
- 数值比较符号表示「猜测值减答案值」，界面箭头表示答案方向：正号向下、负号向上；
  未知评分和年份显示「未知」，不能显示内部哨兵值。
- 公开快照只含公开房态。本人/队伍猜测、观众/出题人答案分别进入私有状态；
  兼容适配同样按连接视角裁剪，不能合并所有上游玩家的私有事件。
- 原版客户端可解密答案是其协议局限，兼容房不宣称全房答案保密。

## 工程与验收

- `/api/ccb/ws` 使用平台信封、TypeBox 严格边界、会话幂等与 RFC 6902 状态同步。
  领域、数据访问、原版适配和视图各自独立；前端复用 common/ui，不横向导入别的游戏组件。
- 来源、上游配置标识和房号共同隔离会话；确认加入后授予聊天身份，被踢/退房即时撤销。
  上游无法确认同号房是否重建时清除旧聊天，禁止无限重试 join 导致意外建房。
- 来源切换、会话恢复和主动请求同步都重置公开与私有状态的差量基线，首次发送完整状态。
  重连宽限内保留的上游会话计入玩家数，但没有下游连接时不得计入在线人数。
- 原版房间存在性检查使用包含私密房的 `/api/list-rooms`，大厅展示再过滤公开房。
  提示阈值为零表示关闭，保留数组位置，不得压缩后与提示文本错配；作品搜索关闭时，
  服务端拒绝当前猜题者的作品与作品角色查询，观战者和已结束玩家可查看。
- 房主重连 60 秒、空房宽限 90 秒、离线清理 3 分钟、闲置清理 10 分钟；
  房间定时由服务端驱动，断线不能导致同步永久卡住。
- 异步出题任务使用独立操作标识，截止时间不能兼作身份。猜测查询回来须复核局、
  同步轮和次数；同角色并发返回时复用首次接受的冻结资料。入房密码校验回来须确认连接仍登记。
- 核心验收：四开关 16 组合、个人/组队、自动/手动、并发和末次猜中、超时、重连、
  观战隐私、连续两局、混合客户端互通、三档响应式、生产资源与容量。
- 玩家栏统一默认头像、姓名、状态、分数与操作；聊天保留独立区域，手机及平板都有入口。
