## 歌词获取、切片与播放

> **改动 `SongLyricPlayer` 或任何 AMLL 渲染行为前，必须先查阅官方文档：<https://amll.dev/>。**
> 组件内核为 `@applemusic-like-lyrics/core` / `react`，其盒模型、`calcLayout` 排布算法、
> `lyricGroupSize` 原生测量与 CSS 变量均以官方文档与已安装版本的类型声明为准，
> 严禁凭印象推测 DOM 结构或字号行高。

Songuessr 引入类苹果歌词播放（AMLL），实现逐字渐变点亮、平滑滚动居中与精确时间轴同步。歌词数据获取遵循严格的四级回退策略：

1. **优先级 1（首选）：网易云官方 `yrc` 逐字歌词**
   - 从 `lyric_new` / `lyric` 返回的 `yrc.lyric` 提取；
   - 通过 `@applemusic-like-lyrics/lyric` 的 `parseYrc` 解析每个单词的起止时间（`startTime`, `endTime`）与注音；
   - 若解析出有效行且包含逐字信息，直接作为本曲歌词。网易云已命中 YRC 时零外部网络开销，不请求第三方服务。
2. **优先级 2（次选）：AMLL 官方 TTML 歌词库（网易云音乐 ID 匹配）**
   - 网易云无有效 YRC 逐字歌词时，异步降级请求 AMLL 官方歌词库：`GET https://api.amll.dev/v1/lyrics/get?ncmMusicId=${id}`；
   - 设置 3 秒超时限制（`AbortController`）并纳入 24 小时 LRU 缓存；
   - 通过 `@applemusic-like-lyrics/ttml` 的 `parseTTML` 解析 XML，内置 `xmlns:itunes` 命名空间与 `itunes:key` 自愈兼容容错；
   - 若解析出有效行且包含逐字信息，作为本曲歌词。
3. **优先级 3（搜索匹配）：AMLL 官方 TTML 歌词库（歌曲名搜索匹配）**
   - 网易云音乐 ID 在 AMLL 库中未命中时，通过歌曲名（与歌手名）发起搜索：`GET https://api.amll.dev/v1/lyrics/search?q=${encodeURIComponent(query)}&pageSize=5`；
   - 取首个候选项目的 `id`，调用 `/v1/lyrics/get?id=${id}` 拉取完整 TTML 歌词；
   - 同样受 3 秒超时与 LRU 缓存保护，若解析有效且含逐字信息，作为本曲歌词。
4. **优先级 4（兜底）：网易云普通 `lrc` 歌词**
   - 前序逐字接口均无数据时，兜底解析网易云普通 `lrc`；
   - 客户端将普通行级歌词每行转换为全行时长的单个单词（`words: [{ startTime: line.time, endTime: line.endTime, word: line.text }]`），AMLL 播放器同样支持顺畅的行级渐变高亮与垂直滚动居中。
5. **纯音乐或无歌词**
   - 若四级回退均为空，则 `lyrics = []`，系统展示“当前歌曲为纯音乐或无歌词”并以随机切片截取播放。

**出题切片、长间奏保护与和声歌词规范**：
- `createSongLyricClip` 必须保证选取的歌词窗口具备演唱连续性，相邻两句之间的间隔必须满足 `lines[i].time - lines[i - 1].endTime <= MAX_LYRIC_INTERLUDE_GAP_MS`（6 秒）。
- 严禁将跨越数十秒超长乐器间奏（如《一样的月光》中间 54 秒间奏）的两段唱词强行拼接为一个出题窗口。当设定行数大于间奏前后的连续段长度时，算法必须主动收缩行数选择紧凑连续段，保证题目片段节奏连贯。
- **和声歌词出题屏蔽与仅在播放演出**：选词滑动窗口必须过滤排除和声歌词（`line.isBG`），仅以主歌词作为候选基准。**严禁以和声歌词作为题目开头，严禁和声歌词充抵题目行数**（避免小字歌词导致题目还没唱完音频就被过早截断）。音频时长严格覆盖主歌词时间窗口；同时落在该出题区间内的所有和声歌词完整保留在 `clip.lines` 中，供播放时作为背景小字自然演出。
- **选区前后延展与音频渐入渐出**：题目音频选区起点前置 1 秒（`Math.max(0, windowStartTime - 1000)`）、终点后延 1 秒（`min(duration, maxLineEnd + 1000)`）。客户端通过 `useAudioClipPlayer` 在首个 1 秒内执行音量由 0 到 1 的平滑渐入，在终点前最后 1 秒内执行由 1 到 0 的平滑渐出，彻底消除音频启停爆音与突然掐断感。播放期间 `SongLyricPlayer` 的时间轴必须如实下发音频真实播放毫秒（`audioMs`），**严禁将前奏缓冲期强行锁定在首句时间戳**，确保第一句歌词在前奏阶段保持静止未触发状态，歌词点亮时值与歌声唱响精确对齐；仅在未播放、暂停或音频时间严重异常时安全锚定在首句避免视觉塌陷。

**逐字时间轴保护规范**：
- 对于带有 `words` 逐字信息的歌词行，`sanitizeLyrics` 必须严格保留其原本精确的 `line.endTime`，严禁被下一行的起始时间粗暴覆盖，以保证歌唱停顿、长间奏和逐字动画停靠精确；
- 对于无 `words` 的普通 LRC 兜底行，保持使用下一行起始时间或 `+5000ms` 兜底，使纯行级高亮在间奏期间自然驻留并居中滚动。

### 客户端歌词生命周期与布局

- 改动前阅读官方[生命周期](https://amll.dev/guides/component/sequence)与[进度对齐](https://amll.dev/guides/component/seeking)，同时核对锁定版本源码。`SongLyricPlayer` 负责 React 容器，`SongLyricScene` 通过原生 Core 单实例统一管理数据、媒体、测量和动画；不得同时用 React 绑定与命令式方法重复驱动同一状态。
- 歌词引用按完整内容深比较，必须包含逐字文本、逐字时间、行级和逐字注音、翻译、和声及对唱标记。禁止只比较文本与词数的摘要键：相同词数也可能有实际内容更新。快照复制不得重建歌词节点。
- 翻译非空时屏蔽行级与逐字注音；无翻译时完整保留注音。通过原生 AMLL 排版测量所有可显示的副行，禁止只计算翻译而漏算注音。
- 题目片段全量挂载，并覆盖内核 `content-visibility: auto` 为 `visible`。挂载不等于排版完成，不能把视口外的固有占位高度当真实行高。
- 高度唯一来源为原生歌词组的 `clientHeight`，与 AMLL 的 `lyricGroupSize` 使用相同口径。持续用 `ResizeObserver` 监听歌词组、宿主及播放器；字体、宽度、字号变化必须重新计算。禁止按字数估算、固定最大高度、轮询若干帧后永久锁定，或用人为延迟掩盖测量竞态。
- 和声容器在播放/暂停/总览始终按真实尺寸占位，统一 `position: relative`、零负间距与无几何变换；活动状态只改变明暗。否则原生和声展开会改变组高，播放时的测量不能复用于总览。
- 歌词及其全部子节点均不接管指针事件，滚轮与触摸交给页面滚动。仅设置播放器根节点 `pointer-events: none` 不够，内核和声容器的 `pointer-events: auto` 会重新开启内部滚动。
- 播放器本体始终维持未缩放的自然高度，宿主高度为 `ceil(自然高度 × lyricOverview.scale)`；外壳由正常盒模型叠加 padding 和边框。播放锚点为 `scale / 2`，总览为顶部零点。模式切换不得修改字体、行高、播放器高度或外壳高度。
- 初始化先挂载歌词并触发实际排版，再等待本段文字的 `document.fonts.ready` 和内核实测尺寸一致，最后强制对齐并显示。禁止先显示从屏幕外飞入的临时位置；新曲不能沿用上一曲的测量或等待回调。
- `requestAnimationFrame` 同时驱动真实媒体时间与 `player.update(delta)`，不触发 React 每帧渲染。暂停和结束事件只暂停演出，不能先倒回首句；只有完成状态切换才进入总览。前奏必须使用实际媒体毫秒，不能提前点亮首句。
- 总览必须保持同一播放器和同一批歌词节点。切换先读取当前屏幕的变换，再计算目标布局，在同一次同步更新中以 Web Animations 从旧位置移动到新位置，同时缩放播放器；两者共用 `Motion.ts` 的 `lyricOverview` 时长与曲线。裸调用 `calcLayout(true, true)` 会瞬移，只能用于隐藏中的首次落位或已捕获起点且立即建立连续动画的目标布局。
- 快速重播必须从尚未结束的当前变换接续；动画结束取消填充状态，播放端清除整体缩放。减弱动效直接落位。卸载须释放播放器、媒体监听、字体监听、ResizeObserver 与动画帧。
- 文字使用现有前景色和衬线字体，主行字重 500、副行 400，禁用深色叠加混合与文字辉光。总览的主行、副行和和声均为完整不透明度，并去除逐字遮罩；仅覆盖 opacity 不能去除遮罩造成的灰字。
- 禁止为屏蔽第三方开发日志而改写全局 `console.log`；生产环境由依赖本身的构建条件移除调试日志。
- 无歌词时保持紧凑提示（`h-24 sm:h-28`）。浏览器回归见 `Client/e2e/SongLyrics.spec.ts`，用 `npm run test:lyrics` 验证真实 AMLL、字体、布局与动画中间帧；jsdom 中的模拟高度不能证明真实排版正确。

## 歌词清洗

时间轴歌词进入游戏前必须：

- 解析多时间戳 LRC，并重新计算每句结束时间。
- 仅删除整行完全匹配歌名、歌手、专辑名的纯元数据标题行（`forbidden.has(normalizedLine)`），**严禁使用子串包含（`includes`）误杀唱到歌名（如《珠玉》）或歌手名（如《我是初音未来》）的真实歌词**。
- **严禁对歌词进行全局副歌去重**，必须在整曲时间轴上完整保留副歌与所有重复演唱，杜绝出题切片跨副歌时产生歌词缺失与时间轴空洞。
- 删除中文和英文作词、作曲、编曲、制作、录音、混音、母带、乐器演奏及发行署名行，包括 `Production Coordination`、`Keyboards & Programming`、`Drums`、`Strings Arranged & Conducted`、`Recorded at`、`Engineered by` 等变体。
- 过滤后的歌词行数达到设置要求时，交给 `createSongLyricClip` 选择连续歌词片段；单句跨度超过 12 秒的候选片段必须跳过，避免截取过长间奏。
- 过滤后的歌词行数不足时，允许纯音乐或未上传歌词的歌曲出题，改为在歌曲时长内随机截取 `设置歌词行数 * 6` 秒的音频片段（该降级策略保持不变）。

### 无效歌词判定：分层结构，禁止穷举词表

署名行必须用**分层判定**，严禁退回到「一张穷举词表 + 行首紧跟分隔符」的老做法 ——
该做法在实战中持续漏网：同人/翻唱圈标签（`翻策`、`美工`、`题字`、`后期`、`翻唱`）永远追不全，
`【翻唱】X`、全角空格缩进的 `　作词：X`、多标签的 `策划/统筹：X` 又会因前缀与分隔符形态不合规而整条失效。

判定顺序固定为：

1. **剥离行首装饰与包裹式括号**，再定位标签边界。
   - 包裹式标签判定必须**先于**装饰剥离，否则 `【翻唱】X` 会被剥成 `翻唱】X` 而失去括号线索。
   - 标签与取值之间的分隔符正则**不得锚定行首**，否则 `翻唱 - 某某` 这类行内分隔永远匹配不到。
2. **词表快速路径**：命中已知标签即判定为署名，覆盖绝大多数常规标签。
   - 标签正则的多个可选分支必须按**先长后短**排序，否则短标签会抢先匹配
     （`sp` 吃掉 `Special Thanks`、`曲` 吃掉 `曲绘`）。
   - 标签部分的复合可选分支必须用 `(?:...)` 包住整组，`^a|b|c$` 只会锚定首尾两项。
   - 标签必须覆盖整个头部才判定命中，避免 `曲终人散：` 这类以署名词开头的正常歌词被误判。
3. **结构判定兜底**：词表未命中时，用「短标签 + 分隔符 + 空格分隔的人名串」这一稳定结构判断，
   使词表不必追上不断新增的同人圈标签。要求标签不含标点数字、右侧片段均不含歌词高频虚词。
4. **连排署名块整体剔除**：制作名单通常连续排布（实测连排 5 行），相邻署名行（默认 3 秒内）
   若形如纯人名串则整块剔除，否则「翻唱」之后的纯人名续行会因不含标签而漏网。

出题侧必须**二次校验**：`createSongLyricClip` 选取窗口时再用同一套单行判定复核，
避免 24 小时歌词缓存里的历史脏数据被截取。歌词缓存只存**歌词本身**，切片每次出题重新随机选取。

### 非署名类无效行：词表与结构判定之外还有六类

仅靠「标签 / 人名串」判定会漏掉一批**结构与署名完全不同**的行。以下各类必须各有独立判定，
且都要接入 `isUnusableLyricLine`（否则出题侧二次校验不会生效）：

- **版权与法律声明**（`词版权管理方：X`、`录音作品及MV版权：X`、`（未经许可,不得翻唱或使用）`）。
  头部是扩展短语而非词表标签（`词版权管理方` 只会被匹配到 `词`），用**包含**固定短语判定，不要用前缀。
- **对唱角色标注**（`男：`、`女：`、`合：`、`合唱：`，以及包裹式空标注 `【合】`、`（男）`）。右侧取值为空，
  `splitCreditHead` 会因「取值缺失」直接返回 undefined 而整条漏网，必须单独匹配「角色词 + 冒号结尾」
  与「括号内仅含角色词」两种形态。
- **注音符号行**（`ㄅㄆㄇㄈㄉㄊㄋㄌ`，周杰伦《反方向的钟》开头口白）。它既非符号也非数字也不短，
  但没有任何可猜语义，按 `U+3105–U+312F` / `U+31A0–U+31BF` 区间整行判定。
- **带后缀的纯音乐占位**（`纯音乐，请欣赏`）。逗号会让 `normalizeComparableText` 的结果不等于 `纯音乐`，
  单纯的集合命中失效，需按前缀判定；同时注意区分「本曲为纯音乐，请欣赏」这类更长的写法。
- **占位遮罩行**（`XXXXXXXXX`、`xxx`、`OOOOOO`）。整行由**同一个 ASCII 字母重复 ≥3 次**构成，
  是上传谱里未填写段落的常见写法。判定要求剥离空白与连接符后整行只含同一字母且长度 ≥3，
  这样 `X你太美`、`xxxxx我爱你`、`XXXXXXXXXXXXXXXXXX你好` 这类含实际文字的行不会被误杀。
- **整行括号包裹的舞台指示**（`(何が綴られていたのか、私たちの文明では到底理解できない)`、
  `（以下反复）`、`(Repeat)`、`(silence)`）。必须**保守判定**，因为括号在真实歌词里是常态：
  仅当「内层命中舞台指示词表」或「内层含 `、,，;；` 这类并列/断句标点」时才剔除。
  `（啦啦啦）`、`(你是我的眼)`、`(Oh yeah baby)`、`（爱してる）` 都因不满足条件而保留。

**无分隔符的英文署名**同样是一类独立形态：`Special Thanks`、`Thanks To` 没有冒号，
走不到词表路径（`splitCreditHead` 返回 undefined）。凡是可能裸写的英文标签都要登记进
无分隔符前缀模式。**旧用例只覆盖了带冒号的 `Special Thanks：某某`，导致裸写形态长期漏网** ——
补测试时必须把「同一标签的带分隔符与不带分隔符两种形态」都写成断言。

**复合限定标签**是另一类稳定漏网形态：`音乐制作：BachBeats`、`音乐指导：bilbili音乐@大家的音乐姬`、
`专辑封面设计：X`。它们同时掉出两条路径 —— 标签不在词表内，且取值是**超过 8 字符的英文/含 `@` 串**，
被结构判定的 `segment.length > 8` 与标点否决。修法是把整词登记进词表
（`音乐制作`、`音乐监制`、`音乐指导`、`专辑封面设计`、`混音室`、`母带处理` 等），
而**不要**放宽结构判定的长度约束（那会连带放行大量真实歌词）。登记复合标签时必须保证
「标签覆盖整个头部」，因此 `音乐响起：我们的故事` 不会被误杀。

反误杀约束（这些规则都是踩过的回归，不得随意收紧）：

- 单个中日文字符是合法歌词（`啊`、`一`、`二`），「过短行」只对非中日文字符且有效字符不足 2 个的情形生效。
- 纯人名串判定要求**至少 2 段短片段**，单段连续文本一律视为歌词，否则会误杀 `第一句歌词`。
- 英文多词标签（`Special Thanks`）判定时只压缩空白为单空格，不能整体删除空格。
- 中英混排拆分的首字符必须是中日文字符，否则 `Special Thanks` 会被误拆成 `S` + `pecial Thanks`。
- 保留不同时间位置的重复演唱，不对整曲歌词按文本去重；清洗结果必须保持时间轴连续。
- 纯音乐行（`Music`、`间奏`、`Interlude` 及叠词变体）、纯符号行、纯数字行同样不得进入候选窗口。
- **角色词单独成标签时必须区分「空标注」与「标记 + 歌词」**：`【合】有英雄漂泊异乡 故土遥远`、
  `【男】让我用心把你留下来` 是**真实歌词**（角色标记 + 歌词正文），若按词表命中整行剔除会
  大面积误杀合唱段落（实测《千里邀月》整段副歌丢失）。判定条件：头部是纯角色词
  **且**取值侧有效字符 ≥4 时，拒绝判为署名行。这是**非签署名判定里最危险的一条**，
  新增任何角色词（男/女/合/合唱/对唱…）都必须同时回归这组反例。
- **新加规则必须跑「含该字词的正常歌词」反例**：版权/角色词很容易误伤，
  已锁定的反例包括 `关于你们之间的故事`、`男女之间`、`后天`、`后期制作人`、`人都走了`、`合唱情歌的夜晚`。
- 注音判定不得越界到日文假名（`あいうえお`）或中英混排行。
- 竞猜阶段当前歌曲为纯音乐或无歌词时，标题更正显示为“音乐片段”，内容区域提示“当前歌曲为纯音乐或无歌词”，避免误导玩家为房间关闭歌词显示。
- **歌词窗口必须能收缩，不能因单行跨度过长就丢掉整首歌的歌词**：出题片段
  （`createSongLyricClip`）要求窗口内**每行**跨度 ≤ `MAX_LYRIC_LINE_DURATION_MS`(12s)，防止把间奏
  算进片段。但含长间奏的曲目会因此整片否决：实测 `JANE DOE`（米津玄師 / 宇多田ヒカル）第 6 句之后
  有 15 秒间奏（该行跨度 14.81s），设定行数 ≥ 7 时**任何**窗口都必然覆盖它，旧实现直接退回
  `lines: []`，让一首有 12 句歌词的歌在界面上显示成“当前歌曲为纯音乐或无歌词”。
  正确行为是**从设定行数逐行收缩**（下限 2 行；设定 1 行时保留 1 行窗口），只有连 2 行的紧凑片段
  都不存在时才退回纯音频窗口。新增或调整窗口约束时必须同时覆盖“设定行数本身不可行”的收缩路径，
  并保留 `lines: []` 的既有语义（空歌词、单行歌词仍判为不可出题）。

### 判定器回归边界

以下规则来自历史歌词抽样，只在调整清洗判定器或词表时查阅。R 编号表示当时的复现批次，不要求新任务重走所有抽样轮次。

- **行首装饰剥离陷阱（四度踩坑，最高频错误）**：`isCreditKeywordLine` 的所有行级判定都作用于
  剥离装饰后的 `undecorated` —— 锚定行首 `《`、`（`、`【` 的正则**必然失配**（R8 `QQ音乐`、
  R11 《》staff、R15 采样括号与多段方括号署名全部栽在这里）。写整行正则前先核对剥离后的实际形态；
  结构性判定（多段方括号署名）必须对**原始文本**判定，不能对 undecorated。
- **词表条目与注释一致性**：词表注释里写「必须进词表」的词**真的要出现在条目列表里**
  （R15 `音乐发行`、R16 `鼓手/民谣吉他/特别合作` 三次注释写了落盘漏加）。候选验证探针是最后防线。
- **变体字符码位收全**：网易云实测出现变体冒号 `︰`(U+FE13)、`﹕`(U+FE55) 与半角/全角加号
  `+／＋` 并存（R15/R16）。分隔符、joiner、装饰剥离的字符类必须同时收全半角与全角码位。
- **真实 LRC 高频错拼是独立漏网源**（R16）：`Arragement`/`arrangemet`（编曲）、`Hormony`（和声）、
  `Dummer`（鼓手）、`Prodused`（制作）等错拼在真实上传谱里成批出现，词表必须收错拼变体。
- **设备型号 token 豁免**（R16 `Yamaha CS-80 Synthesizer`）：型号（`字母-数字` 形态）永远不进词表，
  英文逐词判定允许 ≤1 个型号 token，其余词必须全部命中词表；外层字符类必须含数字与连字符
  （`CS-80` 的 `8` 曾让整条 value 掉出分支）。
- **双语对照翻译用 TitleCase 判定**（R12）：`制谱 Music Copyist`、`企划 Creative Planning` 的英文侧
  永远追不完词表，而「每词首字母大写的短短语」是对照署名的强特征（句中歌词的英文几乎必含小写虚词）。
- **高频歌词词进词表必须同步进 SPACE_SPLIT_HEAD_DENY**（R13/R16）：`音乐`、`歌词`、`故事`、`视觉`、
  `鼓手`、`翻译`、`录制`、`专辑`、`背景` 这类词的**冒号形态**（`音乐：天使盐`）是署名、**空格形态**
  （`音乐 我的生命`）是歌词；DENY 只拦空格 head，冒号路径不受影响。
- **探针 want-keep 旧案例被新能力 drop 时先复核分诊**（R12→R16 `Lead & Background Vocals : Ed Sheeran`）：
  它可能是当年的分诊误判（本该 drop 的署名行），修正探针预期而不是回退产品代码。
- **抽样脚本的 seenIds 排除表会让确认轮空转**：排除表非空时已见歌直接从抽样池剔除，
  「零疑似」可能只是「零查询」。终验必须清空排除表对全池重抽，并把疑似行与既有探针沉淀对比。
- **回归以可复现资产为准**：运行仓库内 `NeteaseMusicProvider.test.ts` 的相关判定用例；每条受影响路径至少覆盖一条应删除与一条应保留的代表样本。新增形态先验证，再沉淀正式用例。
- `.workbuddy/tmp/` 中的历史探针未纳入版本库，仅在本机存在且与本次改动相关时辅助验证。缺失时使用已提交夹具重现边界，不把不可获取的个人脚本设为交付前置条件。

### 真实歌词抽样

仅在任务需要且已有真实接口测试授权时执行。按本次问题选择样本与有限批次，达到相关误删/漏删回归标准后停止；不默认启动持续抓取。

```bash
cd Server
bun run test:music:real
```

实测套路与坑：

- `getSong` **内部已经调用过 `sanitizeLyrics`**，返回的 `song.lyrics` 是清洗后结果。
  想观察「到底删了哪些行」不能对返回值再跑一次 `sanitizeLyrics`（那是空操作），
  而要用 `isUnusableLyricLine` 逐行复核残留。
- 只构造词表内已知形态的用例，永远测不出漏网。**必须用真实歌曲跑一遍并逐行复核**，
  本轮 10 类漏网全是真实数据暴露的，构造用例一条都没覆盖到。
- **「剔除数变多」不等于变好，必须逐行看剔除内容**：真正的验收标准是
  「剔除的全是署名/占位/舞台指示，且没有一行歌词被剔除」。
  拿歌单大批量复测时，要先用真实歌词建立一个「必须保留」白名单再用脚本断言，
  单看 drop 计数会掩盖误杀。
- 抽样来源优先选**用户实际分享的歌单**（华语流行、日语、VOCALOID 各自的特征不同：
  商业曲署名密集、VOCALOID 曲多占位遮罩与舞台指示、同人曲署名最杂）。
- 复测覆盖面要包含：版权声明密集的商业曲、带注音/口白的曲目、对唱曲目、伴奏/纯音乐曲目、
  以及翻唱圈同人曲（署名最密集）。
