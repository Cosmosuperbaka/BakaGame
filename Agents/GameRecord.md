# 对局记录

涉及对局记录的写入、保留、字段口径或按记录做统计时查阅。表结构与连接见 [Database](Database.md)。

## 1. 边界

- 记录只服务后台复盘与统计，不承担回放；房间实时状态仍为纯内存，记录不反向影响对局。
- 三款游戏地位相同，都在「一轮结算」时经端口 `GameRecorder`（`domain/GameRecord.ts`）各交一条记录，服务以可选依赖注入；未配置数据库时不注入，即不落库。
- 猜猜呗只记录增强房：原版房的对局在上游服务器进行，本端拿不到完整答案与全员猜测。

## 2. 写入点

| 游戏 | 时机 | 摘要 `summary` | 时间线 `timeline` |
|---|---|---|---|
| 谁是卧底 | `finishRound`（含主动中止，`winner=aborted`） | 胜负、原因、词对、出题人、全员身份、天数 | 发言、投票、夜晚行动、白板猜词、离场，按时间合并 |
| 猜歌/猜番 | `finishRound`（含房主跳过，`skipped=true`） | 题型、答案歌曲/番剧、出题人、猜中者 | 逐次猜测与结果 |
| 猜猜呗 | `CCBRooms.publish` 发现进入 `settled` | 答案角色、出题人、名次、模式 | 逐次猜测与命中 |

- 猜猜呗的结算散落在多条领域路径，但都以一次发布收尾；按结算摘要对象去重，结算后的多次发布只记一条。
- 玩家行：参与本轮的玩家（卧底为发到身份者，猜歌为正式玩家，猜猜呗为得分表成员），`score` 为本轮增量，`userId` 取连接上的登录身份，游客为空。昵称截到 64 字符。
- 摘要只放复盘需要的最小信息，不放歌词、音频地址、cookie、头像等大字段或敏感字段。

## 3. 落库与保留

- `GameRecordService` 异步写入（单条记录与玩家行同一事务），失败只记告警，绝不抛回游戏服务；数据库不可用时最多积压 200 条，超出丢弃并告警。
- 时间线序列化上限 64 KB：超出保留前段并追加 `{ type: "truncated", omitted }`。
- 滚动保留 7 天：启动即清理一次，此后每小时按 `ended_at` 分批（500 条）删除。停机时先等在途写入完成再关闭连接池。
- 按日统计以北京时间切日：`ended_at`（UTC）加 8 小时后取日期，与访问统计同口径。

## 4. 测试

- `test/GameRecord.test.ts`：记录服务的失败隔离、截断与分批清理，以及卧底、猜猜呗结算各记一条；猜歌的写入断言在 `SonGuessrService.test.ts`。
- 对真实 TiDB 的验证（事务写入、按账号查询、按日聚合、清理）属于一次性人工验收，结束后删除测试数据。
