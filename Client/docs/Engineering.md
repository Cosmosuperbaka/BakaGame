# 客户端工程约束

修改页面架构、房间接入、状态派生、自动保存、时间展示或前端遥测时查阅。跨端原则见 [Spec](../../Agents/Spec.md)；视觉与动效见 [DesignGuide](DesignGuide.md)。组件、常量、配置读代码（`Client/src/`），本文只记约束与理由。

## 1. 前端交付与一致性

- 页面按生产标准交付，包含真实流程、状态反馈、错误与响应式表现；不得把演示或占位页面作为完整实现交付。
- 修改页面前检查目标与相邻组件，复用项目现有控件和语义变量；基础控件（按钮、滑块等）不在业务组件里重写。
- 异步列表首次返回前不得闪现空状态；加载与空状态必须可区分，并具备可访问名称与稳定的布局尺寸。
- **首屏包体只挡累积**：改动渲染阻塞样式表、入口 JS 图、字体子集或首页出档资源都要过包体门禁；预算取值与口径以 `Client/scripts/first-screen-budget.mjs` 为准，做小随时可以，放大上限要在提交说明里写理由与实测幅度。
- **字体是构建产物，不是源码依赖**：完整 TTF 与字体下载缓存都不进 Git，首次构建从固定版本的上游仓库拉取并核对 SHA-256；woff2 子集、注入的 `@font-face` 与清单由 Vite 启动钩子生成。离线构建只能复用本地缓存，不能把完整字体提交到 `public/` 或仓库。

## 2. 组件分层

- 单文件失控膨胀要拆：组件文件变长时主动审视职责；“上帝组件”不并入主线。
- 音频调度、看门狗轮询、WebSocket 生命周期与会话重连封装为专用 Hook，不与视图 JSX 混杂。
- **提示音统一走合成与解锁路径**：不引入音频资源；AudioContext 只在用户手势里创建，未进入运行态不排程，恢复失败保留手势重试；行动提示只在本地玩家由「不可操作」进入「可操作」时响，进房与重连只建基线；聊天提示只对他人的非系统消息按 id 去重。
- 多阶段房间拆成独立阶段组件，根页面只作容器：组装 Store 订阅、分发事件。
- 目录、命名、横向依赖规则见 [Spec §5](../../Agents/Spec.md)；全局基础 UI 不依赖业务 Store。
- **禁止用全局 DOM 事件传递业务信号**：阶段切换、倒计时超时、玩家动作由服务端推送或全局 Store 驱动，不用 `window.dispatchEvent` 横向绕过状态机。超时触发的自动提交基于 Store 里的阶段截止时间戳声明式响应，让组件随生命周期解绑。
- **可访问性描述只写实测语义**：注释与文案不得把「视觉不被遮挡」当成「可交互」。覆盖层（modal 面板、对话框）打开期间，背景对读屏与指针都不可达；离场等可达路径要按实际机制描述，并有用例断言无障碍树与关闭路径。

## 3. React 渲染与 Effect

- 遵循“You Might Not Need an Effect”：不在 Effect 主体里同步 `setState`，级联状态改为基于 props/state 的纯计算派生；需要同步外部系统时才用 Effect，并有明确清理。不得为绕过 lint 把 `setState` 包进零延时计时器。
- 渲染流程中不读写 `ref.current`，保持渲染纯洁与可并发。
- 提交类按钮在请求发出至 ACK/失败前必须有 in-flight 禁用锁与加载反馈。

## 4. 协议基线与状态

- 状态同步引擎维护的快照基线必须严格等于服务端下发的公开数据模型：**禁止在协议快照上就地追加前端展示字段**（如向聊天数组 push 本地提示），否则 JSON Patch 的路径与索引错位。动画、淘汰展示与本地提示属于独立的展示派生层。
- 换房与退房时原子重置模块级版本追踪号、历史补丁缓存与基线引用，避免残留版本号阻断新房间同步。
- 聊天展示层按消息标识去重、按时间排序并保留有上限的条数（首次进入与重连全量也遵守）；不得裁剪原始基线。
- 组件不推断私有权限、不覆盖服务端快照；表单弹窗通过 Props 与校验回调采集数据，不隐式绑定具体游戏 Store。
- 依赖账号的客户端态（如排位档案与榜单）随账号变化重置，旧账号在途的回包作废；由持有数据的 Store 订阅账号变化，账号 Store 不反向依赖它们。
- 偏好类本地记忆（如房间设置记忆）读出时必须经共享契约的 schema 校验，不合规（含损坏）按「无记忆」处理并删掉该键，不重放给服务端、不合并写回；这是对「损坏数据 Fail-Fast」的有意例外：它是可丢弃的增强，不是用户历史。校验库与 schema 体积大，不得进入首屏，按需动态加载。
- 谁是卧底的私有信息只来自私有状态，不从公共快照推断（规则见 [Server/docs/WhoIsFaker](../../Server/docs/WhoIsFaker.md)）。

## 5. 房间接入事务归属

- 页面直链、名称/密码补录与单人建房共用同一房间生命周期的 `AbortSignal`；仅换房或卸载取消，成功快照更新不能取消自身。
- 路由房号先按服务端规则归一（去首尾空白，测试房号大小写不敏感）再用于入房命令、会话键与快照房号比对。
- 入房请求期间的推送状态保留为事务暂存，不覆盖已确认房间的公开展示态；ACK 提交时一次安装匹配房间与令牌的状态。失败或取消不能混用旧房间命令身份与新房间快照。
- **「房间已结束」类事件（关闭、被移出、席位被接管）三款口径一致**：事件房号与当前已确认的房间不同时，只清那间房的本地令牌，不动当前房间与在途入房；房号一致或事件不带房号时，取消在途入房、清令牌并退房。页面只认挂载之后发生的关闭标记，挂载与卸载时各清一次。
- Store 在 ACK 提交身份与持久凭据前核验调用归属与连接代次；已取消的成功 ACK 用精确房间与令牌退房，释放落定后串行处理下一次入房，旧连接回包不得向新连接发送旧退房。
- 同房间、令牌与连接代次的恢复请求共享在途事务，允许 StrictMode 新 effect 接管；主动退房、房间关闭或席位替换也取消自动恢复归属。临时恢复失败保留令牌并拒绝，不伪报成功或自动创建。永久失败先清理对应会话，再按原因分流：房间已不在或人被移出时通知页面退回大厅，不走「房号不存在就开一间」，否则造出同号空房，后刷新的人撞上只会看到座位失效；座位失效时房间还在，页面按普通加入重新进入。

## 6. 自动保存与卸载

- 自动保存（配置、题目选项等非对局状态）只在等待阶段允许写入。回调里的 `enabled` 不能证明仍允许保存，**必须在实际发送边界读取 Store**：当前快照房间与草稿归属一致且仍处于等待阶段才提交。
- 组件卸载、离开视口或失焦刷新残余队列时，若对局已开始，必须立即丢弃待提交的草稿，禁止用旧表单快照覆盖进行中的服务端权威状态；合法的等待阶段防抖与卸载刷新保留。

## 7. 环境适应性

- 业务日期展示禁止无参 `toLocaleDateString()`，必须用 `Intl.DateTimeFormat` 显式锁定语言与基准时区；相对时间用原生 `Intl.RelativeTimeFormat`，抽到独立工具模块避免触发 Fast Refresh 规则；SSR/SSG 场景的相对时间节点标记 `suppressHydrationWarning`。
- 信封 id 与追踪号不得假设存在 `crypto.randomUUID()`（HTTP 局域网等非安全上下文没有），降级用同样可用的 `crypto.getRandomValues` 生成符合 RFC 4122 v4 的值，不得抛 `TypeError` 阻断对局，也不用 `Math.random`。信封 id 要含时间戳、单调计数器与随机熵；命令的追踪号取当前活动跨度的追踪号，与同一跨度里的错误上报同号，没有活动跨度才自造。
- 浏览器存储一律经 `lib/SafeStorage` 访问：存储被禁用时取 `localStorage` 本身就抛 `SecurityError`，写满与隐私模式也会抛，业务代码不各写 `try/catch`，也不直接碰 `window.localStorage`；读不到、写不进按返回值降级，不阻断对局。
- 根据环境变量拼接服务端地址时先剥离基准地址末尾斜杠，避免 `//api`。
- 接口基址的取值语义以 `Client/src/lib/ServerEndpoint.ts` 及其测试为准；同源还是跨域属部署口径，由构建注入的基址决定，不在前端代码里写死当前形态。改口径前先按 [Deployment](../../Agents/Deployment.md) 完成 WebSocket 完整链路验证。

## 8. 前端遥测

- 前端异常用 Sentry 全局托管（`ErrorBoundary` 与未处理异常）；上报统一经后端隧道。 **数据路由会在入口的错误边界之前截住页面渲染错误与分块加载失败**，根路由必须自带错误出口，并与入口边界复用同一份回退界面、同一条上报与自愈路径，不得各写一套。性能观测以 Spans 分布式追踪为唯一真相源，**禁止引入性能剖析插件**（缺少对应文档策略响应头时浏览器会拒绝并抛出不可消除的策略违规，且插件因此全局禁用）。
- **豁免只按错误类别，不按引擎文案放宽**：`ignoreErrors` 只收错误类别与文案绑定的条目——第三方扩展改写 DOM、浏览器级良性中断（View Transition、ResizeObserver、`play()` 竞态）。分块加载失败不在名单里。通用网络失败文案（如 Firefox/Safari 的 fetch 失败裸文案）**禁止入名单**：它们同样由普通 API 请求抛出，入名单等于让弱网、CORS 与边缘故障在这类引擎整体失明，而同类故障在 Chromium 依旧可见，跨引擎结局不对称。分块加载失败的自愈走构建产物自带的 `vite:preloadError`：门闩放行时取消该事件并重载，错误不会抛出也就不上报；门闩已用过后事件不取消，错误照常抛出，由路由错误出口与上报按真实故障处理（未自愈的必须照报）。开发服务器没有该事件，开发态不自愈。
- **壳与网页在事件上必须可区分**：初始化必须携带 `surface` 标签（`web` / `desktop` / `mobile`）；原生壳版本写 `dist`（`clientType@clientVersion`），与网页发布号（`release`）分命名空间。标签唯一来源是壳在页面加载前注入的只读身份（见 `Client/src/lib/BakaChannel.ts`），网页环境探测不到即记 `web`；禁止硬编码现网标识。
- **一切出口经 driver 接缝**：SDK 出口（init、capture、logger、metrics、startSpan、transport）必须全部经 `SentrySdkDriver`，测试注入假 driver 后天然零外发，禁止任何出口绕过接缝直调 SDK；日志出口必须有 `beforeSendLog`，按与事件侧一致的噪声边界过滤。
- **采集链路自身故障必须可见**：客户端事件全部经同源隧道，隧道 5xx 或请求失败时 SDK 只会静默丢事件——transport 出口必须包一层故障感知，以节流的本机告警（`console.warn`）留可见信号，防止「无事件」被误读为「无故障」。
- **不设匿名 HTTP 遥测端点**：事件、日志、指标只有 Sentry 一条通道，新增上报一律经 `Sentry.ts` 的既有出口，禁止另起 HTTP 直报（服务端也不提供此类端点）。
- **瞬时外部干扰必须自愈，且重载严格限流**：分块加载失败与第三方扩展改写 DOM 破坏 React 父子节点不变量，都应自动重载让玩家无感恢复。所有自动重载必须经统一的会话级一次性门闩放行（同一会话同一恢复点位只重载一次），浏览器禁用存储时安全拒绝并按原样抛出真实错误；禁止各处裸写 `sessionStorage` 判定。
- **协议层错误应答是数据，不是异常**：WebSocket 客户端收到的业务拒绝（房间不存在、密码错误、阶段不对等）与断连、超时同属正常协议应答，只记指标与日志；只有真正的 Error 才允许 `captureException`。判定走唯一的类型守卫，禁止各处重复实现形状探测。
- **模块脚本解析失败按栈帧剔除，禁止按文案猜测**：响应体不是合法 JS 时抛出的语法错误与 JSON 解析错误同形，`ignoreErrors` 无法精确表达，必须在 `beforeSend` 里仅当异常类型是语法错误**且**栈帧含内建模块解析帧时丢弃，不得按裸文案过滤。

## 9. 共享代码

共享源码的运行依赖由消费端显式声明，两端都必须声明 TypeBox；客户端的路径映射与 Vite/Vitest 去重把共享文件的 TypeBox 导入解析到 Client 安装，不依赖 Server 的依赖目录，也不复制 schema。映射位置见 [Conventions](../../Agents/Conventions.md)。

## 10. MCP 设置与标签页接管

服务端模型见 [Server Engineering §5](../../Server/docs/Engineering.md#标签页接管)。

- 房间的 MCP 可用性由服务端 `allowAgents` 驱动：建房弹窗、等待页与大厅卡片读同一字段，前端不得自行推断或缓存成另一套开关。房主开关留在房间的 MCP 设置项。
- **配对入口只有一块**：全局设置与房间的 MCP 设置项复用同一个组件，不为房间另写一套提示、锁定或退出方式。配对码不进本地存储，整块对 Agent 不可见。配对成功后设置面板自动收起。
- **接管层挂在根布局**，不依赖路由与页面数据，同步打包：页面崩溃、懒加载失败时收回入口也必须在。接管期间人类看到的只有透明挡板、焦点框、状态条与收回入口，不加模糊或遮罩，任何页面都是这一份。
- **收回入口是安全底线**：始终可点，键盘用 Tab 或 Esc 直达；点击后本地立刻解锁并中止手上的动作，不等服务端回执。断线时补发。
- **锁定按事件是否可信判断**：人类输入都是 `isTrusted`，Agent 回放的是脚本事件。不用 `inert`：它会让真实控件失去焦点，也管不到挂在 body 上的弹窗。浏览器级快捷键（刷新、开发者工具）放行。
- **Agent 操作前必须让人看见**：先把目标滚入视野，焦点框移过去、停一拍再动手。节拍取 `Motion.ts` 的令牌，焦点框只画不改变布局。焦点按控件追踪，跨页面、页面重建或刷新后继续；可交互控件尽量写稳定的 `data-agent-control`，它同时是 Agent 看到的控件 id 与刷新后找回焦点的依据。
- **页面读取只读 DOM**：`PageView.ts` 不碰 Store，新增隐藏答案的展示方式时确认它在 DOM 上确实不存在或被判定为隐藏，不能只靠视觉遮挡之外的手段。
- 接管中不播放「轮到你了」一类的提示：操作的不是人类。
- 焦点框与状态条不显示答案、别的玩家私有信息或聊天正文，只呈现控件标签与动作；输入内容写进真实输入框。公开的站点活动不得带这些内容。
- 玩家侧不展示接入文档页；机器发现由 `llms.txt` 与 well-known 文件承担，二者不互为替代。

## 11. 全局设置与顶栏入口

- 首页、三个大厅与三个房间共用同一份设置面板：齿轮入口固定在右上角，房间内反馈按钮紧挨设置。面板只放本机偏好，不重复房间玩法设置。
- 云同步开关属于本机偏好，不进入同步范围；关闭后停止云同步生命周期，不再上传或读取云端。
- **云同步不得用陈旧本机值覆盖云端，也不得跨账号**：协议整份覆盖，所以只上传自上次同步以来本机改过的键，上传前先拉取云端并带上其余键，上传同时只有一份在途；本机缓存记录所属账号，换号登录先清掉上一个账号的偏好与音乐账号凭据再合并，不上传到新账号。偏好变更与应用通知走模块订阅，不用 `window` 事件。
- 提示音音量只作用于合成提示音；猜歌播放音量仍由猜歌房间顶栏的播放器控件管理，两者不合并。
- 首页入口按 `GET /api/site/config` 呈现：后台临时关掉的模式**留在原位、置灰、标注「暂时关闭」、点不进去**，不隐藏；单一入口游戏把「开始游戏」换成同尺寸的占位格。只有明确的 `false` 才算关，读不到、少字段都按开放处理，解析用共享的 `parseSiteFeatures`，不在页面里另写一份。

## 12. 统一实时入口与站点通道

- 三款游戏与站点通道共用 `/api/ws` 一条升级路径；路径只在 `Client/src/lib/` 的门面里出现，组件不手写 ws 地址。旧路径仅服务端兼容保留，前端不得回退使用。
- **站点通道在根布局建立并保持**：任意页面（尚未进入任何游戏）都必须有一条连接，标签页身份、Agent 活动与站点级事件才有落点。它只走 `site.*`，不承载房间状态。标签页接管不改变这条连接的存续：收回接管只让服务端停止下发页面指令，连接与订阅保持不变。
- **标签页身份由站点连接领取**，规则见 [Server Engineering](../../Server/docs/Engineering.md#标签页身份)。令牌只存 sessionStorage、只走首帧，不进 URL、遥测与任何持久存储；判断「是不是我」一律比 `privateState.playerId`，组件不另存身份。
- **业务命令排在身份之后**：连接打开后先走完前置帧才宣告可用，`send`、`waitForConnection` 与状态回调都以此为准。前置帧失败不拦业务，按无身份继续；令牌迟迟等不到也有上限，不把玩家挡在游戏外。
- **继承来的存储必须丢弃**：sessionStorage 被复制时，身份连同全部座位凭证一起丢，昵称在 localStorage 不受影响；留着座位凭证就会把原标签页顶下线。判定在页面加载时同步完成，新增座位凭证的存储键要登记进统一清理入口。
- 页面指令由根布局的接管宿主执行，执行模块按需加载，没有接管的页面不多下载；结果连同最新画面经 `site.page.result` 回执，未接管时一条都不发。
- 站点通道与游戏通道是**不同的物理连接，同一个身份**：CEE 的客户端票据按握手一次性消费，共用一条连接时任一游戏换票重连都会掐断别处正在进行的座位；身份靠首帧挂到每条连接上。要合并成单连接，必须先把票据改成连接内协商。
- **连接回调必须核对身份，重连必须有抖动**：每个处理器先确认自己仍是当前连接，旧连接（含关闭中）迟到的事件一律丢弃，请求只随所属连接一起被拒；退避取随机延迟并有下限，业务可用后稳定存活一段时间才清零，握手即断的服务端不会形成紧密重连；联网恢复与页面回到前台时把已排定的重连提前，但仍受最小间隔约束。协议里没有应用层心跳或空命令，半开连接只能靠请求超时暴露，不自造探测帧。
- 重连后必须重新发 `site.subscribe`：订阅记在服务端连接上，断开即失效。用统一的连接状态回调重发，不在组件里各写一份。
- 首页指示器只呈现服务端下发的站点活动（名称、位置、动作），不自行推断房间或权限；条目按服务端 TTL 过期，客户端的本地计时只做漏帧兜底，不做第二个真相源。
- 站点活动字段是封闭集合：搜索词、猜测、聊天草稿与控件逐字输入不得进入站点广播；控件焦点由被接管的页面自己画，不经过服务端。`label` 由 Agent 自报（页面标题一类），前端只负责展示与截断。
