# 前端视觉与动效原则

改页面、组件外观、布局或动效时使用本文。大方向见 [DesignVision](DesignVision.md)（冻结，未经用户准许不得修改）；本文只写全局、长期稳定的原则与取舍理由。

**边界**：具体页面布局、控件数量与位置、组件选用、样式值、断点与动效实现以代码为准，本文不记录。实现与本文或局部历史写法不一致时，先判断是否违反本文的全局原则；不违反就按代码现状修订文档，不为对齐旧文案回改实现，也不因此询问用户。令牌值读 `Client/src/index.css` 与 `Client/src/lib/Motion.ts`，组件用法读 `Client/src/components/ui/` 与相邻页面。

## 1. 基本原则

- 修改前先读目标组件、相邻页面与公共控件，复用现有模式；相同交互不在不同页面各写一套。
- 不因局部需求破坏房间信息、游戏主流程、玩家列表与聊天的视觉优先级。
- 用户可见内容只用真实业务文案，不出现设计说明、主题名、展示性文案、占位按钮或假数据入口。
- 不因单个页面的需求修改全局主题；全局观感只改语义令牌。

## 2. 技术基线

- 样式用 Tailwind CSS 与 `index.css` 的语义变量；主题的唯一全局标准在 `:root` 与 `.dark`。圆角、阴影、字体、字距等基础值不在业务组件里重新定义。
- 明暗主题由 `.dark` 类控制，`dark:` 不直接绑定系统偏好；首帧在样式表加载前落位，避免闪白。
- 通用交互优先复用公共控件与底层无障碍原语；条件类名与变体走项目现有工具，不手写第二套。
- 界面图标统一用图标库，不手绘 SVG、不用文字字符或 emoji 冒充标准图标；品牌图标只用官方字形，找不到就回退通用图标，不用近似品牌顶替。
- 层叠只用 `index.css` 的语义层级令牌，禁止业务组件写任意 `z-index` 魔数。

## 3. 色彩与表面

- 保持暖纸与暖褐的基调，不用纯白、纯灰或冷色中性底；纸纹理只铺整页底层，业务表面保持纯净实底。
- 只用语义色令牌，不硬编码颜色；主色只用于主要操作、当前玩家与明确交互焦点，不大面积铺色，不作正文色。
- 状态色只表达真实业务状态；中性状态、等待与旁观用中性文字色，不按氛围给图标上色。
- 状态不能只靠颜色传达，必须同时有文字、图标、边框或形状。
- 表面按“页面底 → 面板/卡片 → 浮层”建立层级，用明度、边框与轻阴影分层；流内区块不加背景模糊，模糊只留给浮层与遮罩。
- 颜色令牌按 WCAG AA 标定；新增或调整颜色时在明暗两个主题下同时核对对比度。

## 4. 字体与文案

- 全站以衬线体为视觉基线；无衬线体只用于微型密集文本，等宽体用于房间号、链接、哈希、时间戳这类数据特征内容。
- 无衬线体与等宽体自托管霞鹜文楷（LXGW WenKai）与霞鹜文楷 Mono 的 WOFF2 子集；完整字体文件不随仓库分发，构建期从固定版本的上游仓库取源并核对摘要。
- 字体子集、生成 CSS 与上游下载缓存都是构建产物，由 Vite 启动钩子按输入哈希生成，不提交到仓库；站点不得直接分发完整字体文件。
- 站点只引用生成出来的字体子集，不手写 `@font-face`。新增字重、调整字符范围或升级字体版本后必须更新固定版本与摘要并重新生成子集；字体许可原文随静态资源一并提供。
- 字号、行高、字距取全局令牌，不写任意像素值，不按视口动态缩放；业务组件不单设字距。
- 层级靠字号档与字重建立，不用宣传页式大字；面板内标题保持紧凑。
- 文案简短、直接、可执行，按钮用明确动词；用户生成内容必须能换行或截断，不得挤压关键操作。

## 5. 布局、间距与形状

- 用稳定的布局手段管理尺寸，避免加载、内容变化或错误态导致跳动；空、加载与错误状态保持主要布局尺寸。
- 控件高度与基础间距沿用公共组件与全局档位，不在局部另设一套。
- 圆角、阴影与边框保持统一档位；不用装饰性卡片包裹普通区块，不在卡片里嵌套卡片。
- 主要结构用一层轻边框分层；阴影越靠近用户操作焦点越明显，流内内容不用重阴影。

## 6. 组件与交互

- 基础控件与通用交互只维护一份公共实现；业务组件不重写按钮、输入、弹窗、浮层等基础能力。
- 每个可点击元素都有按压或悬停反馈，并提供禁用与进行中状态；异步提交在回执前防重复提交。
- 危险操作必须显式确认；确认与取消的顺序、强度和语义在全站一致。
- 校验失败尽量落在对应字段；归不到字段的失败给可见文案或全局提示。
- 弹窗、浮层与覆盖层必须可从键盘关闭，关闭后焦点回到触发点；打开期间背景内容不可交互。

## 7. 响应式与可访问性

- 页面改动至少检查窄屏、双栏与宽屏三档；文本、按钮、徽章与顶栏不得重叠，空间不足时优先截断次要信息。
- 可交互元素必须有可见的键盘聚焦指示；图标按钮有可访问名，可展开与切换控件暴露对应状态。
- 禁用、加载、错误与离线状态不能只靠颜色或动画表达。
- 连续追加的内容流用合适的 live region 只播报新增内容；装饰性动画对读屏隐藏。
- 减弱动效偏好下界面完整可用，状态变化仍可辨。

## 8. 动效

- 动效必须有成因：用户操作、服务端状态变化或元素进出场；说不出成因的动画不加。
- 空间连续：浮层从触发它的元素展开并沿原路收回；同一对象在移动中始终是同一个 DOM 元素，不做两个元素交接。
- 运动有重量与方向：优先弹簧与阻尼，轻的东西快、重的东西慢；hover 之外的动效不得是匀速线性，加载旋转与进度条除外。
- 所有时长、曲线、弹性、位移与缩放只取 `Motion.ts` 令牌，业务组件不写裸数字、裸贝塞尔或字符串缓动。
- 只动 `transform` 与 `opacity`；尺寸变化优先缩放，循环动画只用于真实的持续状态。
- 延迟只建立因果次序，不推迟玩家的操作能力；不把淡入加纵向位移当作批量列表的主要进场手段。
- 折叠与指示箭头同步；交替两态在同一容器内交叉，不先清空再出现。
- 骨架屏与真实内容共用布局，只淡出不缩放；同一屏多个动画元素要有前后层级与节奏。
- 页面导航经统一路由过渡，不各写一套；过渡期间不响应会改变当前页内容的点击。

## 9. 验收

- 新增样式前先确认公共组件或现有语义类已覆盖需求。
- 页面改动按 Testing 完成构建、静态检查与受影响页面的浏览器验证；只改本文档不触发客户端构建。
- 新增组件或视觉状态同步补 Storybook 故事；样式调整用截图对照评审。
- 浏览器检查覆盖与本次修改相关的状态：正常、空、加载、错误、禁用、长文本、窄屏与减弱动效。
- 验收看现有页面的一致性、真实可用性与交互完整性，不以单张静态截图作唯一判断。
