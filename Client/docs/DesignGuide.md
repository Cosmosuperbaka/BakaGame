# 前端设计细则

改页面、组件外观、布局或动效时使用本文。大方向见 [DesignVision](DesignVision.md)（冻结，未经用户准许不得修改）；本文是它的执行细则。

维护：大模型发现本文与项目实际风格不符、过时或可以更清晰时，可以直接修订本文，使其符合 DesignVision 的精神；改动先在代码里落地并验证，再改文档。本文只写**约束与取舍理由**，不写能从代码读出的清单、数值和文件位置：令牌值读 `Client/src/index.css` 与 `Client/src/lib/Motion.ts`，组件用法读 `Client/src/components/ui/` 与相邻页面。

## 1. 基本原则

- 修改前先读目标组件、相邻页面与 `components/ui/` 里已有的实现，复用现有模式；相同交互不得在不同页面各写一套外观和行为不一致的私有版本，需要复用时下沉到公共组件。
- 不因局部需求破坏房间信息、游戏主流程、玩家列表和聊天的视觉优先级。
- 用户可见内容只用真实业务文案，不出现设计风格说明、主题名或展示性文案。不保留占位按钮、假数据入口。
- 不因单个页面的需求修改全局主题，除非这次变化明确要影响整个客户端。

## 2. 技术基线

- 样式用 Tailwind CSS v4 与 `index.css` 的语义变量。主题取 tweakcn 的 `vintage-paper`，唯一的全局设计标准在 `index.css` 的 `:root` 与 `.dark`。要调整全局观感就改主题变量，不在业务组件里局部覆盖，也不在组件里重新定义圆角、阴影、字体、字距这类基础值。
- `dark:` 绑定到 `.dark` 类而不是系统偏好；站内顶栏提供「浅色 / 深色 / 跟随系统」三档切换，首帧由 `index.html` 的内联脚本在样式表加载前落位，避免闪白。
- 通用交互优先复用 `components/ui/`，不绕过底层 Radix 的行为。条件类名用 `cn`，变体用 `class-variance-authority`。
- 图标：界面图标统一 `lucide-react`，不手绘 SVG，不用文字字符或 emoji 代替标准图标。第三方平台品牌图标用 Font Awesome 官方字形，npm 包与开源项目品牌图标用 simple-icons，都必须逐图标引入（聚合入口无法摇树）。品牌图标只用于标注站外平台或依赖本身。找不到官方字形时回退通用图标，不手绘、不用近似品牌顶替。
- 全站图片的原生拖拽虚影由全局统一处理，业务组件里不再散落 `draggable={false}`。

### 层叠

层叠只用 `index.css` 里 `--z-index-*` 语义标尺，从低到高：base、panel、sticky、drawer、dropdown、overlay、modal、popover、toast。禁止业务组件写任意 `z-[80]` 之类魔数。变量必须写在 `--z-index-*` 命名空间下，写成 `--z-*` 不会生成工具类，类名静默失效。

## 3. 颜色与表面

- 页面是暖白，卡片与浮层比页面更亮，正文暖褐。不要改回纯白、纯灰或冷色底。
- 用语义色（`background`、`foreground`、`card`、`muted`、`accent`、`border`、`primary` 等），不硬编码颜色。
- `primary` 只用于主要操作、当前玩家与明确的交互焦点，不大面积铺色，不作正文色——不作正文色是层级取舍，不再是对比度限制：主色已与状态色同一档按 AA 双向标定（实底压前景、作文字压标定表面与自身 `/10` 浅底）。`--ring`、`--chart-1`、`--sidebar-primary`、`--sidebar-ring` 与主色同值同标定，改这几枚取值由 `src/lib/DesignTokens.test.ts` 复算守住。`accent` 只作悬停与浮层内高亮，不作流内常驻底色。
- 次要文字直接用 `text-muted-foreground`，不再叠透明度，令牌已按对比度标定。禁用与离线状态整体降不透明度。
- 三块主面板（游戏区、玩家栏、聊天栏）用 `bg-panel`，不用 `bg-card` 或硬编码色替代。
- 就近浮层（表情选择器、提及候选、下拉、Tooltip 等）用 `floating-surface`，靠模糊与阴影立起来，不靠加深底色。`bg-secondary` 偏深、`bg-card` 近纯白，都不作浮层底色。
- 亮暗两个主题的表面明度顺序并不对称。新增颜色必须在 `:root` 与 `.dark` 下同时确认对比度；骨架条、选中底块、开关滑块、遮罩的暗色写法按现有组件照做，不凭亮色经验推断。
- 纸纹理只铺在整页底层画布。业务表面（卡片、面板、按钮、浮层）保持纯净实底，整页外壳与房间顶栏不设不透明底色遮挡纹理。调整纹理或表面色后，重新核对文字对比度。

### 状态语义色

- 状态色只用于真实业务状态，一律取 `index.css` 的语义令牌（`destructive`、`success`、`warning`、`questioner`、`info`），不写调色板色阶，不逐处补 `dark:` 变体。
- 中性状态（等待、旁观）取 `muted-foreground`，不引入第三种灰。阶段本身不是状态，不按氛围给图标上色。
- 浅底、描边、悬停预览只用一套透明度档位：底色 `/10`、描边 `/40`、悬停预览 `/5`。浮层内的选中档例外，半透明底会被浮层底吃掉，改用实底。
- 浮在内容之上的状态提示（Toast）外层必须不透明，浅底叠在内层，保证对比度与身后内容无关。
- 状态不能只靠颜色传达，必须配文字、图标、边框或形状。
- 令牌按 WCAG AA 标定（铺纹理后的实测）。新增或调整令牌时两个主题同时核对。完整无障碍验证需要辅助技术与人工审查。

### 表面档位与悬停

- 中性表面只用五档：页面底（`bg-background`）、面板（`bg-panel`）、实色块（`bg-muted`、`bg-card`）、淡色块（`bg-muted/40`，流内唯一的半透明中性档）、浮层。不再按局部观感另调透明度（`bg-muted/20`、`bg-card/40` 之类）。
- 实色块上不再叠半透明 muted，内嵌小块改用 `bg-background`。中性描边与分隔线不带透明度。
- 淡色块与虚线空状态不加外投影；流内区块不加 `backdrop-blur`，模糊只留给浮层与区内遮罩。
- 悬停分三类：流内可点击的行、卡片、选项用 `hover:bg-accent/40`，不改文字色；按钮与浮层内条目用实底 `hover:bg-accent`；嵌在淡色轨道里的 ghost 小按钮用 `hover:bg-background`。带滑动指示器的容器里，未选中项悬停只加深文字，不加底色。

## 4. 字体与文案

- 全站以衬线体为视觉基线，`body` 默认 `--font-serif`；西文字体在字体栈里置前，避免中文字体自带西文导致发虚。
- 无衬线体只用于四类微型密集文本：玩家分组标题与计数、玩家状态与身份徽章、分数后的单位、聊天发言者姓名。统一常规字重（小字号配粗体会糊死）。除此之外不得滥用 `font-sans`。
- 等宽体择机用于房间号、分享链接、哈希、时间戳这类代码或数据特征的内容。
- 字距由全局令牌统一控制，业务组件不单设 `letter-spacing`。字号基线由 `html` 控制，不按视口宽度动态缩放。
- 字号只取 Tailwind 字号档与 `@theme inline` 的字号令牌，不写 `text-[11px]` 一类任意值；确需新档位先加令牌。微型字号令牌必须用 `px` 定义（根字号不是 16px）。
- 阶段标题、区域标题、正文、辅助信息各用固定的字号档，不使用宣传页式大字。只有产品名与确属页面主标题的内容用大字号。面板、弹窗、卡片内标题保持紧凑。
- 文案简短、直接、可执行，按钮用明确动词。用户生成内容必须能 `break-words`；单行名称空间不足时 `truncate`，不得挤压关键操作。
- 断行由全局统一处理：标题平衡、段落避免孤字。成段说明用 `<p>` 才能拿到。只写 `text-wrap-style`，不写简写 `text-wrap`（会重置继承的 `nowrap`）。聊天气泡这类按内容收窄的容器不加 `pretty`。

## 5. 间距、圆角与阴影

- 用稳定的 `flex`、`grid`、固定侧栏宽与 `min-w-0` 管布局，避免内容变化导致跳动。
- 控件高度沿用公共组件，不另设；常规间距优先 `gap-2` 至 `gap-4`、`space-y-3` 至 `space-y-6`；游戏主区域内边距沿用现有写法。
- 圆角整体偏方正：标准圆角 `rounded-md`。聊天气泡是唯一例外（`rounded-xl` 加单侧 `rounded-sm` 区分方向）。圆形（开关、进度、状态点）与胶囊（步进器、音量、标签组）用 `rounded-full`。除此之外禁止 `rounded-lg`、`rounded-2xl`，也禁止不带尺寸的 `rounded` 与 `rounded-sm`，更不得写死像素圆角。
- 他人聊天气泡用 `bg-muted`（明度略低于所在面板），自身气泡用 `bg-primary`；不要把他人气泡改成近白的 `bg-card`。
- 主要结构用一层轻边框区分。阴影只用三档：流内 `shadow-sm`（更平用 `shadow-2xs`，流内不用 `shadow-md` 及以上）；就近浮层 `shadow-md`；覆盖整块内容的层 `shadow-lg`。`shadow-xl` 与 `shadow-2xl` 不用。控件即使配了 `floating-surface` 也取 `shadow-sm`。
- 不在卡片里嵌套装饰性卡片，不把普通区块全部做成悬浮卡片。

## 6. 组件使用

这一节只写**该用哪个公共组件**与**为什么**。用法细节、属性读组件本身与 Storybook。

- 命令用 `Button` 的既有变体；纯图标命令用 `size="icon"` 并提供可访问名。进行中状态一律用 `Button loading`，按钮文案保持原名，不换成“创建中…”；多个按钮共用一把锁时全部禁用，`loading` 只落在被点的那个上。
- 悬停说明用 `Hint`，不用原生 `title`。只在悬停能说出正文看不到的内容时才挂：被截断的文本、纯图标按钮、相对时间、汇总数。`Hint` 不能夹进 Radix 的 `asChild` 槽位链，要改写成显式的 `TooltipTrigger asChild` 套在外层。
- 关闭按钮用 `CloseButton`；加载指示用 `Spinner`（不手写 `animate-spin`）；输入用 `Input` / `Textarea`，外框用 `field-frame`，调用处只改高度、内边距与底色；回车提交的输入框先判断 `nativeEvent.isComposing`。
- 能落到具体字段的校验失败走字段自身的错误态，点过一次提交后才显示；服务端返回、归不到字段的失败只给文案或 Toast。
- 搜索统一用 `SearchCombobox` 与 `UseIdleSearch`：停止输入后自动查，不另设“搜索”按钮；结果面板走 Portal，不把操作区往下挤；候选整行可点，不在行尾另放“选择”。
- 模态任务用 `Dialog`，取消在前（`outline`）、确认在后；带输入的弹窗整体是 `<form>`，回车提交，失败只写在弹窗内。
- 简短状态用 `Badge` 的既有变体，不把按钮做成徽章，也不覆写徽章的底色、描边、字重、字号。谁是卧底的身份只用 `RoleBadge`。可移除筛选项用 `FilterChip`。
- 二元配置用 `Switch`，枚举用 `Select` 或 `Tabs`，两三个互斥且需常显的选项用 `SegmentedControl`，有界整数用 `SettingStepper`，连续值用封装好的 `Slider`（禁止手写透明原生 range）。设置面板里的字段一律用 `common/room/SettingFields` 的 Setting 系列组件，不手拼 `useId` + `Label` + `Input`。
- 折叠区域用 `Collapsible` / `CollapsibleRegion` / `SettingsAccordion`，不写原生 `<details>`；非房主在设置里看到与房主同一份结构，只是控件换成取值文字。
- 结算得分表统一用 `common/room/ScoreTable`；数字不着状态色（绿与金只表达状态）。
- 房间列表加载用 `RoomCardSkeleton`，与真实卡片共用 `RoomCardLayout`，加载前后不跳动。
- 全局浮动提醒统一居中底部浮层，适配暗色，不用硬编码告警色，开发环境不展示。展示层只由 Props 驱动，检测逻辑另放。

## 7. 页面布局

规则优先于细节；具体的断点、宽度、字段读 `RoomShell`、`LobbyPage` 等实现。

### 7.1 主页

- 站点主页只含站点标识、游戏入口区、页脚三层，居中、易扫描，不新增营销模块、玩法介绍或标语。账号入口是唯一例外：右上角一枚小控件，账号系统未启用时整枚不渲染。
- 游戏入口在各视口单列堆叠。未上线的入口保持相同尺寸，以“即将上线”徽章表达，整卡不降不透明度，不可点击不可聚焦。
- 点击可用条目即导航，不等按压播完。
- 图标资源放 `public/assets/` 并按真实文件名引用，不通过 `src/assets` 打包。
- 页脚只放友情链接、外部链接图标行与版本号；外部链接是纯图标链接，新标签打开，带名称提示，不加文字标签，不做彩色品牌底。
- 对外口径的下载入口措辞必须自带限定，不得读成游玩的前置条件；链接地址只有一个来源，不得在组件里写第二份。

### 7.2 大厅

- 三个游戏的大厅共用同一套外壳，保持单列居中；各游戏把自家房间摘要映射成统一视图，外壳不认识任何游戏的字段。
- 公共外壳的输入上限由各游戏按自家协议传入，外壳只给默认值；抽取公共组件时不得把某个游戏的限制硬编码成全局值。
- 房间项整张卡片可点，徽章与人数不换行，空间不足只截断房名。上游不提供的数字（如旁观人数）传 `null`，不显示，不伪造为 0。
- 空状态、加载、错误不得改变主要布局尺寸，必须给真实业务反馈。创建入口只有一个。
- 用户名为空时点创建或进房，在页内拦截，不开弹窗。
- 只在建房这一刻生效的选项由 Props 驱动，没有资格就不传，不渲染成禁用态让人点了才被服务端拒。

### 7.3 房间页

- 三个游戏的房间页共用 `RoomShell`：固定高度顶栏 + 三栏主体 + 覆盖面板。顶栏、栏宽、断点与内边距只在该组件内维护，各游戏只提供栏内容。
- 玩家栏与聊天栏同时常驻的断点要保证游戏区仍有足够宽度；断点以下走顶栏入口加覆盖面板（`RoomDrawer`，焦点锁定、Esc 与点背板关闭、关闭后焦点回入口）。窄屏专属浮层用 `UseCloseFrom` 监听断点，不各写 `matchMedia`。
- 游戏区统一挂 `PhaseStage`，阶段内容不再各自写内边距。阶段标识变化即触发切换。倒计时用 `CountdownBadge`，不各写一套。
- 等待页：主操作同一口径（房主整宽开始按钮，不能开始时禁用并写明原因；非房主居中的准备切换）。设置在等待阶段就地折叠编辑、防抖自动保存。
- 队伍选择面板分「我方」与「对手」两区：当前队伍占满一行并列出全部队员，其余队伍用紧凑小格，个人游玩单独一行；所有选项仍是同一个原生 radio 组，换队后的视觉重排不得改变键盘顺序。
- 阶段内按钮只按两种口径排，不追加尺寸覆盖：表单提交整宽，推进类居中。结算操作区居中，描边的次按钮在前。
- 指定出题人或主持人是独立阶段，三个游戏同一形态；候选名单只取服务端下发的，客户端不自行筛选。
- 玩家行只有 `PlayerRow` 一处实现，差异由插槽注入；头像用统一的首字方块头像，只作身份提示，不编码身份、得分或在线状态。玩家栏固定“玩家”“旁观”两组，队伍分块用公共的 `TeamSection`。
- 玩家行首行固定放名字、房主、账号身份徽章与分数，状态放次行；房主、准备、离线都要有文字徽章，不只靠图标、整行透明度或颜色。离线不压整行透明度，避免名字不可读。
- 账号身份徽章（开发者 / 贡献者 / 内测 / 赞助）紧跟房主标识、在分数之前，用中性描边与状态色区分；文字始终保留，无徽章时不占位。徽章按用户 ID 从公开资料缓存读取，不写进房间快照。
- 两行玩家行保持紧凑：组队房间八人以上应在一屏内可见。优先压缩队伍标题、分组间距与列表外留白，不缩小头像与字号；头像高度加两行信息就是行高下限。
- 玩家列宽等跨组件共享的布局常量单一定义，且必须以 `rem` 表达（根字号不是 16px）。
- 纵向 `ScrollArea` 内容层用块布局，禁止表格最小内容宽度撑开玩家栏。长名字、分数、历史展开必须用浏览器验证实际可见范围。
- 发言历史：发言单元格直接渲染进玩家行内，逐行对齐靠 DOM 结构，不靠两侧各自复刻行高；展开状态记录 `roundId`，不存布尔值。
- 发言按顺序揭示：前面的人没交，后面已交的也保持折起；未公开的格子用 `PendingSpeech` 占位。
- 本人词语始终是同一个元素：居中放大展示后连续位移缩小到顶栏停靠位，顶栏只放等尺寸占位。
- 游戏区内的区内浮层只在游戏区内部分层，不越过玩家面板。
- CEE 反馈表：一次猜测一行，最新在最上；每格一个色块，远近另由箭头数量区分，不只靠颜色；窄屏角色列贴左缘，底色不透明；整表在窄视口横滚是既定形态，改动列宽或栏宽时重测这条分界。
- 猜歌顶栏音量控件、音乐账号配置的细节读对应组件；约束只有：触屏没有悬停，弹出层里轨道始终是粗的一档；静音与直接输入的显示值与提交值一致；音乐账号的展开与收起态在同一格里交替，行高不跳。

### 7.4 管理后台

- 与大厅同一种顶栏，页面本身不设权限，数据全部由服务端按管理员身份校验；页面不进静态外壳，不被索引。
- 各标签面板共用 `components/admin/AdminParts` 与 `UseAdminQuery`；筛选用 Setting 系列字段，关键词搜索停止输入后再查；时刻一律按北京时间。
- 危险操作走 `ConfirmDialog`（取消在前、destructive 确认在后）。不能对自己封禁或改角色时不给按钮并写明原因。
- 反作弊复核处置只给队列记账，不改对局、不处罚任何人，因此不做二次确认。

### 7.5 版本信息与开源致谢页

## 8. 动效细则

动效的精神见 DesignVision。令牌、变体与数值**只**在 `Client/src/lib/Motion.ts` 与 `index.css` 里维护，新增变体必须在 `Motion.ts` 里写清适用场景（本文不再登记清单，避免两份事实）。

### 8.1 硬性规则

- **接入反馈。** 每个可点击组件都接入既有的按压反馈，仅有 hover 颜色不够；公共组件已内置的直接复用。新增可点击元素时同次提交接入。
- **取值。** 所有时长、曲线、弹性、位移与缩放幅度只取自 `Motion.ts`。业务组件里不得出现裸数字时长、裸贝塞尔数组、字符串缓动简写（`"easeOut"`）或自行编写的 `whileTap`。等动画结束的 `setTimeout` 用计时令牌，不写裸毫秒。
- **非线性。** hover 之外的动效必须非线性：弹性过渡，或时长配缓动曲线。禁止 `ease: "linear"`，唯二例外是持续旋转的加载指示与倒计时进度条。
- **不批量位移。** 禁止把 `opacity + translateY` 当主要动画手段，尤其不对批量列表项统一纵向位移。列表项进场用既有的列表变体，继承父级错峰的项只写变体引用；纵向位移只用于单个有明确方向语义的元素。
- **不写 CSS 按压缩放。** 不用 `active:scale-*`（没有过渡，也不受减弱动效约束）。
- **不用不存在的类。** 项目未安装 `tailwindcss-animate`，`animate-in`、`zoom-in-95`、`slide-in-from-*` 等全部无效。Radix 浮层的开合只有两种做法：能包 `AnimatePresence` 的由 framer-motion 接管；只受 `data-state` 驱动的由 `index.css` 的关键帧提供。
- **CSS 令牌单一来源。** `--motion-*` 变量由 `installMotionTokens()` 写入 `:root`，`index.css` 不手写。Tailwind 过渡类不写 `duration-*` / `ease-*`，默认值已指向令牌。
- **手势预设只挂在真正的交互元素上。** 含 `whileTap` 的预设会让 framer-motion 自动补 `tabIndex=0`。预设、`role`、`tabIndex`、键盘事件必须在同一个元素上；外层仅承担动画的包裹元素显式写 `tabIndex={-1}`。验收：键盘逐次 Tab，每个可点元素恰好一个停靠点。
- **减弱动效。** `MotionConfig reducedMotion="user"` 只管 framer-motion。新增 CSS 关键帧必须自行包裹 `prefers-reduced-motion: no-preference`；加载指示一律用 `Spinner`。减弱动效下界面仍然完整可用，状态变化仍可辨。
- **性能。** 只动 `transform` 与 `opacity`；`width`、`height`、`filter` 仅在无替代时用且限定范围。尺寸变化优先 `transform: scale`。循环动画只用于真实的持续状态。
- **含文本区块的整体缩放动画**：收紧弹簧的静止判定，并在结束回调里清空内联 `transform`，否则残留的分数缩放会让文字发生子像素抖动。

### 8.2 因果与连续

- **浮层有来源。** 弹窗从触发按钮展开并沿原路收回（用 `useOriginTracker` 捕获触发点）；侧边抽屉从它收回的那条边缘滑入滑出；就近弹层的缩放原点朝向触发元素，用 Radix 给出的原点变量，不写死方向。Popover 一律受控并带 `forceMount` + `AnimatePresence`，否则没有退场。无法取得触发点时，至少把原点指向按钮所在方向，不留在中心。
- **同一个元素连续位移。** 跨区域移动的对象必须是同一个 DOM 元素，不允许两个元素交接（`layoutId` 交接在字号差异大时会换字形）。唯一例外是跨页，由 View Transitions 把同名元素读作同一个对象。
- **页面导航**一律经 `usePageNavigate`，路由为数据路由；共享元素名只在本次过渡另一端是对应伙伴时才命名，避免重名；会改动当前页内容的副作用放在换页之后。过渡期间页面不响应点击。
- **折叠与指示箭头**同步翻转；选中指示器用唯一的 `SlidingIndicator`，位置按布局值量出，不用 `layoutId`（弹窗缩放开合时会飞）。
- **交替的两态**放在同一个 `AnimatePresence mode="popLayout"`（或 grid 叠放）里交叉，不先清空再出现。用 `popLayout` 的两态格必须自身 `relative` 定位，且不能被临时成为包含块的东西包裹（`whileTap` 缩放中的按钮、`will-change: transform` 的容器），否则退场的一态会飞到包含块左上角。
- **玩家栏换组**是整列重排：行 `key` 取“玩家编号 + 换组次数”，不直接用玩家编号，否则退场未完成时换回原组会被原地复活并停在透明态。
- **聊天**发送与别人的消息各有自己的形态，发送用掷出的胶囊并由回显接手；不要把两者的参数互相引用。
- **骨架屏**只在首屏出现、只淡出不缩放，与真实内容共用布局，在同一格内交叉。

### 8.3 层级与节奏

- 延迟只用来建立因果次序，不制造节奏感；任何延迟都不得推迟玩家的操作能力。
- 同屏多个动画元素要有前后关系：阶段切换新内容自后方推入、旧内容向前退出，尺度方向相反；覆盖层背板先于内容出现、后于内容消失；`z-index` 与动画方向一致。
- 缩放原点落在元素“被抓住”的位置：列表项用左缘，浮层用触发点，聊天气泡用发送方一侧的底角。
- 弹性档位按被移动物体的质量感选：越轻越快。需要确定收束时间（擦除、折叠、退出）时才用时长配缓动。

### 8.4 状态反馈与可访问性

- 成功、失败、断线、异步提交反馈用真实状态文案，不靠动画替代业务状态。
- 异步提交失败或超时必须把玩家已输入的内容交还给输入方：动画的落点即内容回位的时刻，成败只按服务端回执判定。动画既不吞原文，也不替回执判定成败；回执已到的那一路不得被动画读成“没发出去”。
- 连续追加的内容流（聊天、日志）读屏用 `role="log"` 配 `aria-live="polite"` 与 `aria-relevant="additions"`：只报新增，不把整段历史每来一条重读一遍。装饰性投掷层保持 `aria-hidden`。
- 所有可点击元素除动效外，仍必须有可见的键盘聚焦、禁用与进行中状态。图标按钮必须有 `aria-label`，可展开元素有 `aria-expanded`，切换类控件有 `aria-pressed`。动效不得是传达状态的唯一手段。

## 9. 交互状态与响应式

- 键盘聚焦指示全站一种：基础层对可交互元素画统一的 `:focus-visible` outline。组件不再写 `focus-visible:ring-*` 或 `outline-none`，只按需声明偏移。`field-frame` 是第二种合法形态。
- 凹槽轨道类控件（步进器、年份区间、团队选择）把这一条指示收在**轨道边界**：外层 `has-[input:focus-visible]:outline-2 outline-ring`，内层输入写 `outline-none`，一个控件只留一条可见指示。这不是第三种形态，内层的 `outline-none` 只是把重复的那条关掉。
- 被 `overflow-hidden` 裁掉圆角的内嵌按钮（筛选胶囊的移除叉）用负偏移把同一条环收进轮廓（`focus-visible:outline-offset-[-2px]`），不改颜色、不加底色来冒充焦点；底色变化只能作为该元素自身语义的补充，不能作为唯一指示。
- 禁用态：原生控件用 `disabled:`；Radix 用 `data-disabled` 的原语改写 `data-[disabled]:` 放在根节点上。字段禁用时标签与图标一并降到同档，字段说明保持原色并经 `aria-describedby` 挂到控件上。
- 异步操作防重复提交，并用按钮状态、加载指示或 Toast 反馈；确认、投票等结果由服务端状态驱动，不依赖本地临时样式。
- 屏幕阅读器播报口径：Toast 容器具名，error 用 `role="alert"`、其余 `role="status"`；倒计时徽章本身不播报，只经旁边的 polite 节点在关键秒数报一次；交替动画期间可访问名写在外层，动画层 `aria-hidden`。
- 页面样式改动至少检查窄屏、`md` 双栏、`xl` 三栏。文本、按钮、徽章和顶栏不得重叠；空间不足时优先截断次要信息、换行或换成图标。
- 固定格式控件用明确的高度、宽度或网格列，避免加载文本、动态图标引发布局偏移。
- 数据表格：不折行的数值列保持原宽，只压缩可折行的文本列，名称列给 `min-w-*` 下限；表头、数值与徽章单元格显式 `whitespace-nowrap`；长拉丁词用 `[overflow-wrap:anywhere]`。表格标题在外部区块标题里时，`<table>` 用 `aria-labelledby` 指向它。
- 窄屏固定定位浮层两侧留等宽边距；居中弹窗用 `w-[calc(100%-2rem)]` 配平移居中，不用 `mx-*` 叠 `w-full`。
- 弹窗与覆盖面板打开后背景不得产生误操作，关闭后焦点由 Radix 原语恢复。

## 10. 验收

- 新增样式前确认公共组件或现有语义类是否已覆盖需求。
- 页面改动按 Testing 完成构建、静态检查与受影响页面的浏览器验证；只改本文档不触发客户端构建。
- 新增组件或视觉状态同步补 Storybook 故事；样式调整用截图对照评审。
- 浏览器检查覆盖与本次修改相关的状态：正常、空、加载、错误、禁用、长文本、移动端、减弱动效。
- 验收看现有页面的一致性、真实可用性与交互完整性，不以单张静态截图作唯一判断。
