# CEE 客户端界面与交互约束

修改猜猜呗（CEE）页面、房间界面或客户端会话行为时使用本文。玩法规则、协议、权限、隐私与搜索见 [Server/docs/CEE](../../Server/docs/CEE.md)；视觉规范见 [DesignGuide](DesignGuide.md)。组件、文案、常量读代码（`Client/src/components/cee/`、`pages/`、`lib/`）。

## 1. 会话与直链

- 页面生命周期是唯一的房间恢复入口，连接监听只订阅大厅；断线清除旧视图，卸载释放连接、重试定时器和待请求，保留可恢复的标签页凭据。原版过期凭据须删除后允许重新加入。
- 房间页直链加入被 `ROOM_NOT_FOUND` 拒绝时，用同一房号就地开一间增强房再进入（服务重启清空、测试房、已关闭房间的分享链接），与另外两款游戏同口径；密码错误、重名等其它业务拒绝原样报错。
- 直链进房全程**自动加入**，不弹“设置用户名”打断：先用本地已存用户名，没有就取访客名；私密房收到 `PASSWORD_REQUIRED` 才转入输入密码步。用户名与密码步的弹窗共用 `RoomJoinGate`。
- 进入房间期间不得抢跑状态同步，见服务端文档“协议、解析与会话”。耗时命令不设短超时，不报假失败。

## 2. 建房与设置

- “不在大厅显示”（原版房）与“私密房间”（增强房）是同一语义的两种界面表述；原版的开关常驻说明其只影响大厅显示。建房弹窗与等待页设置措辞一致。
- 反作弊房开关只对原生壳且已登录的建房者呈现，不达标时整行不出现，而不是点了才被拒；原版房与增强房共用建房弹窗，切到原版即收回选择。
- 等待页设置面板在反作弊房里保留一组只读“反作弊”状态，房主与非房主看到同一份：对所有人披露“这间房在记录”，没有人能再改。结算页只有一句“本局已记录，仅用于人工复核”，都不点名、不指控。
- 非房主在等待页看到同结构的只读设置。

## 3. 房间界面

- 玩家栏与另外两款游戏共用 `PlayerRow` 与首字方块头像：身份、姓名、状态、分数与房主操作都由该行承载，CEE 只注入次行内容（次数）与猜测进度；聊天保留独立区域，手机及平板都有入口。聊天栏第一行固定提示“聊天仅增强版玩家可见”。
- 有人组队时玩家组按队伍分块：队伍按队号升序在前、个人游玩的人在后，组内保持服务端座次；标题行给队号、人数与合计分；队员次数一致时只在标题出现一次，不一致（原版房逐人取自上游）时留在各自行里。
- 入队在等待页的队伍面板（个人与各队按格），点一格即加入；只给玩家组成员，旁观者没有队伍，玩家栏不放队伍下拉框。
- 状态徽章与另外两款游戏同口径：旁观分组不重复“旁观”，等待阶段表达准备状态，开局后按出题人标识标“出题”。出题人、其队友与中途加入者看到身份说明，不显示对他们无意义的次数。
- 旁观切换只在等待阶段出现，开局后不接受改身份；房间关闭观战后不再提供“加入旁观”，但已在旁观的人仍可“取消旁观”。
- 顶栏在准备与出题阶段显示即将开始的下一局编号。
- 数值比较的箭头表示答案方向；未知值显示“未知”，不显示内部哨兵值。
- 猜测进度取服务端的标记串渲染：原版房沿用上游原样，只在渲染层把标记翻成图标，整串作为一个图像读给读屏，悬停提示给出同一份文字描述，**不靠颜色传达**。

## 4. 结算页

- 增强房结算界面在得分表下方、猜测表上方提供操作按钮组：左侧描边“返回等待房间”，右侧主按钮“再来一轮”（房主直接开始下一局，沿用当前在线参与者），请求期间两者互斥加载/禁用。原版房继续服从上游行为。
- 结算页的本局回放**暂不向玩家开放**：默认关闭，只由本地开关启用，界面上不得出现入口。打开后：首条自动播放，手动切换即暂停，播完停在末条；整局跨回合按回合号与时间顺序重演；回放历史在房间页累积，换房或刷新即清空，不新增协议。
