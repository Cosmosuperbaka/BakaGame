# CEE 客户端会话约束

修改猜猜呗（CEE）页面、房间界面或客户端会话行为时使用本文。玩法规则、协议、权限、隐私与搜索见 [Server/docs/CEE](../../Server/docs/CEE.md)；视觉原则见 [DesignGuide](DesignGuide.md)。界面布局、组件与文案以实现为准，本文不记录。

## 1. 会话与直链

- 页面生命周期是唯一的房间恢复入口；连接监听只订阅大厅。断线清除旧视图，卸载释放连接、重试定时器与待请求，保留可恢复的标签页凭据。过期凭据须删除后允许重新加入。
- 房间页直链加入被 `ROOM_NOT_FOUND` 拒绝时，用同一房号就地开一间增强房再进入（服务重启清空、测试房、已关闭房间的分享链接），与另外两款游戏同口径；密码错误、重名等其它业务拒绝原样报错。
- 直链进房全程自动加入，不弹“设置用户名”打断：先用本地已存用户名，没有就取访客名；私密房收到 `PASSWORD_REQUIRED` 才转入输入密码步。
- 进入房间期间不得抢跑状态同步，见服务端文档“协议、解析与会话”。耗时命令不设短超时，不报假失败。

## 2. 建房与设置

- 原版房的“大厅可见性”与增强房的“私密”是两种产品语义，界面措辞必须让玩家分清；具体文案与控件以实现为准。
- 反作弊房开关只对原生壳且已登录的建房者呈现；不达标时不呈现该入口，而不是点了才被拒。
- 非房主不得通过客户端推断或提升自己的设置权限；设置权限与只读语义由服务端按房主身份判定。反作弊房对所有人披露“这间房在记录”。
- 客户端不自行推断权限或过滤私有数据；服务端按连接视角裁剪，客户端只渲染收到的内容。

## 3. 排位页

- 排位页挂在 CEE 布局下，复用同一条 CEE 连接，不另建连接；排位状态只来自服务端推送的排位状态事件，页面不自行推断准入与阶段。网页端只展示「需要客户端」与下载入口，客户端未登录时引导登录；真正的准入以服务端拒绝为准。
- 排位的三条准入命令在壳内发出前先确认本次握手带了通道票据，没有就换票重连；被服务端以缺少通道证明拒绝时换票重试一次。
- 搜索框与角色图通过数据源上下文取数：缺省是多人房那套，排位页换成排位命令，组件本身不认识两种来源；图片缓存键按来源区分，避免同一角色在两种来源下的结果互相污染。
- 系列赛进行中开启窗口级防截屏，结束或离开即恢复，与反作弊房同一口径。
- 对手面板只画服务端给出的脱敏线索，不从任何其它字段拼回对手猜了谁；人机不显示分数。

## 4. 房间与结算

- 玩家栏、聊天与状态展示复用本项目公共组件；CEE 只提供自身业务字段，不复制另一款游戏的私有实现。
- 身份、次数、猜测进度与结算数据以服务端下发的字段为准；未知值显示为未知，不显示内部哨兵值，不靠颜色单独传达状态。
- 聊天与旁观的可见性、组队与出题人规则服从服务端 CEE 文档；客户端不做「收到但藏起来」的过滤。
