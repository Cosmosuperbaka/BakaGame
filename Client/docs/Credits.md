# 开源致谢与版本信息页

维护 `/abouts`（开源致谢 / 更新日志 / 提交历史 / 隐私说明 / 用户条款）、参与开发的大模型名单、品牌图标或依赖许可证数据时查阅本文。页面实现与视觉原则见 [DesignGuide](DesignGuide.md)，更新日志文案与版本结算见 [Commitment](../../Agents/Commitment.md)。文件位置、数据结构、命令读代码，本文只留约束。

## 1. 数据来源

- 更新日志、提交历史、依赖清单、许可证原文都由构建期从**真相源**生成，不手写、不在文档或页面里写死依赖数量、包名列表或版本。新增依赖不需要手工登记。
- 手写维护的只有参与开发的大模型与核心技术栈，均在 `Client/src/data/CreditsContent.ts`。
- 许可证原文不常驻页面，按需懒加载；失败不缓存。
- 包链接只放行绝对 http(s)。`repository` 的各种简写要归一成仓库页，认不出就不渲染“项目主页”，不把简写当 `href` 输出成站内死链。

## 2. 模型署名与品牌标识

`CONTRIBUTING_MODELS` 是“实际参与过本项目开发的大模型”的唯一定义处。

- **改动或实行的规划才署名。** 提交过仓库文件改动的模型，在完成改动后把自己的名字加入对应公司；只做规划且规划被如实实行的，规划者与执行者都登记一条。规划未落地、或仅参与讨论、咨询、评审的不署名。
- **叫不出型号就不登记。** 只认自己运行上下文里的真实发布名；内部别名、会话日期和自我印象都不算。确定不了时不写条目，在交付说明里写明改动由哪个会话完成，由维护者补登记。
- **排序。** 英文公司在先、按名称字母排序；中文公司在后、按拼音转写排序。同一公司的模型按发布日期从早到晚。展示前统一经排序函数收口，新增公司追加到数组末尾即可。
- **文字只写模型名。** 不写分工、日期或宣传语。
- **发布页链接。** 尽量带厂商官方新闻或文档链接；没有公开页面时省略，徽章退化为静态标签，不放死链。
- **每条都带官方标识。** 公司用厂商标识，模型用模型家族标识；是两枚不同字形时分别登记，相同可以复用。

品牌图标：

- 优先使用已引入的官方图标包；没有品牌字形时回退通用图标，不用近似品牌顶替。品牌图标只标注依赖、技术栈或模型/厂商本身，不装饰业务页面。
- 自备资产必须登记来源、许可证与改法，来源与许可必须允许再分发。npm 别名包与被别名的包共用同一品牌键。

## 3. 展示与验证

- 页面布局、列轨、搜索、筛选与抽屉交互以实现为准，不在此维护；依赖数量、包名与版本不手写。
- 验证范围按 [Testing](../../Agents/Testing.md)；页面改动覆盖相关状态、三档宽度与减弱动效。
- 改动确认的署名、依赖数据或数据侧约束，同步回本文与 `CreditsContent.ts` 的注释，不只留在聊天或提交信息里。
