# 设计大方向（冻结文档）

> 本文只有用户批准后才能修改。任何 Agent 不得自行编辑、重排或“顺手润色”；确需改动时先向用户说明并取得明确准许，改完后按 [AGENTS.md](../../AGENTS.md)「冻结文档」更新哈希。
> 全局视觉与动效原则写在 [DesignGuide](DesignGuide.md)，那一份允许大模型按本文精神自行优化；局部页面布局、组件与样式以实现为准。

本文写给有审美判断力的大模型：给出方向，不给配方。遇到本文与 DesignGuide 冲突时，以本文的精神为准，并回头修订 DesignGuide。

## 一、美术风格

BakaGame 是一间多人在线的游戏室：几个朋友围着一张桌子，玩谁是卧底、猜歌、猜角色。界面是那张桌子。

- **纸与墨。** 基调是暖色的旧纸张与衬线字体，像一本被翻过很多次的书或一副牌。页面是暖白，文字是暖褐，主色克制，不用纯白、纯灰与冷色中性底。
- **克制。** 视觉服务于游戏流程、信息识别和操作效率。界面不炫技，不做宣传页式排版，不堆装饰。游戏中的信息（房间、玩家、聊天、当前阶段）永远是第一层级。
- **方正而温和。** 轮廓偏方，阴影轻而暖，边框代替重阴影来分层。空间靠明度的细微差别建立，不靠大面积色块。
- **一致胜过新奇。** 同样的事在不同页面长得一样、动起来一样。新页面应当像本来就在这里。
- **诚实。** 界面只说真实的业务话。不出现设计说明、风格自述或展示性文案，也不放假数据与占位入口。
- **可读与可达。** 颜色之外必须有文字、形状或图标共同传达状态。小屏、长文本、减弱动效下，界面仍然完整可用。

## 二、动效追求

动效是编舞，不是出现方式。

- **因果。** 每段动画都能追溯到一个成因：用户的一次点击、服务端推来的一次状态变化、一个元素的进出场。说不出成因的动画不要加。
- **空间连续。** 界面是一个连续的空间，不是一叠互不相关的区块。一切从哪里来、往哪里去，都应当在空间上说得通：浮层从触发它的东西里长出来，也沿原路回去；同一个对象在移动时始终是同一个对象。
- **有重量。** 运动由弹簧与阻尼驱动：有动量、有一点过冲、会回落。轻的东西快，重的东西慢。被抛出的东西带着初速度，被收回的东西先蓄一下力。
- **有方向。** 沿运动方向与垂直方向可以有不同的节奏，让形变读作力的结果，而不是等比缩放。瞬时的冲击可以用离散的、逐格衰减的抖动，而不是平滑摇摆。
- **不塑料。** 拒绝无意义的淡入淡出和匀速缓动。宁可没有动画，也不要有解释不通的动画。
- **不拖慢人。** 动效从不推迟玩家的实际操作。减弱动效偏好下，状态变化依然清楚。

## 三、给 Agent 的使用方式

- 做视觉与动效判断时，先问：这符合上面哪一条精神？符合就大胆做，DesignGuide 没覆盖的局部实现由你判断。
- 小模型执行局部修改时，只依 DesignGuide，不要把本文当成可以放大发挥的许可。
- 本文不记录任何具体数值、组件名、颜色值或令牌名。那些属于代码。
