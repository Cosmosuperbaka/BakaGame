# 设计大方向（冻结文档）

> 本文只有用户批准后才能修改。任何 Agent 不得自行编辑、重排或“顺手润色”；确需改动时先向用户说明并取得明确准许，改完后按 [AGENTS.md](../../AGENTS.md)「冻结文档」更新哈希。
> 全局视觉与动效原则写在 [DesignGuide](DesignGuide.md)，那一份允许大模型按本文精神自行优化；局部页面布局、组件与样式以实现为准。

本文写给有审美判断力的大模型：给出方向，不给配方。界面有多套主题，本文先写所有主题共有的精神，再分节写每套主题自己的美术规范。主题之间可以换材料、换字体、换颜色，共有的精神不换。遇到本文与 DesignGuide 冲突时，以本文的精神为准，并回头修订 DesignGuide。

## 一、共有的精神

BakaGame 是一间多人在线的游戏室：几个朋友围着一张桌子，玩谁是卧底、猜歌、猜角色。界面是那张桌子；主题只决定这张桌子是什么材料。

- **克制。** 视觉服务于游戏流程、信息识别和操作效率。界面不炫技，不做宣传页式排版，不堆装饰。
- **游戏信息是第一层级。** 房间、玩家、聊天、当前阶段永远最先被看到。任何主题的风格都不能盖过它们，也不能把它们挤到次要位置。
- **一套语言。** 每套主题都有一个出发点，可以是一种材料，也可以是一种字体。字、形、线、留白、色与表面都从这个出发点推出来，彼此印证。出发点不同的元素不拼在一起：圆润的轮廓配锋利的字、软的投影配硬的线，都是两种语言在打架。
- **一致胜过新奇。** 同样的事在不同页面长得一样、动起来一样。新页面应当像本来就在这里；同一款主题之内，没有哪个页面自成一派。
- **诚实。** 界面只说真实的业务话。不出现设计说明、风格自述或展示性文案，也不放假数据与占位入口。
- **可读与可达。** 颜色之外必须有文字、形状或图标共同传达状态。小屏、长文本、减弱动效下，界面仍然完整可用。每款主题的亮色与暗色都要同样读得清，不为某一款放宽。

## 二、动效追求

动效是编舞，不是出现方式。它属于产品本身，所有主题共用同一套编舞，不随主题变化。

- **因果。** 每段动画都能追溯到一个成因：用户的一次点击、服务端推来的一次状态变化、一个元素的进出场。说不出成因的动画不要加。
- **空间连续。** 界面是一个连续的空间，不是一叠互不相关的区块。一切从哪里来、往哪里去，都应当在空间上说得通：浮层从触发它的东西里长出来，也沿原路回去；同一个对象在移动时始终是同一个对象。
- **有重量。** 运动由弹簧与阻尼驱动：有动量、有一点过冲、会回落。轻的东西快，重的东西慢。被抛出的东西带着初速度，被收回的东西先蓄一下力。
- **有方向。** 沿运动方向与垂直方向可以有不同的节奏，让形变读作力的结果，而不是等比缩放。瞬时的冲击可以用离散的、逐格衰减的抖动，而不是平滑摇摆。
- **不塑料。** 拒绝无意义的淡入淡出和匀速缓动。宁可没有动画，也不要有解释不通的动画。
- **不拖慢人。** 动效从不推迟玩家的实际操作。减弱动效偏好下，状态变化依然清楚。

## 三、各主题的美术规范

每一节写这套主题的出发点，以及字、形、空间、层次、色与表面怎样从出发点推出来。

### v0：默认样式

出发点是 shadcn/ui 的默认样式，项目最早上线时的样子。它是参照系，不追求个性，追求干净、标准、一眼就熟悉。

- **字。** 系统无衬线，正文与标题同一副面孔，层级只靠字号与字重。
- **形与线。** 中等圆角，一层浅灰描边把区块分开。
- **色与表面。** 中性的白与灰，主色近黑，不带暖色，不铺纹理；投影轻而薄，只帮浮层离开页面。
- **分寸。** 保持官方默认的气质，只为满足共有的可读性做最小的偏离，不往里加任何本项目的风格。

### v1：纸与墨

出发点是一本被翻过很多次的书，或一副牌。默认主题。

- **字。** 楷体写正文，衬线体写标题与强调，像手写的批注落在印好的书页上。
- **色。** 基调是暖色的旧纸张与暖褐的墨。页面是暖白，文字是暖褐，主色克制，不用纯白、纯灰与冷色中性底。
- **形。** 方正而温和：轮廓偏方，转角略钝，像用旧了的纸边。
- **表面。** 阴影轻而暖，边框代替重阴影来分层。空间靠明度的细微差别建立，不靠大面积色块。纸的纹理只铺在最底层，像桌上那张纸本身的质地。

### v2：书页与陶土

出发点是一款对话式 AI 产品界面那种温和的书卷气：像在读一页排得很松的书，对面有人轻声和你说话。它不讲材料的年代感，讲安静、干净与好读；和 v1 的旧纸褐墨分开，也和 v0 的标准界面分开。

- **字。** 两种字各管一层。衬线体担纲阅读：正文、标题与聊天都是书卷气的衬线，标题里的拉丁字母配一款笔画带弧度、气质温和的衬线体。按钮、标签、徽章这类界面小字交给一款自托管的无衬线体，中文用与正文宋体同一家族的黑体，字面与中宫和正文一脉相承；它们像书页边上的铅笔标注，不和正文抢气质；数据仍用等宽体。衬线字面大，行距放得开一些。
- **形。** 中等圆角，柔和但不圆滚。大小元素是同一种弧度，不出现胶囊配直角，也不出现圆滚滚的按钮配端正的衬线字。
- **线。** 极细的暖灰描边，只负责分区，淡到几乎不被注意；可以落笔的输入框比别处略重一点。
- **表面。** 底是干净的暖象牙白，不铺纹理，留白宽。面板与卡片是一页比一页更亮的纸，靠极细的描边与一点明度差浮起来；几乎不用投影，浮层只有一层很轻、很散的影。凹陷、次要操作与自己说的话落在同一层暖灰浅底上。暗色是暖调的深灰，不是纯黑，也不发褐。
- **色。** 墨是近黑的暖墨，几乎不带颜色。点缀只有一种陶土橙，克制地落在主要操作、当前玩家与焦点上，不铺大面积。状态色与陶土橙错开色相，各占一方，亮暗两套都要读得清。

## 四、给 Agent 的使用方式

- 做视觉与动效判断时，先问：这符合上面哪一条精神？符合就大胆做，DesignGuide 没覆盖的局部实现由你判断。
- 只改某一款主题时，先读共有的精神，再读那一款的一节；一款主题的规范与共有的精神冲突时，以共有的精神为准。
- 业务界面对所有主题都要成立，不为某一款主题的观感去改组件；某一款需要不同的观感，从它的出发点推出新的取值。
- 新增主题时，先在第三章为它加一节规范，写清出发点与各项怎样从出发点推出来，经用户批准后再动手。
- 小模型执行局部修改时，只依 DesignGuide，不要把本文当成可以放大发挥的许可。
- 本文不记录任何具体数值、组件名、颜色值或令牌名。那些属于代码。
